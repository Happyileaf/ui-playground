UI Playground 组件开发指南

从零开始构建纯原生、零依赖的交互组件。本文档涵盖快速开始、安装配置、核心概念、基础用法、常见问题与更新日志，帮助你在十分钟内建立完整的开发心智模型。

一、快速开始

欢迎使用本组件库。整个项目遵循「原生优先、零框架冗余」的设计哲学：你不需要安装任何构建工具，也不需要理解复杂的模块打包配置。只需要一个现代浏览器与一款趁手的文本编辑器，就可以开始编写高质量的交互界面。

最快的上手方式是直接克隆示例仓库，然后在浏览器中打开对应的 index.html 文件。所有案例均以静态文件形式提供，双击即可运行，离线环境下同样拥有完整的视觉效果与交互能力。

如果你希望在现有项目中引入组件，只需将对应的 HTML、CSS、JavaScript 三个文件复制到你的静态资源目录，并通过 <link> 与 <script> 标签引入即可，无需任何额外的运行时支持。

$ git clone https://example.com/ui-playground.git
$ cd ui-playground
$ # 直接用浏览器打开 index.html，或启动任意静态服务器
$ npx serve .

启动后，你将看到暗黑风格的工作台界面。左侧画廊陈列全部可用案例，点击任意卡片即可在隔离的沙箱容器中加载并运行对应组件。

二、安装配置

本组件库不强制要求使用包管理器。你可以选择最适合团队工作流的方式进行安装：通过 npm 拉取源码、使用 CDN 引用（仅限分发场景），或者直接下载 ZIP 归档解压使用。

推荐的目录结构遵循关注点分离原则：标记语言、表现层与行为层各自独立成文件。这样的组织方式既便于代码审查，也让单个组件可以被轻松抽取到任意宿主项目中。

  • 零依赖：组件运行时不依赖 React、Vue、jQuery 等任何外部库。
  • 零构建：无需 Babel、Webpack 或 Vite 等编译步骤即可运行。
  • 可移植：每个案例文件夹自包含，复制即可在任意站点复用。
  • 可访问：默认支持键盘导航、焦点管理与屏幕阅读器语义。

如果你需要对源码进行二次开发，仅需在编辑器中开启对 ES2020+ 语法的支持即可。所有脚本均通过 IIFE 封装，不会向全局作用域泄漏任何变量。

{
  "name": "my-project",
  "scripts": {
    "dev": "serve .",
    "check": "node --check script.js"
  }
}

三、核心概念

理解三个核心概念，将帮助你掌握本组件库的设计全貌：隔离沙箱、渐进增强与声明式状态。它们共同构成了所有交互案例的底层骨架。

隔离沙箱意味着每个案例都运行在独立的 iframe 之中，案例之间的 CSS 变量、全局样式与 JavaScript 变量互不干扰。音频上下文、画布状态也会随容器销毁而被完整回收。

渐进增强要求我们先用语义化的 HTML 描述内容与结构，再用 CSS 叠加视觉表现，最后通过 JavaScript 赋予行为。即使脚本加载失败，文档的核心信息依然可以被完整阅读。

声明式状态体现在滚动监听类组件中：当前阅读位置由 DOM 中的锚点关系唯一确定，脚本只负责同步 is-active 类名与 aria-current 属性，而非维护一份独立的状态副本。

const observer = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (entry.isIntersecting) setActive(entry.target.id);
  });
}, { rootMargin: '0px 0px -70% 0px', threshold: 0 });

这种以浏览器原生能力为核心的思路，大幅降低了状态不一致的风险，也让代码在长时间运行后依然保持稳定。

四、基础用法

本节通过几个典型场景，演示组件在真实页面中的组合方式。所有示例代码都可以直接复制到你的项目中运行，无需额外调整。

首先是锚点目录导航。目录容器使用 position: sticky 跟随视口滚动，内部锚点与正文 section 的 id 一一对应。当读者滚动页面时，IntersectionObserver 会根据元素与视口交叉区域的变化，自动高亮当前章节。

  • 在桌面端，目录固定于文章右侧，宽度比例约为 1:2。
  • 在移动端，目录自动隐藏，替换为顶部的 select 下拉选择器。
  • 点击锚点时平滑滚动，并通过 pushState 更新地址栏 hash。
  • 使用浏览器前进、后退按钮时，高亮状态会随之正确同步。
links.forEach((link) => {
  link.addEventListener('click', (event) => {
    event.preventDefault();
    target.scrollIntoView({ behavior: 'smooth' });
    history.pushState(null, '', '#' + target.id);
  });
});

其次是阅读进度条。监听文档的总滚动距离与视口高度的比值，通过 requestAnimationFrame 节流后写入进度条的 transform 属性，可以获得丝滑且不占用主线程的更新体验。

最后建议为所有可聚焦元素提供清晰的 :focus-visible 样式，并在 prefers-reduced-motion 媒体查询下将平滑滚动降级为瞬间定位，以照顾对动画敏感的读者。

五、常见问题

Q：组件可以在旧版浏览器中运行吗？

A：组件使用了 IntersectionObserver、CSS 自定义属性与 sticky 定位等现代特性，主流浏览器近两年的版本均可完整支持。对于不支持 IntersectionObserver 的环境，脚本内置了基于滚动位置的降级方案，目录高亮依然可用。

Q：为什么锚点跳转后标题会被吸顶栏遮挡？

A：这是固定头部布局的经典问题。解决方式是为每个 section 设置 scroll-margin-top: 88px，浏览器在计算锚点目标位置时会自动预留出吸顶栏的高度。

section {
  scroll-margin-top: 88px;
}

Q：目录在很短的章节下高亮不准确怎么办？

A：当章节高度小于观察者的判定区域时，可能出现两个条目同时或均不命中的情况。本组件通过「滚动方向 + 最近命中条目」的策略进行修正，确保任意时刻都有且仅有一个目录项处于激活状态。

Q：如何在深色与浅色主题之间切换？

A：所有颜色均以 CSS 变量定义在 :root 上，你只需覆盖这些变量即可整体换肤，无需修改任何组件内部的样式规则。
