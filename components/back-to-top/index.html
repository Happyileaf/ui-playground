长夜读尽，一键归航

这是一篇可以无限向下的长文。右下角的悬浮按钮会在你远行之后出现，环绕它的光环记录着你走过的阅读深度；轻点，便顺滑地回到故事开始的地方。

一、为什么需要一个回到顶部按钮

当一篇文章被拉得足够长，读者在结尾处抬头，往往只剩下一条看不到尽头的滚动条。回到顶部按钮最初只是一个朴素的功能补救：替用户省去手动拖拽滚动条的麻烦。但随着交互设计的演进，它逐渐承担起更多角色——它是页面深处的一盏灯，提示用户随时可以重新开始。

好的悬浮按钮懂得克制。它不会在页面顶部就贸然出现，打扰读者最初的沉浸；也不会在用户需要时缺席。通常的约定是：向下滚动超过一屏或某个固定阈值之后，按钮才以轻微的动画浮现，既宣告自己的存在，又不抢夺正文的注意力。

而在这个组件里，我们为它加上了一圈环形进度。它不再只是一个方向的符号，同时也是一把尺子，把抽象的阅读进度变成可视的弧线。你读到哪里，光环就延伸到哪里。

二、环形进度是如何计算的

浏览器并不会直接告诉你"读了百分之几"，但它给出了足够的原料：当前的滚动距离 scrollTop、视口高度 clientHeight，以及整页的 scrollHeight。可滚动的总距离等于 scrollHeight 减去 clientHeight，用当前滚动距离除以这个值，便得到一个介于 0 与 1 之间的比例。

SVG 的环形描边提供了两个关键属性：stroke-dasharray 定义虚线的排布，stroke-dashoffset 定义虚线的起始偏移。对于一个半径为 r 的圆，其周长约为 2πr。把 dasharray 设为周长，再让 offset 随进度从周长变化到 0，圆环便会被逐格"点亮"。

为了让进度从正上方开始而不是三点钟方向，圆环整体需要旋转 -90 度。这个细节常被忽略，却决定了进度环看起来是否符合直觉——人们习惯从上往下阅读，进度也理应从顶端启程。

需要注意的是，当页面内容不足以产生滚动时，分母会趋近于零。此时应当直接把进度归零并收起按钮，而不是让除法产生无意义的数值。防御性的边界处理，是组件健壮与否的分水岭。

三、用 requestAnimationFrame 节流滚动

scroll 事件的触发频率远高于屏幕的刷新频率，在一次滚动中可能倾泻出几十次回调。如果每次回调都去读取布局、写入样式，浏览器将被迫进行大量重复计算，掉帧与耗电随之而来。长页面上，这种浪费尤为明显。

requestAnimationFrame 给出了优雅的解法：滚动事件本身只负责"预约"一帧的更新，真正的计算被推迟到浏览器下一次绘制之前。如果一帧之内发生了十次滚动，实际执行的更新仍然只有一次，节奏与屏幕刷新严格对齐。

这里的关键是一个布尔标记：回调触发时若已有更新在等待，便直接返回；帧任务执行完毕后清除标记，允许下一次预约。几行代码，就把高频的事件风暴收敛成了平滑的逐帧更新。

四、平滑滚动与持续更新的进度环

点击按钮之后，window.scrollTo 配合 behavior: smooth 会让页面以浏览器原生的缓动曲线滑回顶部。原生实现的好处是无需手写动画循环，曲线自然、性能出色，并且会在用户中途介入滚轮时优雅地让位。

平滑滚动并不是瞬间完成的传送，而是一段持续数百毫秒甚至数秒的旅程。在这段时间里 scroll 事件照常触发，因此进度环会随着页面的回升而不断收缩，仿佛光环在逆向倒流，直到顶端彻底合拢。

按钮的显隐同样不应生硬。我们用一个 class 配合 opacity 与 transform 的 CSS transition 来表达出现与离开：出现时淡入并轻轻上浮，离开时淡出并微微下沉。可见性的切换交给 pointer-events 处理，避免隐藏状态下的按钮仍然拦截点击。

五、尊重 prefers-reduced-motion

动画对大多数人是愉悦的，但对部分前庭功能敏感的用户，持续的位移动画可能引发眩晕与不适。操作系统为此提供了"减少动态效果"的偏好开关，浏览器通过 prefers-reduced-motion 媒体查询把这一意愿传递给页面。

尊重它并不意味着功能的缺失。在这个组件里，当用户选择减少动态时，滚动行为切换为瞬时的 auto，按钮的淡入淡出与位移动画被一并关闭，呼吸光点也静止下来。功能保持完整，只是表达更加安静。

这类适配的成本极低，却体现了一个组件的教养：默认情况下尽情精致，而当用户明确表达不适时，立即收敛所有多余的表演。

六、键盘与无障碍细节

悬浮按钮首先是一个真正的 button，而不是 div 加 click 的拼装。这意味着它天然可以被 Tab 聚焦，可以用 Enter 与空格触发，屏幕阅读器也能正确识别其角色。剩下要做的，是为它补上一句 aria-label，让辅助技术读出"回到顶部"而非一段空白。

焦点样式是键盘用户的光标。:focus-visible 让鼠标点击时不出现多余的轮廓，而在键盘导航时呈现一圈清晰的高对比光环。装饰性的 SVG 则统一标记 aria-hidden，避免屏幕阅读器把它们当作有意义的图形反复念诵。

按钮的尺寸也值得斟酌。48 像素左右的圆形既不会在视觉上压迫版面，又能满足触控屏上手指点按的热区要求。右下角的定位使其符合多数用户的操作直觉，无论握持手机还是移动鼠标，都能轻易抵达。

七、毛玻璃与暗色基调

深色背景之上，纯黑的实心按钮会显得沉闷，纯白又过于刺眼。毛玻璃质感的 surface 半透明地透出底层的微光，既与页面分离，又保留了环境的呼吸。backdrop-filter 的模糊让滚过按钮背后的文字化为柔和的色块。

页面底色由深色与两团径向渐变共同构成：一团靛蓝的微光落在左上，一团天蓝色的晕染沉在右下，像暗室里两盏遥远的灯。按钮的靛蓝渐变与发光阴影正从这套基调中生长出来，彼此呼应而非各自为政。

克制地使用发光是关键。阴影只在按钮出现与悬停时轻微增强，光环始终纤细。廉价感往往来自过度的渐变、过宽的模糊与四处弥漫的霓虹；精致感则来自收束的边界与有限的色彩。

八、移动端的适配

在手机上，屏幕边缘是最容易误触的区域，也是拇指最容易到达的区域。按钮距右、距下各留 18 像素，既避开了系统手势条的热区，又保持了足够近的距离。桌面端可以给出更宽裕的 28 像素留白，让悬浮元素不与滚动条挤在一起。

正文被约束在约 720 像素的宽度内居中，这是中文长文舒适阅读的区间：每行容纳适量的汉字，视线换行时不至于迷失。超出宽度后，两侧的留白自然增大，文字栏始终稳固地停在视口中央。

段落间距、标题层级与卡片内边距也随视口收窄而略微收紧，在小屏上为正文争取更多空间。响应式并非简单的缩放，而是重新安排各元素之间的呼吸。

九、零依赖的封装哲学

整个组件的 JavaScript 被包裹在一个 IIFE 之中，执行完毕后不向全局留下任何变量。它不依赖任何框架、不引用任何 CDN，也不需要构建步骤。三个文件彼此引用，双击 index.html 即可在任何现代浏览器中完整运行。

这种朴素在工具链日益复杂的今天近乎一种坚持：把问题还原到浏览器原生能力的边界内，用 scrollTo、SVG 属性与 requestAnimationFrame 这些被充分实现的基础原语完成全部交互。没有版本冲突，没有打包产物，也没有离线时的白屏。

独立自包含还意味着可移植。整个文件夹可以被拷贝到任何位置、嵌入任何 iframe、归档进任何 ZIP，它都保持同样的行为。这正是案例库中每一个组件必须守住的黄金法则。

十、尾声：随时可以重新开始

你已经接近这篇长文的尽头。此刻向右下角望去，按钮上的光环应当已经接近合拢——那是你一路阅读的痕迹。再向下一点，弧线将在底部圆满。

轻点它，页面会带着光环一起向上流淌，经过你刚才停留的每一个标题，回到最初的"长夜读尽，一键归航"。然后按钮安静地退场，仿佛在说：随时欢迎重新开始。

一个回到顶部按钮能做的事情其实很有限，但把每一个细节——出现的时机、进度的诚实、滚动的顺滑、对用户偏好的尊重——都做到位，有限的功能也能透出温度。这正是原生组件值得被精工细作的原因。
