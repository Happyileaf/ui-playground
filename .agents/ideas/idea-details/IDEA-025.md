## 创意概述

一个「乱码 → 解码 → 定稿」的文字动效：文本初始由随机字符（片假名 / 十六进制数字 / 符号）占位，随着一道解码波前从一侧扫向另一侧，字符逐列从随机乱码「锁定」为目标字符，如同终端破解或数据流被实时解析。可用于 Hero 主标题、数据面板键值、终端 / 赛博风格页面的入场与悬停强调，解决静态大标题缺少「信息被解析、被解锁」仪式感与可反复触发反馈的问题。

## 预期展示效果

- **构图与整体风格**：
  深色克制的终端氛围舞台，采用带微弱色温倾向的精致暗色背景（遵循 Anti-Slop：不用泛滥蓝紫渐变、不用高饱和刺眼霓虹）。舞台包含一个大号主标题、一行次要副标题 / 标签，以及一组可独立交互的「文本芯片」（如导航项或数据键值），以此体现它是可复用的文字动效组件，而非只能播放一次的大字特效。右上角固定统一 HUD Title 胶囊（点阵指示灯颜色固定，不随参数联动）。
- **主要视觉元素**：
  乱码阶段使用系统等宽字体栈强化终端感，字符定稿后排版与整体字重协调；解码波前是一道极细的竖向高亮光带（扫描线）；每个字符在「锁定」的瞬间有一次极轻、不刺眼的亮度脉冲；可在控制台切换乱码字符集（十六进制数字 / 片假名 / 通用符号）。
- **层次、材质、光影与关键细节**：
  尚未解码的乱码字符保持低对比（次要文本色），越接近波前亮度越高；已锁定字符为高对比主文本色，保证定稿后正文对比度满足 WCAG AA；波前光带只使用一种克制的固定强调色（深空青或琥珀二选一作为主题色）；背景允许极弱网格或微噪点衬托，但不得喧宾夺主；HUD 使用项目统一毛玻璃材质。

> 设计文档约束最终体验与设计意图；除上述与创意强相关的约束外，不提前限定具体算法实现、精确尺寸或具体色值。

## 动态与交互

- **入场自动播放**：文本进入视口（IntersectionObserver）后自动解码一次；主标题按列错峰，波前默认从左到右推进（方向应可配置），整体时长在约 1 秒量级，平滑收敛。
- **悬停 / 聚焦重触发**：鼠标悬停或键盘聚焦任一文本芯片时，对该芯片文本快速重新执行一次「随机化 → 锁定」解码，形成可反复把玩的微交互；键盘聚焦需有清晰的 `:focus-visible` 焦点样式。
- **重播**：提供重播按钮，点击主标题也可再次播放完整解码。
- **参数控制台（默认折叠）**：通过右上角齿轮与 `H` 键唤出、`Esc` 收起；可调解码速度、乱码字符集、波前方向、悬停是否重触发；面板事件需防穿透。
- **减弱动效兜底**：`prefers-reduced-motion: reduce` 时直接呈现定稿文本，不出现乱码闪烁与波前动画。
- **移动端触控**：触控等价于悬停 / 点击，不依赖鼠标或键盘也能完整体验；可点区域满足触控尺寸要求。
- **性能与稳定**：动画用 `requestAnimationFrame` 配合帧间时间差驱动；解码期间容器不得因字符宽度变化产生换行 / reflow 抖动（用等宽占位或预留尺寸等方式稳定布局）；离场或动画结束后释放帧循环与观察器，避免常驻开销。

## 核心亮点

1. **交互创意**：把「解码」从一次性入场动画，扩展为可悬停 / 可键盘聚焦反复触发的微交互，并以「可复用文本芯片组」呈现，具备真实组件价值。
2. **表现细节**：波前高亮光带 + 逐列亮度梯度 + 字符锁定瞬间的微脉冲，塑造「信息被逐段解析」的清晰层次，而非整段无规则随机闪烁。
3. **实用可落地**：面向 Hero 标题、数据面板、终端风页面等高频真实场景开箱即用，同时提供可调参数、键盘可达性与减弱动效兜底。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：[src/playground.js](../../src/playground.js) 中全部 59 个注册案例的 id / title / description / tags；`playground/effects`、`playground/components`、`playground/pages` 目录；[rejected.md](../rejected.md)（当前为空）；[completed.md](../completed.md)（当前为空）。
- **相似案例**：
  - `typewriter`（打字机文字）
  - `glitch-text`（交互式故障文字）
  - `particle-text`（粒子解构文字）
  - 远相关：`scroll-reveal`（滚动入场揭示）、`count-up`（数字滚动）
- **差异说明**：
  - **vs typewriter**：打字机是字符按顺序「出现 / 删除」、内容从无到有；本效果字符始终存在，先以随机乱码占位再逐列「锁定」为目标字符，核心是解码波前与字符替换，并支持悬停 / 聚焦重复触发。
  - **vs glitch-text**：故障文字是持续的 RGB 位移、切片与色偏扰动，没有「收敛到定稿」的过程；本效果是一次性收敛解码，强调从混乱到确定的进度与波前光带，不使用 RGB 撕裂表现。
  - **vs particle-text**：粒子文字基于 Canvas 光栅化粒子做物理飞散与弹性回归；本效果是 DOM 文本字符的替换动画，无粒子、无物理模拟、不依赖 Canvas。
  - **vs scroll-reveal / count-up**：滚动入场仅做整块淡入位移、不改写字符；数字滚动仅对数值做 tween。本效果针对任意文本做逐字符语义解码，交互方式与视觉表达均不同。
  - 结论：在核心创意、视觉表达与交互方式上均存在实质差异，不属于更换颜色 / 文案或微调参数的重复方案。

## 实现约束（仅记录该案例必要的约束）

- 纯原生 HTML / CSS / JS，零框架、零 CDN、无外部字体或图片，双击 `index.html` 完整离线可用。
- 乱码阶段使用系统等宽字体栈（不引入任何外部字体文件），并保证解码过程不产生换行 / 布局抖动。
- 入场使用 IntersectionObserver；动画使用 `requestAnimationFrame` + delta time；必须响应 `prefers-reduced-motion`；动画结束 / 离场时释放观察器与帧循环。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（强制）；参数控制台默认折叠、`H` / `Esc` 切换、事件防穿透；底部按需提供交互指引胶囊。
- 定稿文本对比度满足 WCAG AA；触控可点区域不小于 44px；交互对键盘可达。
