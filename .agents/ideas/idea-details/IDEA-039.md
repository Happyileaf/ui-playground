## 创意概述

步进音序器（Step Sequencer）是电子音乐硬件（经典鼓机 TR-808 / TR-909）与现代音乐类产品（节奏工坊、DAW、beat maker、音乐教学应用）里最经典的交互范式：一张「轨道 × 步进」的网格，行是不同音色（底鼓、军鼓、闭合镲、开镲等），列是时间上循环往复的节拍格；用户点亮任意格子，就把这件乐器安排到了那个时间点，按下播放，一条由自己编排的鼓点循环立即开始流动，光标逐格扫描前进，格子在被击中的瞬间被点亮并真实发声。它把「作曲」降到了「点格子」的零门槛——不需要识谱、不需要会演奏乐器，每个人都能在十几秒内拼出一段可听的节拍，且**听到的每一声都严格对应自己点亮的那个格子**，输入与声音的因果关系即时、确定、可反复验证。

本案例做一个纯原生、零依赖、零 CDN、零音频资源、双击离线即用的**可编程步进鼓机音序器**：约 4～6 条音色轨道 × 16 个步进格（两小节、四四拍，每 4 格为一组有视觉重音分组），全部音色（kick / snare / clap / closed-hat / open-hat / tom 等）由 Web Audio API **实时合成**（振荡器扫频做底鼓、滤波噪声做军鼓/镲片、包络塑形），不加载任何 mp3/wav。播放使用 `AudioContext` 时钟的 **lookahead 调度器**（setInterval 前瞻 + `audioCtx.currentTime` 精确定时把每个步进事件排进音频线程），保证节拍不随主线程卡顿抖动；播放头逐格扫描高亮、当前步进列整列脉冲、被击中格触发一次「击打」反馈（亮度/缩放闪动）与可选的 Web Audio 合成咔嗒触感音（沿用项目音效惯例，手势内懒激活 AudioContext）。交互完整：点击/触控切换格子、播放/停止、BPM 调节（约 60–180）、逐轨音量/静音/独奏、清空、若干预设节拍图案一键载入（并可见格子真实点亮，证明非黑盒播放）、单个格子的试听（点轨道头即时触发该音色）；键盘可空格播放停止、方向键移动选区、Enter 切换格、C 清空。支持 swing（摇摆）、当前步进位置等通过默认折叠的 Micro-HUD 实时调节与显示。全部动效尊重 `prefers-reduced-motion`（扫描列与格子仍可切为瞬时高亮、不做位移动画，但播放、声音与编辑全部功能完整），并在卸载/切后台时可靠停止调度与音频。

当前案例库 60 个已注册案例中，Web Audio 相关仅有 `interactive-piano`（钢琴键盘：按下琴键即时发一个音，是**实时演奏**模型，无时间网格、无循环、无编排）、`fireworks`/`confetti-burst`/`swipe-card-deck`/`capsule-tabs`/`dynamic-dock` 等把 Web Audio 仅用作**一次性触感音效**；在池 38 个 Ready 中，IDEA-030 音频反应频谱可视化虽以「振荡器 + 时钟调度的合成鼓点循环」作为**内置演示音源**，但其本体是 AnalyserNode 驱动的 FFT 频谱/波形**视觉反应**，循环是固定不可编辑的演示源、用户不参与编曲；全仓与活动池检索 `sequencer / drum / 鼓机 / 音序 / beat / BPM`，无任何「轨道×步进可编程网格 + lookahead 调度器 + 合成鼓音色」主题。这是「用网格编排时间型声音」这一高频音乐交互场景里一个干净、实用、与现有音频案例机制完全不同的空白。

## 预期展示效果

- **构图与整体风格**：
  - 案例视口是一台深色、哑光、克制的**桌面硬件鼓机（drum machine）面板**：上方为传输控制区（主播放/停止大键、BPM 数码读数与加减/滑杆、swing、预设选择、清空），中部为核心的**步进网格**——每行一条音色轨道（左侧轨道头：音色名、专属轨道色点、音量/静音/独奏控件、点按可试听该音色），右侧是 16 个等宽步进格，按每 4 格一组做背景分组（四四拍两小节，组边界可辨识），当前播放列在播放时有一道纵向扫描光随时间移动。
  - 延续项目暗色、低饱和、Anti-Slop 审美：面板为近黑哑光金属/磨砂塑料质感（极细描边、柔和圆角、极轻投影与微弱内高光），每条轨道一种克制的专属强调色，只用于「被点亮的激活格 / 该轨击打反馈 / 轨道头色点」，未激活格为深灰低对比凹槽；拒绝霓虹满屏、彩虹渐变堆砌与大面积毛玻璃炫技。读数使用等宽数字（系统等宽字体栈），全部图形/图标为内联 SVG 或 CSS 构造，零外部图片/字体/音频/请求。
  - 桌面宽屏网格完整展开 16 列；平板保持可点网格（可略减轨道或紧凑间距）；手机上网格可横向滑动或压缩间距但 16 步与轨道身份不丢失，触控热区充分（格子不小于舒适触控尺寸），传输区换行排布不溢出。
- **主要视觉元素**：
  - **可编程步进网格**：轨道行 × 16 步，未激活格是暗色凹槽、激活格是该轨专属色的实心发光垫（pad）；每 4 步一组有可辨识的分组底纹/分隔，小节起点略强。
  - **播放头扫描与击打反馈**：播放中当前步进列整列有一道克制的纵向高亮随 BPM 精确推进（非 CSS 无限动画假装走，而是由音频时钟调度回调驱动当前列索引）；当列内某个激活格被真正调度发声时，该格做一次短促「击打」闪动（亮度脉冲 + 极小 scale 回弹），轨道头可同步轻闪，声音与闪光严格同格同时。
  - **传输与状态区**：播放/停止主控件状态明确（不仅靠颜色，配三角/方块图标与 aria-pressed），BPM 数码读数实时、可滑杆可步进加减；预设载入时可见对应格子真实点亮；静音/独奏有明确状态样式。
- **层次、材质、光影与关键细节**：
  - 视觉三层：深色面板背景（可带极弱工业网格/拉丝底纹但不喧宾夺主）→ 传输区与轨道头（次级面板层级）→ 激活格/播放列/击打闪光（最高动态焦点）。
  - **声音与灯光必须对得上是底线**：播放推进与每一声击打必须由同一个 lookahead 调度计划驱动（调度某步进发声的同一时刻安排该格的视觉反馈，可通过按音频时钟换算的时间戳触发视觉，避免声音与闪光错位）；不允许用「CSS 动画匀速扫 + 独立随便播声音」造成声光漂移，也不允许主线程 setInterval 直接触发声音导致高负载下节拍抖动。
  - 击打反馈短促克制（百毫秒级衰减），扫描列透明而非盖住格子本色；BPM 变化时扫描速度与声音节奏同步改变、不跳拍错位（正在响的音自然衰减，下一拍起按新间隔调度）。
  - 激活/未激活、分组、播放列三种信息不能仅靠颜色区分（配合形状/亮度/描边分组），保证在低对比与色觉差异下仍可读。

> 设计文档约束最终体验与设计意图；轨道数与具体音色组合、16 步以外是否提供步长档位、各音色合成参数、lookahead 时长与调度间隔、swing 的具体实现、预设图案数量与具体节奏型、HUD 暴露哪些参数，由实现阶段按手感统一决定，不在此过早钉死；但「点亮格子 → lookahead 调度器按音频时钟精确发声且同格同时闪光 → 16 步循环、BPM/编辑实时生效、声光严格对应、可播可停可清空可载预设」这条链路必须真实成立，不允许用预设 CSS 动画假装播放、不允许声音与网格脱钩、也不允许引入任何外部音频文件。

## 动态与交互

- **触发方式（多输入统一，非纯自动播放）**：
  - **指针/触控**：点按网格切换该步激活/取消（即时视觉态，播放经过时发声；编辑已点亮格子也可选择即时轻触发该音色作为反馈）；点播放/停止启停；拖动或点击调节 BPM；轨道头静音/独奏、点按试听单音色；预设按钮载入图案；清空复位。
  - **键盘**：空格启停，方向键在网格间移动选区（可见焦点框），Enter/Space 切换选区格，数字或 M/P 切换当前轨静音/独奏（可选），C 清空，Esc 关闭 HUD/移出格编辑；焦点环始终可见，Tab 顺序符合视觉。
- **音频调度引擎（核心逻辑）**：
  - 首次用户手势内创建/恢复 `AudioContext`（懒激活，不自动播放、不预耗资源）；所有音色实时合成（如 kick：正弦振荡器频率快速下扫 + 增益包络；snare/clap：白噪声 buffer 经带通/高通 + 衰减包络，可叠三角波体；hat：高频噪声经高通 + 短包络，开镲包络更长；tom：中频振荡扫频），经各轨增益（音量/静音/独奏逻辑）→ 主输出，可选主限幅/音量。
  - 调度采用 lookahead 模式：定时器以较短间隔前瞻，把未来一个调度窗口内落在播放位置上的激活格，用 `audioCtx.currentTime` 精确 `start/stop` 排进音频线程；维护当前步进索引与每步时长（由 BPM 与 swing 计算），并据已调度事件的时间戳同步推进视觉播放列与击打闪光，保证节拍稳定、声光对齐。
  - 编辑（点亮/取消、静音/独奏、切预设、清空）对**下一个被调度到的步进**立即生效，不要求停止重来；BPM 改变平滑作用于后续步间隔；停止时取消未触发的调度计划、停止播放头，正在衰减的声音自然收尾或快速淡出，不残留持续响的振荡器。
- **控制与可配置项（Micro-HUD 默认折叠，`H`/`Esc` 切换、事件防穿透）**：BPM、swing 量、主音量、是否播放击打触感音/动效强度、步长（如 16 步档），实时显示当前步进位置、小节/拍号、各轨峰值或触发状态等真实读数；预设图案与清空等常用操作放在主面板而非藏入 HUD。
- **可访问性（一等路径）**：
  - 网格格可作为可切换按钮暴露语义（`button`/`role="gridcell"` + `aria-pressed`/`aria-selected`，轨道与步进可用 `role="row"/"grid"` 组织），播放按钮 `aria-pressed`/可读状态，BPM 与音量为可键盘操作的 range（带可读值）；播放走到某格不抢焦点，但可通过 `aria-live="off"`/谨慎播报避免每拍刷屏（仅在播放/停止、载预设等阶段边界用 `aria-live` 轻播报）。
  - 文字/控件对比度达 WCAG AA，焦点可见，状态不仅靠颜色；尊重 `prefers-reduced-motion`：扫描与击打闪光改为瞬时/极短非位移高亮、不做 scale/位移动画，但**播放、合成声音、循环调度、网格编辑、键盘操作全部功能完整保留**。
- **移动端与触控**：窄屏网格保持 4～6 轨 × 16 步身份，可紧凑间距或容器内横滑，触控热区充分、点按不与滚动手势冲突；传输区自适应换行；横竖屏切换后网格与播放头位置不错位。
- **生命周期**：停止播放或卸载案例（iframe 销毁）、页面隐藏时，停止调度定时器、挂起/关闭 AudioContext、断开节点并取消未触发事件，无后台继续发声、无悬挂定时器/监听；重新进入时从干净状态开始。

## 核心亮点

1. **补齐「时间型声音编排」高频场景的空白**：步进鼓机是硬件鼓机到 beat maker/音乐教学类产品的标志性交互，库内 60 案例与在池 38 个 Ready 无一覆盖「轨道×步进网格编曲」；本案例把作曲降为零门槛点格子，可直接用于音乐类产品演示、节奏教学、互动落地页（实用性 5 分）。
2. **真实的 Web Audio lookahead 调度而非摆拍**：难点与亮点都在——所有击打由统一的音频时钟前瞻调度精确发声，视觉播放列与格子击打闪光由同一批调度事件的时间戳驱动，做到**声光严格同格同时、节拍不随主线程抖动**，区别于「CSS 动画假扫描 + 脱钩音效」的廉价实现。
3. **零音频资源的实时合成鼓组**：kick/snare/hat/tom 等全部由振荡器扫频、滤波噪声与包络当场合成，零 mp3/wav、零网络，双击离线即可听可玩；每条轨道独立合成路径与音量/静音/独奏总线，具备小型真实混音台的完整度。
4. **完整交互面，严格规避纯自动播放**：点亮/取消格、逐格试听、播放停止、BPM/swing 实时变速、多套可看见落点的预设、清空、全键盘编曲（空格/方向键/Enter/C）——声音的每一声都由用户编排且可反复验证，不是加载即放完的演示动画。
5. **硬件鼓机面板美学 + 工程鲁棒**：哑光硬件面板、一轨一色的克制 pad、精确推进的扫描列与短促击打闪光，拒绝霓虹彩虹的 AI Slop；编辑对下一拍立即生效、停止无余响泄漏、切后台/卸载彻底回收定时器与音频节点，reduced-motion 下功能完整。

  - `fireworks` / `confetti-burst` / `swipe-card-deck` / `capsule-tabs` / `dynamic-dock` 等：仅把 Web Audio 用作点击/爆发瞬间的**一次性触感音效**（懒激活短音），无持续时钟调度、无音乐性、无网格，与本案例的循环音乐引擎不同。
  - 其余注册案例与在池 IDEA 逐一核对：无任何网格音序/节拍机/DAW 类主题；IDEA-013 环形拨盘时间选择器虽含「表盘」字样，但它是选择时分值的表单组件、不发声；`interactive-piano` 之外无其他音乐类交互。确认无历史（含已删除）`step-sequencer` id 或物理目录冲突。
- **差异说明**：核心创意是「**一张轨道×步进的可编程网格，用户点亮格子编排节拍，Web Audio 实时合成鼓音色并由音频时钟 lookahead 调度器精确循环播放，播放头与击打闪光严格随同一调度事件推进的离线鼓机**」。与 interactive-piano 相比，差异在时间编排/循环传输 vs 按键实时演奏；与 IDEA-030 相比，差异在「生产可编排音频的乐器」vs「消费固定音频做 FFT 可视化」（合成鼓点只是共享的底层素材，成品、用户任务与视觉表达完全不同）；与各触感音效案例相比，差异在持续音乐时钟调度 vs 一次性音效。差异同时体现在核心创意、视觉表达（硬件鼓机面板 × 一轨一色发光 pad × 精确扫描列）、交互方式（点格编曲/键盘编曲/BPM/swing/预设/多轨混音）与整体表现（可演奏的乐器工具）上，不属于换颜色、文案或微调参数类重复。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 HTML5 + CSS3 + ES6+，零框架、零第三方库、零音频库（合成与调度全部手写 Web Audio API）、零图标库/图标字体、零 CDN、零外部图片/字体，且**零音频资源**（不加载任何 mp3/wav，鼓组音色全部由 OscillatorNode / 噪声 AudioBuffer / BiquadFilter / Gain 包络实时合成），双击 `index.html` 完整离线可用（沿用案例三件套 `index.html` / `style.css` / `script.js`）。
- 播放必须基于 **AudioContext 时钟的 lookahead 调度**（前瞻定时器 + `currentTime` 精确排程），不得用主线程 `setInterval` 直接触发声音；视觉播放列与击打闪光必须由同一批调度事件（按其音频时间戳）驱动，做到声光同格同时、节拍稳定；BPM/swing 变化对后续步进平滑生效且不跳拍错位。
- 全部声音由用户的网格编排与传输控制决定（非纯自动播放）：点亮/取消、试听、播放/停止、BPM、swing、逐轨音量/静音/独奏、预设（须可见格子真实点亮）、清空均可操作并对后续调度即时生效；首次发声在用户手势内懒激活/恢复 AudioContext；停止、页面隐藏与案例卸载时取消未触发调度、停止/挂起 AudioContext 并断开节点，无后台发声、无定时器/监听泄漏。
- 交互多路径：指针/触控点格与传输控制 + 完整键盘（空格启停、方向键移动选区、Enter/Space 切格、清空等），网格格具备可切换语义（aria-pressed/gridcell）、播放状态可读、控件 AA 对比且焦点可见、状态不仅靠颜色；`prefers-reduced-motion` 下扫描/击打改为瞬时非位移高亮，但播放、合成、编辑、键盘功能全部完整。
- 视觉为暗色哑光硬件鼓机面板：一轨一克制强调色仅用于激活垫/击打/轨道色点，未激活格为低对比凹槽，分组与小节边界可辨识；桌面/平板/手机自适应（窄屏保持 16 步与轨道身份、热区充分、不横向溢出布局）。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（强制）；BPM、swing、主音量、触感音/动效开关、步长与当前步进位置/拍号等真实读数通过默认折叠的 Micro-HUD 提供（`H`/`Esc`、事件防穿透）。
