## 创意概述

做一个待办/歌单/栏目管理风格的单列线性排序列表：用户可以用鼠标/触屏**拖拽**条目改变顺序，也可以完全不依赖鼠标、仅用键盘（抓取手柄 + 上下移动）完成同等排序。核心解决的体验问题是——原生 HTML5 拖拽 API 出了名的“键盘不可达、触屏不稳、样式反馈弱”，本案例以**统一指针拖拽（Pointer Events）+ 完整键盘重排双通道**的方式，演示一个生产可用、符合 WAI-ARIA 网格/列表重排模式（类似 dnd-kit / @dnd-kit/sortable 的无依赖原生实现）的高可访问性排序组件，并配以 FLIP 式平滑让位动画、插入指示线与实时 `aria-live` 播报。

## 预期展示效果

- **构图与整体风格**：深色工作台风格（延续项目 Anti-Slop 深色基底，近黑冷灰背景 + 低饱和中性描边 + 单一克制的强调色，不用蓝紫渐变与霓虹）。画面中央为一张浮起的列表面板，标题区含“拖拽或用键盘排序”的副标题与顺序计数；列表条目为横向行卡片，每行左侧有由六点阵组成的**拖拽手柄（drag handle）**，中部为条目标题与次要说明，右侧显示当前序号徽标。
- **主要视觉元素**：
  - 拖拽手柄：六点阵 grip 图标（内联 SVG），默认低对比，悬停/聚焦/抓取时强调色点亮并轻微抬起；
  - 插入指示线：一条 2px 强调色水平线 + 端点圆点，指示松手后落点；
  - 被抓取条目：脱离文档流跟随指针，带轻微缩放、克制投影与不透明度变化；
  - 其余条目：在插入点两侧以 FLIP 过渡平滑上下让位，而非生硬跳动；
  - 序号徽标随顺序变化实时刷新；可选的“重置顺序”按钮恢复初始排列。
- **层次、材质、光影与关键细节**：
  - 面板为一层哑光卡片（1px 半透明白描边 + 柔和环境阴影），被拖拽条目是第二层（阴影加深、z-index 抬升、边框强调色微亮）；
  - 拖拽期间指针事件统一捕获（setPointerCapture），行内文字禁用选择、行禁用误触；
  - 键盘模式下被“抓起”的条目有清晰、区别于 hover 的聚焦轮廓（:focus-visible，2px 外圈偏移），让位动画与指针模式一致；
  - 触觉反馈可选（navigator.vibrate 短促一次，能力检测，不支持则静默）；
  - `prefers-reduced-motion: reduce` 时关闭 FLIP 位移与缩放，仅保留插入指示线与即时重排。

## 动态与交互

- **指针拖拽（鼠标/触屏/触控笔统一走 Pointer Events）**：在手柄（或整行，取决于实现取舍，默认手柄抓取以避免与行内点击冲突）按下并移动进入拖拽态；条目跟随指针，实时计算指针位于相邻条目的上/下半区以决定插入点，其余条目 FLIP 让位并显示插入指示线；松手后吸附到目标位置、播放落位回弹、更新顺序与序号。
- **键盘重排（不依赖指针，完整可达）**：
  - Tab 聚焦到某行的手柄按钮；Enter/Space “抓起”该行（`aria-pressed`/抓起态，`aria-grabbed` 已废弃，采用 `aria-describedby` + 实时区域说明当前位置）；
  - 抓起后 ↑/↓ 方向键逐步移动插入位置（可带长按加速，非必须），其余条目实时让位；Enter/Space 放下，Esc 取消并回到原位置；
  - 移动过程通过一个可视的 `aria-live="polite"`（或 assertive 的短提示）区域播报“项目 X，当前第 N 位，共 M 项”。
- **焦点管理**：拖拽/放下后焦点保持在被操作行的手柄上；Esc 取消时焦点也回到原处，不丢失键盘上下文。
- **触控标准**：手柄触控目标 ≥ 44×44 CSS px；纵向拖拽与页面滚动手势通过手柄限定区域 + 必要时 `touch-action: none` 协调，避免整页误滚动。
- **其他**：重置按钮可恢复初始顺序（附过渡动画）；reduced-motion 下所有位移动效退化为即时切换；操作在窄视口（手机 375px 宽度）下保持可用、行内信息不溢出。

## 核心亮点

1. **双通道等价操作**：指针拖拽与纯键盘重排能力完全对等，是少见的把“可访问性排序”做到可直接投产水准的原生组件，而非只服务鼠标的炫技 demo。
2. **FLIP 让位 + 明确插入指示**：其余条目平滑腾位、插入点指示线与序号实时刷新，解决原生 DnD“跳动突兀、不知道会放哪”的体验痛点。
3. **ARIA 实时播报与焦点往返**：操作全程对屏幕阅读器透明（位置播报 + 抓起/放下状态 + Esc 还原 + 焦点不丢），对齐 WAI-ARIA 重排模式。
4. **统一 Pointer Events + 能力降级**：一条事件通路覆盖鼠标/触屏/触控笔，规避 HTML5 DnD 在触屏上不可用的问题；振动、动画等增强能力全部特性检测、静默降级。

- **差异说明**：

  - 与 `swipe-card-deck` / `split-pane`：虽都用指针，但前者是卡片飞出/喜欢的手势消费，后者是容器尺寸拉伸，均无“列表项顺序重排”语义与插入点计算。
  - 与 `virtual-list` / `tree-view`：前者只解决大数据渲染，后者是层级展开/选择，均无拖拽与排序。
  - 与在途 PR：表单（多步输入）、视图过渡（页面/元素形变）、Toast（通知堆叠）、Coverflow（3D 画廊切换）、Split-Flap（翻牌显示）、日期区间选择（日历输入）均不涉及列表重排，无本质重复。
  - 结论：在核心创意（可访问性线性排序）、交互方式（指针 + 键盘双通道）、视觉表达（FLIP 让位 + 插入指示线）上与历史和在途案例均有实质差异。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 ES6+，零框架、零第三方拖拽库（不引入 SortableJS / dnd-kit 等）、零 CDN，双击 `index.html` 离线完整可用。
- 统一使用 Pointer Events（`pointerdown/move/up` + `setPointerCapture`）覆盖鼠标/触屏/笔，不依赖 HTML5 Drag and Drop API（因其触屏不可用且键盘不可达）；不使用任何只在某类输入设备生效的事件作为唯一通路。
- 必须同时实现键盘重排通路与 `aria-live` 播报、Esc 还原与焦点往返；ARIA 用法遵循现行推荐（不使用已废弃的 `aria-grabbed`/`aria-dropeffect`）。
- 图标用内联 SVG；无外部图片/字体/音频依赖。
- 触控目标 ≥ 44px，窄视口可用；`prefers-reduced-motion` 下关闭位移动效。
- 遵循统一 HUD 规范（右上角 Title 胶囊；如配 Micro-HUD 默认折叠、`H`/`Esc` 快捷键且不与列表自身 Esc 语义冲突）。
