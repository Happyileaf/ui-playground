## 创意概述

近几年 Apple、Linear、Vercel、Stripe 等产品的官网首屏几乎都用同一种布局语言讲「产品有哪些能力」：一张**非对称的 Bento Grid（便当盒网格）**——大小不一、高低错落的卡片被精确编排进同一个栅格，大卡承载主特性（配一块可视化区域）、小卡承载单点能力（图标 + 一句话），疏密有致、层级一眼可读。但绝大多数落地页的 Bento 只是「静态拼贴」：卡片大小写死、点击没有反馈，信息全摊在表面，首屏信息密度高却不深入。

本案例做一个纯原生、零依赖、零 CDN、双击离线即用的**可展开 Bento 特性网格**：在同一套 CSS Grid 栅格里排布约 6～8 张尺寸不等的特性卡（1×1 小卡、2×1 / 1×2 长条卡、2×2 主打卡），点击/键盘激活任意卡片后，该卡**在网格内部平滑放大展开**，露出更详细的说明、可视化演示与操作按钮，**其余兄弟卡片被栅格自动重新流式排布并以 FLIP 动画平滑让位**（先记录展开前位置 First、切换状态后记录新位置 Last、反转 Invert、播放 Play），全程不弹浮层、不跳路由、不刷新、网格容器不产生突兀跳动；再次点击、点击其他卡片或按 Esc 即收起/切换，展开与切换像液体填充一样连续。展开卡内部包含真实可交互的微型内容（如迷你图表、开关、参数示意），避免「展开只是多一段文字」。首屏卡片做一次克制的错峰入场，悬停有轻量提升与高光，全部动效尊重 `prefers-reduced-motion`（即时切换布局、仅保留透明度过渡或直接呈现），并提供完整键盘操作（Tab 聚焦卡片、Enter/Space 展开、Esc 收起、方向键可选地在卡片间移动焦点）与 ARIA 语义（卡片为 `button` 或带 `aria-expanded`、展开内容容器关联、展开/收起通过 `aria-live` 轻播报、焦点在收起后归还触发卡）。Micro-HUD 默认折叠，可实时切换网格密度（列数）、动效曲线/时长、是否允许同时仅展开一张等并查看当前展开项与栅格状态。

当前案例库 60 个已注册案例中，布局/栅格相关的交互组件有：`accordion-faq`（**垂直单列**手风琴，高度用 grid-rows 过渡展开问答）、`split-pane`（拖拽**分隔条**调节固定面板宽度，面板内容不变、不重排其他项）、`kanban-board`（Pointer 拖拽在**四列**间重排卡片，带浮动克隆与占位符）、`resizable-table`（表头手柄调列宽）、`swipe-card-deck`（叠放卡牌拖拽飞出，非网格）；在池 37 个 Ready 中检索 `bento / 网格 / feature grid / 磁贴 / 非对称 / FLIP`，无任何同主题条目（命中 `FLIP` 的 IDEA-035 飞入购物车是元素沿抛物线飞向购物车的一次性微反馈，命中「网格」的 IDEA-009 是 SVG 图表、IDEA-031 是表单，均非网格形变）。这是「产品官网首屏特性墙」这一高频真实生产场景里一个干净、实用、且与上述案例核心机制（栅格内 FLIP 让位形变）完全不同的空白。需要说明：工作台外壳 [index.html](../../index.html) / [playground.css](../../src/playground.css) 自身用了名为 “Gallery Bento Grid” 的卡片栅格，但那是外壳的静态展示布局、非可下载独立案例，本案例不触碰外壳。

## 预期展示效果

- **构图与整体风格**：
  - 案例视口是一张深色、哑光、克制的**产品特性展台**：居中一张有明确栅格节奏的 Bento 网格，卡片在统一的列/行轨道上做非对称排布——一张 2×2 主打卡承载核心特性（含一块主要可视化区域，如迷你数据看板/实时曲线/可操作小部件），一至两张 2×1 或 1×2 长条卡承载次重点特性，其余为 1×1 小卡（一枚内联 SVG 图标 + 标题 + 一句短描述）。
  - 卡片默认态信息克制（图标、标题、一句概述、一处暗示「可展开」的 affordance，如右下角小箭头/展开角标），展开态在卡内揭示更完整的说明、微型可视化与一两个真实操作控件；展开的是**同一张卡在栅格内占据更多轨道**，而非盖在其他内容之上的弹窗。
  - 延续项目暗色、低饱和、Anti-Slop 审美：卡片为近黑哑光面 + 极细描边 + 柔和圆角与极轻投影，仅允许主打卡/强调元素使用一处小面积语义强调色；拒绝霓虹满屏、红蓝紫渐变堆砌与大面积毛玻璃炫技。所有图标为内联 SVG，零外部图片/字体/请求。
  - 桌面宽屏为多列（如 4 列）非对称编排；平板降为较少列数（如 2～3 列）并保持非对称节奏；手机转为窄列（如 1～2 列），展开仍在网格内进行、页面自然增长高度而不横向溢出，触控热区充分。
- **主要视觉元素**：
  - **非对称特性卡矩阵**：6～8 张尺寸/跨度不同的卡片，主打卡含真实微型可视化（如会动的迷你柱图/曲线、一个可拨动的开关与联动状态、或参数示意），长条卡可放横向小图示，小卡放图标 + 短文案；卡片内容覆盖一个虚构产品的多种能力（如数据分析、自动化、协作、安全、集成、性能等），文案具体、不说空话。
  - **栅格内展开/收起形变**：激活某卡后其 `grid-column` / `grid-row` 跨度改变，浏览器栅格重新分配轨道，兄弟卡片流向新位置；整个过程用 FLIP 让**每张发生位移的卡片**从旧位置平滑滑到新位置，展开卡自身尺寸变化用同一节奏过渡，展开内容随展开淡入/轻微上移出现，收起时反向播放。
  - **展开内容区**：更详细的特性描述、微型可交互演示、主次操作按钮；点击另一张卡时当前卡收起、目标卡展开并再次触发整体 FLIP 让位（默认手风琴式单选，是否允许多卡同开由 HUD 可切换）。
- **层次、材质、光影与关键细节**：
  - 视觉三层：深色展台背景（可带极弱网格底纹呼应栅格，但不得喧宾夺主）→ Bento 卡片哑光面（统一描边与圆角，主打卡可有略强的层级区分）→ 卡内可视化/图标（最高信息焦点）。
  - **不跳、不闪、不叠影是底线**：FLIP 必须基于真实前后几何（getBoundingClientRect / offset 位置与尺寸），用 transform/scale 反演再过渡到恒等，避免直接对 width/height/top/left 动画造成的重排抖动；位移的卡片与改变跨度的展开卡节奏一致（统一时长与缓动），切换时不出现卡片重叠、残影或栅格容器高度突变（容器高度变化也应平滑）。
  - 悬停态轻量：卡片轻微上浮（translateY 极小）+ 描边/高光微亮，主打卡可随指针有极弱的高光跟随（可选），幅度克制；展开态有明确但不刺眼的选中样式（描边强调色 + 极弱内发光），状态不仅靠颜色（配合角标/aria）。
  - 动效曲线与时长参数化（如统一的 cubic-bezier 与 ~300–500ms 区间），既能干脆也能舒缓；入场仅在首屏播放一次的错峰显现，之后展开/收起不再重复入场。

> 设计文档约束最终体验与设计意图；具体卡片数量、每张卡跨度与文案、列数断点、FLIP 的实现写法（WAAPI `element.animate` 或 rAF/transform 反演）、缓动与时长默认值、展开内容里微型演示的具体形式由实现阶段按手感统一决定，不在此过早钉死；但「同一 CSS Grid 内非对称卡片 → 激活改变跨度 → 所有受影响卡片基于真实几何 FLIP 平滑让位 → 容器无突变、内容不重叠 → 可收起/切换且键盘与读屏完整可用」这条链路必须真实成立，不允许用浮层/弹窗盖在网格上冒充展开、不允许只对被点卡做动画而让其他卡片瞬跳、也不允许写死每张卡的绝对位置绕过栅格重排。

## 动态与交互

- **触发方式（多输入统一，非纯自动播放）**：
  - **指针**：鼠标点击或触屏点按卡片在网格内展开/收起；点击另一张卡切换展开目标；点击空白/关闭角标或按 Esc 收起；悬停有轻量提升反馈（触屏无悬停，以点按为准）。
  - **键盘**：卡片原生可聚焦（用 `button` 或带 `tabindex`/角色的可激活元素），Tab 顺序遵循视觉顺序，Enter/Space 切换展开，Esc 收起并把焦点归还原卡；可选方向键在网格卡片间移动焦点（实现时明确几何邻近导航规则，至少不破坏 Tab 顺序）；焦点环始终可见。
  - 展开内容内部若有可操作微件（开关/按钮/迷你图表），展开后焦点管理需明确（可把焦点移入展开内容或停留在触发卡，收起时归还触发卡），不使焦点丢失或陷入背景。
- **FLIP 形变引擎（核心逻辑）**：
  - 展开/切换/收起前记录所有受影响卡片的位置与尺寸（First）；改变被点卡的栅格跨度并让浏览器完成布局后记录新的位置与尺寸（Last）；对每张发生变化的卡片用 transform（translate/scale）从差值反演（Invert），再一帧过渡到无变换（Play）；展开卡内部「被缩放」的子内容需做反向补偿或仅对容器位移做 FLIP、对内层用透明/位移过渡，避免内容被拉伸变形（FLIP 常见的文字挤压问题要规避）。
  - 容器自身高度变化同步平滑；动画期间的快速连续点击（重入）需语义明确（取消未完成动画、以最新目标状态为准），不产生重叠、残影或卡在中间态；动画结束后清理内联 transform/动画对象，不残留样式。
- **控制与可配置项（Micro-HUD 默认折叠，`H`/`Esc` 切换、事件防穿透）**：网格密度/列数（桌面列数档位）、动效缓动曲线与时长、单选（手风琴式仅展开一张）/多选模式、入场动画开关、悬停高光开关；面板实时显示当前展开卡片、栅格列数与各卡跨度等真实状态。
- **可访问性（一等路径）**：
  - 卡片可激活语义正确（`button` 或 `role="button"` + 键盘支持），用 `aria-expanded` 表达展开态、`aria-controls` 关联展开内容容器，展开内容在收起时对辅助技术隐藏（`hidden`/`aria-hidden` 处理需与视觉一致）；展开/收起在阶段边界通过 `aria-live="polite"` 轻播报一次（如「已展开：数据分析」），不随动画逐帧刷屏。
  - 文案与控件对比度达 WCAG AA，焦点可见，状态不仅靠颜色区分；尊重 `prefers-reduced-motion`：默认不做位移动画（布局直接切换到最终态），可保留一次极短、非位移的透明度过渡，但**展开/收起、切换、键盘、微件交互的全部功能逻辑完整保留**。
- **移动端与触控**：窄屏列数与卡片跨度重排为可读的单列/双列，展开仍在文档流网格内进行、页面高度自然增长，不横向溢出；点按热区充分；视口变化（resize / 横竖屏切换 / 密度档位切换）后重新计算栅格与展开态位置，展开卡保持展开且不错位，FLIP 不在 resize 过程中制造抖动（resize 时可即时收敛）。
- **生命周期**：所有指针/键盘监听、resize/ResizeObserver、任何 rAF 或 WAAPI 动画对象在案例卸载（iframe 销毁）、页面隐藏时统一清理，无悬挂动画、无观察者与监听泄漏；切换案例后不在后台继续运行。

## 核心亮点

1. **补齐「产品特性墙」高频生产场景的空白**：Bento Grid 是 Apple/Linear/Vercel/Stripe 官网首屏的标志性布局语言，库内 60 案例与在池 37 个 Ready 无一覆盖非对称特性网格；本案例把「静态拼贴」升级为「可在栅格内展开探索」的交互式特性墙，可直接用于真实产品落地页/功能介绍区（实用性 5 分）。
2. **真实的多卡片 FLIP 让位引擎而非摆拍**：难点与亮点都在——被点卡改变跨度后，**所有**受影响兄弟卡片基于真实前后几何同步平滑位移、容器高度平滑、切换时无重叠/残影/中间态卡死，并解决 FLIP 常见的内层文字被 scale 拉伸问题；这是区别于「只动画一张卡、其他卡瞬跳」的工程严谨性展示点。
3. **非对称编排 + 主打卡真实微件的信息层级美学**：2×2 主打卡承载可操作微型可视化，长条/小卡疏密搭配，展开揭示更丰富内容而非多一段废话；以统一栅格轨道、哑光材质与一处强调色做出克制高级的层级，拒绝渐变堆砌与毛玻璃炫技的 AI Slop。
4. **完整交互面，严格规避纯自动播放**：点击/点按展开收起、卡片间切换、Esc、完整 Tab/Enter/Space/方向键、展开内真实微件、HUD 密度/曲线/单多选切换——把一个布局组件做成可探索的展台，而非加载即放完的动画。
5. **工程边界鲁棒 + 零资源离线**：重入/快速连点的动画取消与状态收敛、resize/横竖屏/密度切换后的不错位重算、reduced-motion 下功能完整的即时布局、aria-expanded/controls/live 的语义闭环与焦点归还、卸载统一回收监听/观察者/动画；内联 SVG 图标、系统字体栈、零图片零字体零 CDN，双击离线完整可用。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：src/playground.js 全部 60 个注册案例（id / 标题 / 描述 / tags）+ playground/effects、playground/components、playground/pages 物理目录（实测 12 effects / 45 components / 3 pages）+ 活动池 IDEA-001～IDEA-037（全部 Ready）+ rejected.md（当前为空）+ completed.md（当前为空）；另全仓检索 `bento / FLIP / 网格 / feature grid / 磁贴 / 非对称`。
- **相似案例**：
  - `accordion-faq`（手风琴问答）：最接近的「展开/收起」语义，但它是**垂直单列**列表，展开的是某一项自身的问答内容、靠 `grid-rows 0fr→1fr` 做单项高度过渡，下方兄弟项仅被线性下推；本案例是**二维非对称 CSS Grid**，激活卡改变 `grid-column/grid-row` 跨度，兄弟卡在行列轨道上**多方向流式重排**，且要对所有受影响卡片做 FLIP 位移、处理容器二维形变与主打卡可视化——结构（二维非对称网格 vs 单列）、形变（多卡 FLIP 让位 vs 单项高度过渡）与场景（产品特性墙 vs FAQ 列表）均不同。
  - `split-pane`（可调分栏）：同样涉及「面板尺寸变化引起重排」，但它通过**拖拽分隔条**改变的是少数几个固定容器的宽度，面板内容不切换、其他面板不做卡片式流式让位，也没有激活-展开的状态机；本案例尺寸变化由点击卡片的跨度切换驱动、影响的是一组离散卡片的二维排布。
  - `kanban-board`（拖拽看板）：同属「网格/轨道上的元素位置变化」，但它是**四列内纵向列表**，靠 Pointer 拖拽 + 浮动克隆 + 占位符指示落点完成**跨列手动重排**，是用户自由排序；本案例无拖拽、元素不离开自身卡片身份，是由展开状态驱动的**确定性栅格重排 + FLIP 形变**，目的是内容展开而非排序。
  - `resizable-table`（列宽可调数据表）与 `virtual-list`（虚拟滚动）：前者调的是表格列宽、后者是定高窗口化渲染，均为数据密集型表格场景，不涉及非对称特性卡的展开形变。
  - `swipe-card-deck`（叠放卡堆）与 `spotlight-cards`/`card`（3D/聚光卡片）：前者是叠层拖拽飞出，后两者是单卡悬浮/聚光微交互，都不是多卡二维栅格的协同重排。
  - 在池 IDEA 逐一核对：IDEA-035 飞入购物车虽使用 **FLIP 思路**，但那是**单个商品缩略图沿抛物线飞向购物车角标的一次性微反馈**，不改变任何布局轨道、无兄弟卡片重排；IDEA-015 视图转场是页面/共享元素转场、IDEA-002 轮播是幻灯片切换、IDEA-033 骨架屏是占位→内容、IDEA-009 图表/IDEA-031 表单等命中「网格」字样者均非网格形变；全池无 bento / feature grid / 磁贴墙主题。全仓 `bento` 仅命中工作台外壳 [index.html](../../index.html) 与 [playground.css](../../src/playground.css) 的 “Gallery Bento Grid”——那是**外壳静态画廊布局**、非独立可下载案例，本案例不触碰外壳；确认无历史（含已删除）`bento-grid` id 或物理目录冲突。
- **差异说明**：核心创意是「**一张非对称 CSS Grid 特性墙，激活卡片改变其栅格跨度，所有受影响卡片基于真实几何以 FLIP 同步平滑让位、容器高度平滑、展开卡在原位揭示可交互详情，且键盘/读屏/降级完整的产品首屏组件**」。与 accordion-faq 相比，差异在二维非对称网格多卡 FLIP 形变 vs 单列单项高度过渡；与 split-pane 相比，差异在点击驱动的离散卡片确定性重排 vs 拖拽分隔条的连续容器尺寸；与 kanban-board 相比，差异在状态驱动的展开重排 vs 指针驱动的自由排序；与 IDEA-035 相比，差异在多卡片布局轨道的协同形变 vs 单元素抛物线飞行。差异同时体现在核心创意、视觉表达（非对称哑光 Bento 矩阵 + 主打卡可视化 × 统一动效曲线）、交互方式（点击/键盘展开切换 + 密度/单多选 HUD + 卡内微件）与整体表现（产品特性展台）上，不属于换颜色、文案或微调参数类重复。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 HTML5 + CSS3 + ES6+，零框架、零第三方库、零动画库（FLIP 用原生 WAAPI `element.animate` 或 rAF + transform 手写）、零图标库/图标字体、零 CDN、零外部图片与外部字体（图标内联 SVG、系统字体栈），双击 `index.html` 完整离线可用（沿用案例三件套 `index.html` / `style.css` / `script.js`）。
- 布局必须基于真实 **CSS Grid 轨道**（`grid-template-columns` + 卡片 `grid-column/grid-row` 跨度），非对称卡片由栅格自动排布；展开/切换通过改变被点卡跨度并让浏览器重排实现，不得用绝对定位写死每张卡位置、不得用浮层/弹窗/覆盖层盖在网格上冒充展开、不得只动画被点卡而让兄弟卡片瞬跳。
- FLIP 必须真实：记录变化前后真实几何（位置与尺寸）→ transform 反演 → 过渡到恒等；所有发生位移的兄弟卡片与改变跨度的展开卡节奏一致，容器高度变化平滑；需规避内层文字/可视化被 scale 拉伸（对内容做反向补偿或仅对容器位移做 FLIP、内层改用透明/位移过渡）；快速连续操作时取消未完成动画并以最新状态收敛，动画结束清理内联 transform/WAAPI 对象，无重叠、残影、中间态卡死与残留样式。
- 交互必须多路径且非纯自动播放：点击/点按展开收起、点击他卡切换、Esc 收起、Tab/Enter/Space（可选方向键）完整键盘操作、展开卡内真实微件可操作；明确动画重入语义、焦点在展开/收起后的归属（收起归还触发卡）；resize / 横竖屏 / HUD 密度切换后重新计算且展开态不错位；所有监听、ResizeObserver/rAF/WAAPI 动画在卸载与页面隐藏时统一清理。
- 可访问性为一等路径：卡片可激活语义与 `aria-expanded`/`aria-controls` 正确，展开内容显隐与辅助技术可见性一致，`aria-live` 仅在展开/收起阶段边界播报一次；AA 对比度、可见焦点、状态不仅靠颜色；`prefers-reduced-motion` 下不做位移形变（布局即时到最终态，可保留极短非位移透明度过渡），但展开/切换/键盘/微件全部功能完整。
- 视觉为暗色哑光克制的产品展台：统一栅格描边与圆角、主打卡略强层级、仅一处小面积强调色，拒绝霓虹满屏与蓝紫渐变/毛玻璃炫技的 AI Slop；桌面/平板/手机按列数断点自适应、窄屏不横向溢出、触控热区充分。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（强制）；网格密度/列数、缓动曲线与时长、单选/多选、入场与悬停高光开关，以及当前展开卡片、列数、各卡跨度等真实状态，通过默认折叠的 Micro-HUD 提供（`H`/`Esc`、事件防穿透）。
