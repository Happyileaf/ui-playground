## 创意概述

基于浏览器原生 View Transitions API（`document.startViewTransition` + `view-transition-name` + `::view-transition-*` 伪元素）打造一个多场景交互展厅，演示“同一元素在两个视图状态之间自动形变（FLIP / shared element morph）”的现代网页过渡范式：点击缩略图平滑放大为大图灯箱、筛选/重排时卡片流畅位移、主题切换时圆形擦除扩散。目标是让开发者直接看到“零动画库、纯浏览器原生能力”完成过去需要 FLIP 库才能实现的高级过渡，并可一键提取单场景代码用于真实落地页。

> ID 协调说明：本创意最初按本地空池拟编号 IDEA-001，落盘时发现远端 PR #54（`...idea-exploration-r1`，基线同为最新 main、处于 OPEN 待审）已合规占用 IDEA-001（分步表单向导 form-wizard）。按探索 SOP「发现并发修改不得覆盖、先对齐 ID 序号」，本创意顺延为 IDEA-002，使用独立 `-r2` 分支交付，不改动 #54 任何内容。

## 预期展示效果

- **构图与整体风格**：
  - 延续项目深色精致工作台美学：暗色磨砂背景上以一张居中、有呼吸感的展厅舞台承载三个可切换的场景；顶部为极简场景切换胶囊（缩略图灯箱 / 筛选重排 / 主题擦除），场景之间淡入切换，不让切换器本身抢戏。
  - 每个场景内部都是“接近真实产品”的布局而非抽象 demo：灯箱场景为错落的作品集图片网格；重排场景为带标签筛选条的卡片墙；擦除场景为迷你设置面板。
- **主要视觉元素**：
  - 灯箱场景：6–9 个圆角图片卡（图片全部由纯 CSS 渐变/几何构造，零外部图片资源），点击后该卡“飞出”放大为居中灯箱大图，伴随遮罩柔和压暗；关闭时大图精准回缩回原缩略图位置。
  - 重排场景：若干带分类标签的作品卡，点击筛选胶囊后，命中的卡片以 View Transition 的平滑位置/尺寸插值重新排列，退出项淡出、进入项淡入，无跳变闪烁。
  - 擦除场景：明暗主题切换按钮，以点击点为圆心做圆形 clip-path 式揭示（通过给新旧根视图命名 + 自定义 `::view-transition-old/new` 的 clip-path/圆形遮罩动画实现）。
- **层次、材质、光影与关键细节**：
  - 过渡期间放大的共享元素带轻微阴影加深与圆角连续变化，营造“被拿起”的层级感；遮罩用半透明深色高斯模糊压暗背景。
  - 动效曲线克制有质感（偏 ease-out 的柔和曲线，时长短促），避免浮夸回弹；形变过程中图片内容保持清晰、不拉伸失真（靠双伪元素的宽高与 object-fit 自然过渡）。
  - 三个场景视觉语言统一：一致的圆角半径、间距节奏与强调色，但各自拥有可区分的材质（图卡、信息卡、面板）。

> 设计文档约束最终体验与设计意图；具体动画时长、缓动值、配色与 DOM 组织在实现阶段决定，不在此提前硬编码。

## 动态与交互

- **缩略图 → 灯箱**：鼠标/触摸点击缩略图触发 `startViewTransition`，浏览器自动完成缩略图到大图的共享元素 morph；点击遮罩、关闭按钮或按 `Esc` 关闭并反向回缩；灯箱打开时焦点进入、关闭后焦点归还触发缩略图，支持 `Tab` 与 `Enter/Space` 键盘操作。
- **筛选重排**：点击筛选胶囊或用左右方向键切换分类，卡片增删与位置重排全部包裹在一次视图过渡中；快速连续点击时以最后一次状态为准，避免动画堆叠错乱。
- **主题圆形擦除**：点击切换按钮，从指针位置扩散圆形揭示新主题；尊重系统/手动的明暗初始状态。
- **统一控制**：默认折叠的 Micro-HUD（沿用项目统一 HUD 规范，`H`/`Esc` 唤出、事件防穿透），可开关“原生视图过渡”以对比“无过渡的瞬时切换”，直观展示 API 价值。
- **移动端**：全部基于 Pointer 事件/点击，触控命中区域足够大；灯箱在窄屏自适应为近全宽。
- **减弱动效**：识别 `prefers-reduced-motion` 时，跳过/极简化视图过渡（瞬时切换或仅保留淡入），不产生大面积位移类动画。

## 核心亮点

1. **交互创意**：补齐项目完全空白的原生 View Transitions 技术域——用浏览器内建的共享元素过渡，零 GSAP/FLIP 库实现“缩略图↔灯箱”的精准往返 morph，这是当下真实网页（媒体站、电商、作品集）落地率极高的模式。
2. **表现形式**：一个展厅内串联三种最具代表性的原生过渡用法（共享元素形变、列表重排 FLIP、根视图圆形擦除），并提供“开关原生过渡”的实时 A/B 对比，教育价值与观赏性兼备。
3. **设计细节**：纯 CSS 渐变构造全部画面素材，保持案例 100% 离线零资源依赖；圆角、阴影、遮罩随形变连续变化，追求高级克制而非廉价炫技。
4. **工程严谨**：对不支持 View Transitions 的浏览器与 `file://` 双击打开场景做特性检测降级（瞬时切换，功能不丢失），而非直接报错。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：`src/playground.js` 全部 60 个注册案例（effects 12 / components 45 / pages 3）的 id/标题/描述 + `playground/` 全目录 + `rejected.md`（当前为空）+ `completed.md`（当前为空）+ 远端在审的 IDEA-001（PR #54 分支，尚未合入 main）。
- **相似案例**：
  - `capsule-tabs`（胶囊标签动效展厅）——同为“切换器 + 多形态动效展厅”结构；
  - `menu-morph`（汉堡形变导航）——含图标/遮罩形变；
  - `image-zoom`（商品放大镜）、`image-comparison-slider`（图片对比滑块）、`image-cropper`（图片裁剪器）——均涉及图片与几何形变；
  - `holo-card-studio` / `card` / `swipe-card-deck` ——含 3D/卡片转场；
  - IDEA-001 分步表单项导（form-wizard，PR #54 在审，尚未落地）——同属 components 且含“分步切换”。
- **差异说明**：
  - 上述已注册案例无一使用 View Transitions API。`capsule-tabs` 是单容器内指示条按物理曲线滑动，作用域是“同一组静态选项卡”；本案例是浏览器接管的**跨视图状态快照过渡**，自动处理元素在两个完全不同布局（网格 ↔ 全屏灯箱、筛选前后网格）间的位置/尺寸形变，核心机制（`startViewTransition` + `view-transition-name` + 新旧视图伪元素）与 CSS 动画驱动的指示条位移有本质区别。
  - `menu-morph` 是固定汉堡图标的预编排路径/遮罩动画；本案例的形变目标位置由真实布局动态决定（缩略图可在网格任意位置）。
  - `image-zoom` 是同页局部镜片放大、`image-comparison-slider` 是 clip-path 裁剪、`image-cropper` 是手柄变换，均不存在“元素在两个视图间共享身份并自动 morph”的概念；本案例的灯箱是独立覆盖层视图，且关闭时精准回到来源缩略图。
  - 3D 卡片类使用 transform/perspective，不涉及视图级过渡 API。
  - 与 IDEA-001（form-wizard）的差异：form-wizard 解决“长表单分步录入 + 校验 + 进度状态机”，其步骤切换是同一表单容器内的面板切换；本案例不涉及表单数据与校验，核心是跨布局共享元素的原生视图形变，二者问题域、交互方式与视觉表达完全不同，且本案例在 PR #54 正文的“下一轮建议（View Transitions 页面过渡）”中即被点名，属预期互补而非撞题。
  - 结论：核心创意（原生跨视图共享元素过渡）、交互方式（视图切换 + 键盘可达灯箱 + A/B 过渡开关）、整体表现（多场景原生过渡展厅）均构成实质差异，非换色或参数微调。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生零框架、零 CDN、零外部图片（画面用纯 CSS 渐变/几何构造），双击 `index.html` 可离线完整运行。
- 使用 View Transitions API 前必须做特性检测（`typeof document.startViewTransition === 'function'`）：不支持时降级为瞬时切换，保证灯箱开关、筛选、主题切换功能本身可用。
- 过渡必须尊重 `prefers-reduced-motion`；灯箱需焦点管理（打开聚焦、Esc/遮罩关闭、关闭后焦点归还）。
- 视觉 HUD 遵循项目统一 Title 胶囊 + 默认折叠 Micro-HUD 规范。
