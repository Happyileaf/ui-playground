## 创意概述

操作后的即时反馈是网页中最高频的反馈原语之一（保存成功、删除可撤销、复制完成、表单校验失败、网络异常）。站内**没有任何一个独立案例**覆盖这一方向：外壳层仅有一个仅供自身使用、单条固定文案、无堆叠无动作的内部 `showToast`；`notification-center` 解决的是需要回看的、持久化的通知中心，语义与生命周期完全不同。本案例做一个纯原生、零依赖、可直接投产的 Toast 轻提示系统：多条通知在屏幕角落**自动堆叠、互不遮挡**，支持成功/信息/警告/错误/加载五种语义类型、可选操作按钮（如「撤销」）、自动倒计时（悬停暂停）、手动关闭与横向滑动手势消除，具备完整 ARIA live region 无障碍播报与多方位停靠，并提供一个真实的设置/操作面板场景驱动各类提示。

## 预期展示效果

- **构图与整体风格**：
  - 以一个真实的操作场景承载（如「偏好设置 / 文件操作」演示台）：一组语义明确的触发按钮（保存更改、删除项目、复制链接、提交表单、模拟上传、触发错误），点击即在角落产出对应 Toast，避免出现脱离上下文的孤立通知。
  - Toast 视口（toast viewport）固定在屏幕一角（默认右下，可切换右上/左下/左上/顶部居中/底部居中），多条自上而下（或自下而上）堆叠，新通知从停靠边以位移 + 淡入方式进入。
  - 单条 Toast 为紧凑的横向卡片：左侧语义图标、中间标题 + 一行说明、右侧可选操作按钮与关闭按钮；加载态用细进度环或旋转指示表达。
- **主要视觉元素**：
  - 五种语义类型有可辨识但克制的色彩编码与图标（成功、信息、警告、错误、加载），图标使用内联 SVG；同类型连续触发时视觉一致。
  - 每条 Toast 底部（或侧边）有一条细倒计时进度条，直观表达「剩余停留时间」；进度在悬停/键盘聚焦/窗口失焦时同步冻结。
  - 可选动作按钮（如「撤销」「重试」「查看」）为低饱和的文字/描边小按钮，视觉权重低于通知本体但清晰可点。
- **层次、材质、光影与关键细节**：
  - Toast 采用深色毛玻璃背景（半透明 + backdrop blur）、1px 高光描边与柔和投影，明确悬浮于页面内容之上但不刺眼。
  - 堆叠时后一条以细微的缩放/透明度落差暗示层叠纵深；一条关闭时，其余条目以平滑的 FLIP 位移动画补位，而非生硬跳动或重排。
  - 进入为位移 + opacity 的弹性缓动；退出为向停靠边滑出并淡出；横向拖动跟手，超过阈值或快速轻扫（fling）即消除，未达阈值则弹性回弹。
  - 错误类默认不自动关闭（或停留更久），加载类由代码在异步结束时更新为成功/失败，状态切换在同一卡片内原位过渡，不新增一条。
  - 对最大同时显示数量做上限保护（超出时排队，关闭一条补一条），避免极端操作刷屏。

## 动态与交互

- **触发与生命周期**：点击演示台按钮产出对应类型 Toast；普通类型自动倒计时关闭，悬停/键盘聚焦时暂停倒计时并在移开后恢复；错误类需要更长停留或手动确认；加载类不自动关闭，由完成/失败动作原位更新。
- **手动关闭与手势**：点击关闭按钮立即消除；在 Toast 上横向拖动（Pointer Events 统一鼠标与触控）实时跟手位移与轻微透明，按位移阈值或轻扫速度判定消除，未达阈值弹性回弹；纵向滚动不被劫持。
- **动作按钮**：带动作的 Toast（如删除后「撤销」）点击动作后原位转为「已撤销」反馈再关闭；演示一条真实的删除→撤销链路。
- **键盘与无障碍（ARIA live region）**：Toast 视口为 `aria-live="polite"`（普通通知礼貌播报），错误类使用 `role="alert"` / assertive 及时播报；动作按钮与关闭按钮可 Tab 到达、焦点环清晰，Esc 可关闭最上层或当前聚焦的 Toast；通知出现时不强行抢夺焦点（除非是必须立即处理的阻断式错误，本案例以非阻断为主）。
- **停靠与排列**：可切换六个停靠方位，堆叠方向与进出场方向随方位翻转；窗口缩放时视口保持安全边距不超界。
- **连续触发与上限**：高频连点时正确排队与补位，不出现重叠、闪烁或动画堆叠；退出动画结束后节点被回收移除，无残留 DOM 与定时器。
- 适配 `prefers-reduced-motion`：关闭位移/弹性与 FLIP 动画，仅保留即时的透明度/状态切换，自动关闭逻辑不受影响。

## 核心亮点

1. **可直接投产的完整生命周期状态机**：进入 → 自动倒计时（悬停/聚焦/失焦暂停）→ 原位更新（加载→成功/失败）→ 手势/按钮关闭 → FLIP 补位 → 节点回收，覆盖真实业务全部路径，而非只能弹一条文字。
2. **堆叠、排队与 FLIP 补位**：多条通知自动堆叠、最大数量保护与排队、关闭后其余条目平滑补位，是区别于玩具级提示的关键完成度。
3. **消除手势与动作语义**：横向跟手拖动 + 阈值/轻扫消除 + 弹性回弹，并提供「撤销/重试」内联动作，演示真实删除撤销链路。
4. **严谨的无障碍播报**：polite 与 assertive 分级 live region、不抢焦点、键盘可达与 Esc 关闭，达到生产级反馈组件标准。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：src/playground.js 全部 60 个注册案例（id / 标题 / 描述 / tags）+ playground/effects（12）、playground/components（45）、playground/pages（3）物理目录 + rejected.md（当前为空）+ completed.md（当前为空）。
- **相似案例**：
  - 外壳层内部 `showToast`（`src/playground.js`）：是**工作台外壳自用**的极简单条提示（固定文案、2.4s 超时、无堆叠/类型/动作/手势/ARIA live 区域），不属于 `playground/` 下的独立案例，用户下载任一案例都不会得到它；本案例是独立、自包含、可导出的完整 Toast 系统。
  - `notification-center`（通知中心）：同为「消息反馈」，但它是顶栏铃铛驱动、**持久化、可回看、可筛选已读/未读的下拉面板**；Toast 是**瞬时、非阻断、自动消失、角落堆叠**的操作反馈，生命周期、信息架构与交互方式均不同。
  - `modal` / `drawer` / `guided-tour`：同为覆盖层，但它们是**阻断式、需要显式关闭决策**的大面板/导览；Toast 不阻断当前操作、不抢焦点、自动离场。
  - `top-loading-bar`：同为操作反馈，但仅表达页面顶部一条线性进度，无消息内容、无堆叠、无动作按钮。
  - `like-button` / `confetti-burst`：同有瞬时动效反馈，但分别是按钮局部迸放与全屏庆祝粒子，不是通知容器与反馈系统。
- **差异说明**：核心创意是**角落堆叠的瞬时反馈通知系统 + 倒计时/原位更新/排队补位生命周期状态机 + 滑动消除手势与内联动作 + 分级 ARIA live 播报**，与全部历史案例在核心创意、视觉表达（毛玻璃堆叠卡片 + 倒计时进度）、交互方式（手势消除、撤销动作、悬停暂停）上均无实质重叠；不是外壳 `showToast` 的换肤或 notification-center 的简化，不属于换色/换文案/微调参数类重复。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生零 CDN、双击 index.html 独立离线运行（通用项目铁律，详情不重复）。
- 手势统一使用 Pointer Events（配合 setPointerCapture），区分横向消除手势与页面纵向滚动；动画基于 transform/opacity 与 `requestAnimationFrame`，卸载时取消全部 rAF、定时器并移除监听、清空 Toast 节点。
- 补位动画建议使用 FLIP 思路记录/回放位置，避免布局抖动；同时显示数量设上限并排队，超出不新增 DOM 直到有空位。
- 图标一律内联 SVG，不引用外部图片、字体或网络资源。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊；类型/停靠方位/时长等演示控制使用默认折叠的 Micro-HUD（注意与 Toast 默认停靠位错开，不遮挡）。
- 尊重 `prefers-reduced-motion`（关闭位移与弹性，仅保留即时状态切换）；移动端满足触控热区标准。
