## 创意概述

一个高度拟真的「拖动滑块补齐缺口」人机校验组件（主流登录、注册、领券场景最常见的拼图验证码形态）。面板上方是一张带异形缺口的验证图，下方是一条轨道滑块；用户按住滑块沿轨道向右拖动，一块与缺口同形的拼图块同步平移，松手时若拼图块与缺口位置重合（容差内）即校验通过，否则滑块抖动回弹、缺口与拼图刷新到新位置并允许重试。校验全程纯前端模拟，不依赖任何服务端，验证图由 Canvas / CSS 程序化生成、零外部图片。

解决的体验问题：在注册、登录、风控确认等关键节点，产品普遍需要一道轻量、直观、跨端的人机校验；相比输入扭曲字符，「拖一下对准」的认知成本更低、移动端更友好，且过程本身（按住—跟手—对位—吸附判定）具备丰富的物理与状态反馈空间。当前案例库表单控件（OTP、银行卡、区间滑块等）覆盖密集，但没有任何「安全校验 / CAPTCHA」方向的组件，本 Idea 补齐这一实用缺口。

## 预期展示效果

- **构图与整体风格**：
  - 单屏居中一张验证卡片：顶部为验证图区（宽幅矩形，圆角），底部紧贴一条等宽滑块轨道；卡片右上角按工作台 HUD 规范放置点阵色 Title 胶囊。外层延续工作台深色高级质感，验证卡片本体采用克制的玻璃拟底，让验证图与滑块状态色成为视觉焦点。
  - 轨道左侧为可拖动的滑块手柄（带双向箭头 / 抓手图标），轨道内有「向右拖动完成拼图」之类的提示文字，拖动后文字淡出；验证图左上角可有低调的刷新按钮与状态标识。
- **主要视觉元素**：
  - 验证图：程序化生成的抽象场景（渐变 + 几何 / 流体质感的画面，避免具体照片带来的外部资源依赖），其上挖去一块**拼图形缺口**（带凸起 / 凹陷的异形轮廓，非简单方块），缺口处呈明显暗部描边以增强深度。
  - 拼图块：与缺口同形同尺寸的一块，初始位于验证图左侧（可上下错位），随滑块横向平移，带细微投影与边缘高光，呈现「浮在图上的一块」的层次。
  - 状态反馈：通过时拼图块与缺口融合、验证图泛起成功色调、轨道填充为成功语义色并出现对勾；失败时拼图块与轨道做水平抖动、转为警示语义色，随后刷新新缺口。
- **层次、材质、光影与关键细节**：
  - 拼图块与缺口共用同一段图案纹理（视觉上是从图上「抠下来」的一块），拼图块带柔和投影、缺口内沿带环境光遮蔽式暗边，对位准确时投影减弱、仿佛嵌回纸面。
  - 滑块轨道在拖动过程中有跟手的填充进度色与手柄按压态（轻微放大 / 更深阴影），营造「抓握并拖动」的触感。
  - 松手判定有明确节奏：命中容差 → 成功吸附（轻微过冲回弹后归位、对勾描边生长）；未命中 → 快速左右抖动 2～3 次后拼图块与进度一同阻尼回弹至起点，缺口位置重新随机。
  - 成功后可呈现一个模拟的「提交中 → 已验证」确认小状态条（纯前端演示，不请求服务端），并提供「再试一次 / 刷新」入口，形成完整闭环而非一次性动画。

> 设计文档约束最终体验与设计意图；具体容差像素、缺口随机范围、弹簧与抖动参数、色值由实现阶段按整体视觉统一决定，不在此过早钉死。

## 动态与交互

- **触发方式（Pointer Events 统一鼠标 / 触控 / 手写笔）**：
  - 在滑块手柄上按下（pointerdown）并水平拖动：手柄、轨道填充与拼图块实时跟手平移；垂直位移占优时不抢占（拖动被钳制在水平轨道内），通过 setPointerCapture 保证拖出轨道仍不丢失手势。
  - 松手（pointerup）判定：以拼图块中心与缺口中心的水平距离（异形块可含固定纵向偏移）对比容差区间——容差内吸附归位并进入成功态；容差外进入失败态，抖动后回弹、刷新缺口位置与背景纹理、重置滑块。
  - 点击验证图刷新按钮（或失败一定次数后）可手动换一组缺口 / 纹理；成功后提供「再验证一次」复位入口。
- **桌面端兜底**：鼠标按住拖动是主路径；手柄可聚焦，`→` / `←` 方向键以固定步进移动拼图块（配合长按连续移动），`Enter` / `Space` 在当前位置提交判定，使键盘用户也能完成校验。
- **键盘与可访问性**：
  - 滑块具备 `role="slider"`（或等价的 button + 明确可访问名称）、`aria-valuemin/max/now` 与「拖动完成安全验证」标签；校验结果通过 `aria-live` 礼貌播报「验证成功 / 未对齐，请重试」。
  - 色彩不是唯一的状态信息：成功 / 失败同时依赖对勾 / 警示图标与文字提示，避免色盲不可辨识。
  - 尊重 `prefers-reduced-motion`：减弱动效下去掉跟手弹性、过冲与抖动，改为即时对位与即时状态切换，功能完全保留。
- **移动端触控**：Pointer Events + setPointerCapture，正确设置 `touch-action`（横向拖动手势不触发页面滚动 / 文本选择），在手机视口模拟器与真机上单指即可顺滑完成。

## 核心亮点

1. **拟真的安全验证交互闭环**：按住—跟手平移—对位容差判定—成功吸附 / 失败抖动回弹—自动刷新重试，完整复刻线上主流滑块验证码的真实手感与状态节奏，而非只做一个能拖动的静态条。
2. **零资源依赖的「抠图」一致性**：验证图程序化生成，拼图块与缺口共用同一图案区域并辅以投影 / 暗边 / 融合反馈，在不引入任何外部图片的前提下做出「一块图被抠下又嵌回」的材质层次。
3. **丰富而克制的多态反馈**：手柄按压态、轨道进度填充、命中时对勾描边生长与过冲回弹、未命中时警示色抖动，状态语义明确且不浮夸。
4. **跨输入方式的高可访问性**：指针、鼠标、键盘（方向键步进 + Enter 提交）三条等价路径，ARIA 滑块语义与 aria-live 结果播报、非纯色状态编码、减弱动效适配——在安全类组件上同样不牺牲可达性。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 HTML5 + CSS3 + ES6+，零框架、零第三方库、零 CDN，双击 `index.html` 完整离线可用（沿用案例三件套 `index.html` / `style.css` / `script.js`）。
- 验证图与拼图块零外部图片：以 Canvas（DPR 适配）或纯 CSS 渐变 / 几何程序化生成，且须保证拼图块与缺口区域图案严格同源对位。
- 手势统一用 Pointer Events + setPointerCapture 并钳制水平位移，正确设置 `touch-action`，避免与页面滚动冲突；不引入密集计算循环，拖动以 rAF / 直接 transform 驱动。
- 内联 SVG 图标（抓手、对勾、刷新、警示），不使用任何外部图片 / 字体资源；校验纯前端模拟，不发起网络请求。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊；如需控制面板（调节容差、是否显示提示、自动刷新开关等）默认折叠并支持 `H` / `Esc`。
