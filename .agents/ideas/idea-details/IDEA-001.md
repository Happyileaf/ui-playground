## 创意概述

把一段较长、容易让用户产生心理负担的表单（典型如账号注册、服务开通、收货结账、档案建档）拆分为 3–4 个语义清晰的步骤，用一个有明确进度反馈、分步即时校验、可随时回看修改的引导式向导承载。解决「长表单一眼望不到头、出错定位困难、中途放弃率高」的体验问题，是可直接落地到真实网页的生产级交互组件。

## 预期展示效果

- **构图与整体风格**：
  - 画面中心为一张克制、高级的卡片式向导面板，延续项目既有的深色磨砂质感（细腻边框、柔和投影、毛玻璃层级），不追求花哨堆砌。
  - 卡片自上而下分为三层：顶部「进度步进器（Stepper）」、中部「当前步骤内容区」、底部「操作栏（上一步 / 下一步 / 提交）」。
  - 演示场景建议围绕一条完整、真实可信的业务主线组织（例如「开通一个数字工坊空间」：账号信息 → 个人/团队资料 → 偏好与方案 → 确认提交），让四个步骤有自然的信息递进，而非无意义的字段切割。
- **主要视觉元素**：
  - 水平步进器：圆点/序号节点 + 节点之间的连接线；已完成节点呈现完成态（对勾或实心填充）、当前节点高亮带呼吸/光环、未到达节点为静默态；连接线随步骤推进以「从前到后填充」的方式延展。
  - 步骤内容区：标题 + 简短引导副文案 + 该步骤字段（文本输入、密码、单选/分段选择、开关、选择框等原生控件组合）。
  - 底部操作栏：左侧次要的「上一步」、右侧主按钮「继续 / 完成」，主按钮在提交瞬间可呈现加载/成功态。
  - 终点：最后一步为「信息确认总览」，提交后切换为成功完成态（成功标识 + 简要回执 + 可重新开始）。
- **层次、材质、光影与关键细节**：
  - 卡片与背景之间用细微明度差与柔和阴影拉开层级；当前步骤节点的高亮使用统一主题色光晕，已完成态用同色系收敛表达，避免彩虹色泛滥。
  - 字段聚焦时有清晰但克制的聚焦环/边框提亮；错误态以明确色彩 + 字段下方内联错误文案表达，错误出现时配合一次短促、低幅度的抖动反馈。
  - 步骤切换时旧内容退出、新内容进入具备明确的方向感（前进向左退出/自右进入，后退反之），过渡快速、利落、不喧宾夺主。
  - 进度连接线的填充与节点状态变化、内容区过渡在节奏上协调统一，形成「推进一格」的整体仪式感。

> 设计文档应充分约束最终体验与设计意图，但除非属于创意不可缺少的约束，不要过早限定具体算法、代码组织、精确尺寸或颜色值。

## 动态与交互

- **触发方式**：点击「继续/上一步」按钮、直接点击步进器上**已完成**的节点回跳、键盘操作、在末步提交。
- **分步校验**：点击「继续」时只校验当前步骤字段；存在错误时阻止前进、聚焦第一个错误字段并显示内联错误与轻微抖动；通过后才允许进入下一步。字段在用户修正后错误态可即时或在下次尝试时清除。
- **进度联动**：前进时连接线向前填充、节点从当前态转为完成态；回退时保留用户已填数据，已填步骤在步进器上仍可识别并可点击跳回。
- **方向感过渡**：根据前进/后退方向播放相反的水平位移动画；使用 CSS 过渡即可实现，内容区高度随步骤内容自然适配（允许高度平滑过渡或直接切换，但不应出现明显跳动闪烁）。
- **末步与完成态**：确认总览以分组只读形式回显此前输入，并提供每一组的「修改」入口直接跳到对应步骤；点击提交后主按钮进入加载态，随后整体切换到成功完成态，提供「再填一次/重新开始」。
- **键盘与可访问性**：
  - 完整键盘可用：Tab 顺序合理，Enter 在单行文本中可触发「继续」，步进器节点支持方向键/聚焦与回车跳转。
  - 当前步骤标题通过 `aria-current`/`aria-label` 等方式向辅助技术表达进度；错误字段以 `aria-invalid`、`aria-describedby` 关联错误说明；步骤切换后焦点移动到新步骤标题或首字段，避免焦点丢失。
  - 使用语义化表单结构（`form`、`label`、`fieldset/legend` 等）。
- **移动端触控**：窄屏下步进器可收敛为更紧凑的表达（如「第 2 / 4 步」+ 细进度条，或保持小尺寸节点），按钮与字段满足触控尺寸，面板以内边距与安全区适配，内容可纵向滚动。
- **减弱动效偏好**：尊重 `prefers-reduced-motion`，关闭位移/抖动/呼吸等非必要动效，以即时状态切换呈现，信息与功能不受影响。
- 纯前端演示：数据不落库、不请求服务器；末步提交可用延时模拟，随后进入成功态。可选地以极轻量的 Web Audio 在推进/完成时提供触感反馈，但须手势后懒激活、默认克制，非必需。

## 核心亮点

1. **「推进一格」的整体仪式感**：进度连接线填充、节点状态翻转、内容区方向感滑动三者节奏统一，让抽象的「完成度」变得可感知。
2. **真正可用的分步校验与回看**：按步骤即时校验、错误精确定位与焦点管理；确认总览可一键回跳任意已完成步骤修改且数据不丢失，区别于只能前进的演示玩具。
3. **生产级信息架构与无障碍完成度**：真实业务主线、完整 ARIA/键盘/焦点管理、移动端与减弱动效适配，是可直接用于注册/结账/建档场景的高可访问性组件，而非仅换配色的普通表单。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：`src/playground.js` 全部注册案例（约 55 个，逐一核对 id/标题/描述）+ `playground/components`、`playground/effects`、`playground/pages` 目录 + `rejected.md`（当前为空）。
- **相似案例**：
  - `auth`（LUMEN 登录与空间注册）：单屏双栏的登录/注册表单，含表单校验与流体画布背景。
  - `otp-input`：单一的六位验证码分段输入控件。
  - `payment-card-input`：单屏支付表单 + 实时 3D 卡面预览与卡号校验。
  - 另参考但非同类：`accordion-faq`（手风琴，仅展开折叠）、`capsule-tabs`（标签切换动效）、`guided-tour`（遮罩聚光引导，面向页面功能介绍而非数据录入）。
- **差异说明**：
  - 现有案例均为**单屏/单控件**的数据录入，不存在跨多步、带「步骤状态机 + 进度步进器 + 连接线填充 + 分步即时校验 + 方向感切换 + 末步总览回改 + 完成态」的引导式长表单。
  - 核心创意不同：本 Idea 的核心是**流程化进度体验与分步校验/回看**，而非某个字段控件或单屏视觉；`guided-tour` 虽也分「步」，但它是页面元素聚光解说、不采集和校验表单数据，交互模型与产物完全不同。
  - 视觉表达不同：进度节点 + 连接线填充 + 方向感内容过渡为本案独有；与 `auth` 的流体背景、`payment-card-input` 的卡面 3D 翻转无重叠。
  - 故与历史案例存在实质差异，非仅换颜色/文案/微调参数。

## 实现约束（仅记录该案例必要的约束）

- 纯原生 HTML5 + CSS3 + ES6+，零框架、零构建步骤、零 CDN/外部资源；案例目录自包含，双击 `index.html` 即可完整运行（含模拟提交）。
- 遵循项目统一 HUD 规范：右上角固定点阵色 Title 胶囊；如引入参数控制面板，默认折叠并支持快捷键与事件防穿透（本组件交互已足够丰富，控制面板非必需）。
- 动效与音频（如选用）须支持 `prefers-reduced-motion`，音频须用户手势后懒创建 `AudioContext`。
- 校验与状态全部在前端完成，不发起真实网络请求；不依赖任何外部图片/字体服务。
