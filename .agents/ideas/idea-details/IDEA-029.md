## 创意概述

「点击中央按钮，圆盘高速旋转数圈后在一枚固定指针下缓缓停住，指针所落扇区即中奖结果」的幸运大转盘，是电商大促、会员签到、线下活动、游戏化运营里最高频的抽奖原语之一（wheel of fortune / spin-to-win）。它的体验核心不是让一个圆盘「转起来」，而是一套可信、可复现、可配置的**加权抽奖 + 物理减速旋转**闭环：用户点击 GO 后，系统先依据每个奖项的**真实权重概率**抽出结果，再反推目标角度，让圆盘以「起步即有冲量、中段匀速疾驰、末段带阻尼回摆」的物理节奏精确停在目标扇区中央；停转瞬间给出克制而明确的中奖揭晓（结果卡 / 光效 / 音效），并提供「再来一次」复位与剩余次数等真实运营约束。

当前案例库在营销互动方向已有在池的刮刮乐（IDEA-025，Canvas 笔刷擦除揭示）、庆祝彩带（confetti-burst）、双击点赞（like-button）等，但没有任何「**绕轴旋转 + 固定指针读数 + 加权概率命中**」的转盘原语；刮刮乐解决的是「亲手涂抹揭晓」，彩带解决的是「结果后的粒子庆祝」，二者都不含连续旋转、指针读数与加权落点计算。本案例做一个纯原生、零依赖、可直接投产的 Lucky Wheel：以一个**拟真运营活动卡片**承载可配置奖项（文案 / 颜色 / 权重 / 图标）、真实加权抽样、旋转过程锁定与防作弊（结果在旋转前确定、动画只负责呈现）、结果揭晓与再抽，并遵循减弱动效、键盘可达与统一 HUD 规范。

## 预期展示效果

- **构图与整体风格**：
  - 画面中央是一张**拟真抽奖活动卡片**（延续项目深色玻璃质感、圆角、克制留白与柔和投影）：顶部为活动标题与剩余次数 / 规则入口，中部是绝对视觉焦点——圆形幸运转盘，底部是结果揭晓后才激活的「立即领取 / 再抽一次」操作区。
  - 转盘采用**「圆盘旋转、指针固定」**的经典读法：一枚立体指针（或倒三角）固定在圆盘正上方（12 点位置）不随盘转动，圆盘外圈有灯珠 / 描金边环，中心是一枚高对比的圆形 GO 按钮（同心圆金属 / 玻璃质感）。
  - 卡片外（桌面宽屏）留白处放置极简用法提示小样（如「点击中央按钮开始 · 也可按空格旋转」）；窄屏下转盘等比缩放占满宽度，标题与操作区转为上下结构。
  - 右上角按工作台 HUD 规范放置点阵色 Title 胶囊（固定于案例视口内）。
- **主要视觉元素**：
  - **扇区盘**：由奖项数据程序化绘制的等分（或按权重视觉等宽、仅概率不等）扇区环，相邻扇区高饱和但和谐的双色交替（或品牌色梯度），扇区内径向排布奖项文案与内联 SVG / emoji 图标，文字沿径向或切向排布、保证不溢出扇区；盘心与盘缘有同心描边和内阴影，体现盘面厚度。
  - **固定指针**：12 点位置一枚带投影的立体指针（倒三角 / 宝石形），停转时其尖端明确指向唯一扇区分界内的中央读数线；指针可在停转瞬间做一次极轻的「点头 / 颤抖」反馈。
  - **外圈氛围**：盘缘一圈装饰灯珠（可选跑马灯式明灭），旋转时与转速联动、停转后收敛；灯珠是氛围而非信息载体，关闭后不影响读数。
  - **结果揭晓**：停转后指针下扇区做一次克制的高亮（外发光 / 描金扫光 / 轻微放大），卡片底部或居中浮层呈现结果（奖项图标 + 名称 + 领取按钮），中奖与「谢谢参与」通过图标、文案、版式共同区分，不仅靠颜色。
- **层次、材质、光影与关键细节**：
  - 盘面是「外圈灯珠环 → 彩色扇区盘 → 中心 GO 按钮」的三层同心结构，靠内阴影、描边高光与轻微径向渐变制造盘面凹陷与中心凸起的纵深，而非一张平面饼图。
  - 动效节奏是本案例的灵魂：起步有瞬间冲量（快加速）、中段保持高角速度疾驰、末段以指数衰减 / 自定义 cubic-bezier 缓动减速，并在逼近目标时叠加**极轻微的过冲回摆（可选）**模拟惯性，但回摆不得越过相邻扇区分界、不得造成读数歧义；最终指针稳定落在目标扇区中央容差区内。
  - 结果在点击 GO 的瞬间（旋转前）即由加权抽样确定，旋转动画只负责把既定结果演到指针下——避免「看动画算结果」的前端作弊与可预测性；落点角度在目标扇区内加一个小的随机偏移（不越界），使每次停的位置不机械重复。
  - 旋转中 GO 按钮与卡片操作进入禁用 / loading 态（防止连点产生并发旋转），剩余次数同步扣减；次数用尽呈现明确终态（置灰 + 文案），而非按钮无响应。
  - 可在 Micro-HUD 查看各奖项的配置权重与「本轮命中奖项」（演示 / 调试用），但默认界面不暴露概率表，贴近真实活动。

> 设计文档约束最终体验与设计意图；扇区数量、圈数、旋转时长、缓动曲线参数、灯珠密度、随机偏移容差与具体色值由实现阶段按整体视觉统一决定，不在此过早钉死。

## 动态与交互

- **触发方式（Pointer / 键盘统一）**：
  - 点击（pointerdown / click）中心 GO 按钮启动一次旋转；按钮具备真实键盘焦点，Tab 可聚焦、Enter / Space 触发等价旋转。
  - 旋转启动后立即：扣减剩余次数 → 依据权重抽样确定结果 → 计算目标角度（当前角度基础上追加若干整圈 + 到目标扇区中央的角度，并加入不越界的随机偏移）→ 锁定输入开始动画。
  - 动画结束（transitionend / rAF 计时收敛）后：解锁、高亮指针下扇区、指针轻反馈、弹出结果揭晓并通过 `aria-live` 礼貌播报中奖名称；「再抽一次」在有剩余次数时重新启用。
- **加权概率与落点**：
  - 每个奖项含 `label / color / weight / icon`；抽样按权重线性扫描或前缀和 + 随机数实现，结果分布应与配置权重一致（可在 Micro-HUD 提供「连续抽 N 次统计分布」的可验证演示，但不强制）。
  - 角度计算以固定 12 点指针为读数基准，正确换算扇区索引到角度（考虑扇区绘制起始角与旋转方向），保证「抽中哪个扇区，指针最终就指向哪个扇区」严格一致，零错档。
  - 多次旋转采用**累加角度（单调递增）**而非复位归零，避免反向回转与重置跳变；「再抽一次」后盘从当前角度继续同向旋转。
- **结果与运营状态机**：`idle（可抽）→ spinning（锁定、次数已扣）→ result（揭晓，可领取 / 再抽）→ idle / exhausted（次数耗尽终态）`；纯前端模拟领取（可注入成功 / 失败分支），真实环境可替换为发奖接口回调；旋转中不响应会造成状态错乱的二次操作。
- **可访问性**：
  - GO 按钮使用语义化 `button` 并具可访问名（如「开始抽奖」）；旋转过程对屏幕阅读器以 `aria-live="polite"`（必要时 `aria-busy`）播报「正在旋转…」与最终「恭喜获得 X / 谢谢参与」；奖项不仅靠扇区颜色区分（同步有图标 + 文案）。
  - 尊重 `prefers-reduced-motion`：减弱动效下关闭多圈疾驰与灯珠跑马，改为少量角度 / 直接把盘定位到结果扇区（可保留一次极短的不透明度 / 高亮过渡），抽样、读数、结果播报与状态机完整保留，键盘用户可完整完成抽奖。
  - 转盘图形信息有等价的文本 / 语义兜底（奖项列表或结果文案），不依赖纯视觉读图。
- **移动端触控**：中心 GO 按钮热区足够大（不小于典型 44px 触达），单指点击即转；转盘使用 transform 合成、等比缩放（容器查询 / viewport 单位 / ResizeObserver），在手机视口下不变形、不横向溢出；旋转期间禁用误触的多次启动。
- **可选 Micro-HUD**（默认折叠，`H` / `Esc` 切换、事件防穿透）：调整旋转圈数 / 时长、切换减弱动效对照、查看权重表、注入「指定中奖奖项」用于演示落点准确性、连续抽奖分布统计、音效开关；非必需时至少保留右上角 Title 胶囊。

## 核心亮点

1. **补齐高频营销抽奖原语空白**：库内 60 个案例与在池 28 个 Ready Idea 中没有任何「绕轴旋转 + 固定指针读数 + 加权概率命中」的 Lucky Wheel；它是电商大促 / 签到 / 会员运营 / 线下活动的通用抽奖交互，成品可直接嵌入真实活动页对接发奖接口，实用性 5/5。
2. **真实加权抽样与精确落点，而非纯演出玩具**：结果在旋转前按权重抽出、角度反推、指针零错档；累加角度不回转、扇区内随机偏移不机械重复；概率与动画解耦（结果先定、动画只呈现），既贴近生产实现又防前端作弊。
3. **有物理感的旋转节奏**：起步冲量、中段疾驰、末段阻尼减速与可选的不越界轻微回摆，配合盘心 / 盘缘三层纵深材质、外圈灯珠联动与停转指针轻反馈，把「等一个结果」做成有期待感的仪式，而非匀速计时转圈。
4. **完整运营状态机与边界**：idle / spinning / result / exhausted 全态、剩余次数扣减与终态、旋转中防并发、中奖与谢谢参与多态、领取 / 再抽、可注入发奖成败，覆盖真实活动分支。
5. **键盘一等路径 + 零资源依赖**：Tab / Enter / Space 可完整抽奖，aria-live 播报过程与结果，图标 + 文案 + 颜色共同表达奖项；盘面、灯珠、奖项图标全部由 Canvas / CSS 渐变 / 内联 SVG 程序化构造，无外部图片 / 字体，双击离线即用；减弱动效下功能与读数完整。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 HTML5 + CSS3 + ES6+，零框架、零第三方库、零 CDN，双击 `index.html` 完整离线可用（沿用案例三件套 `index.html` / `style.css` / `script.js`）。
- 转盘扇区、灯珠、奖项图标与盘面材质零外部图片：优先 Canvas 2D（DPR 适配高清屏）或纯 CSS conic-gradient + 内联 SVG 程序化绘制；具体绘制技术由实现阶段按画质与性能权衡，不在此钉死。
- 概率与动画必须解耦：点击瞬间先按权重抽样确定结果，再反推目标角度并播放动画；角度换算以固定 12 点指针为读数基准，保证抽中扇区与指针最终指向严格一致（零错档），多次旋转累加角度、不复位回转，扇区内随机偏移不得越出该扇区分界。
- 实现可信单一状态机（idle / spinning / result / exhausted）：旋转中锁定 GO 与操作区防并发，剩余次数扣减与耗尽终态明确；发奖为纯前端模拟、可注入成败，真实环境可替换为 Promise 回调。
- Pointer 与键盘均可完成完整流程（按钮语义化、Tab 可达、Enter / Space 旋转）；提供 aria-live 过程与结果播报，奖项以图标 + 文案 + 颜色共同区分，不仅靠颜色；结果信息对不读图用户有文本兜底。
- 尊重 `prefers-reduced-motion`（关闭多圈疾驰 / 灯珠跑马 / 回摆，可短过渡或直接定位到结果扇区，抽样 / 读数 / 播报 / 状态机完整）；转盘等比缩放适配窄屏、不横向溢出；GO 触控热区充分。
- 如引入音效，Web Audio 必须在用户手势内懒激活 AudioContext，并允许在 Micro-HUD 关闭。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（强制）；如需参数控制（圈数 / 时长、权重表、指定中奖、分布统计、音效、减弱动效对照）使用默认折叠的 Micro-HUD（`H` / `Esc`、事件防穿透）。
- 卸载或切换案例后清理事件监听、rAF / 定时器与过渡回调，避免后台继续旋转或重复回调。
