## 创意概述

多步骤流程（结账支付、账号注册、资料完善、问卷填报）是网页中最高频的「容器型」交互原语之一：把一段长任务拆成可预期的若干小步，配进度指示、分步校验与前进/回退导航。历史案例库中已有大量独立表单控件（OTP、银行卡、取色器、区间滑块、可搜索下拉、日历待开发）与弹层组件，却缺少把这些控件组织进**线性多步流程**的容器。本案例做一个纯原生、零依赖的步骤向导：顶部带连接器进度填充的步骤指示器、中部分步内容的方向感动画切换、底部上一步/下一步操作栏，内置分步校验拦截、任意回看、ARIA 向导语义与完整键盘支持，并以一个真实的「四步结账」流程承载演示，可直接作为生产环境流程容器使用。

## 预期展示效果

- **构图与整体风格**：
  - 以真实「结账 / 注册」场景承载（推荐四步结账：配送信息 → 配送方式 → 支付信息 → 确认下单），避免无上下文的空壳向导；整体延续项目深色玻璃质感、圆角与克制留白的语言。
  - 桌面端为一张居中的毛玻璃流程卡片，自上而下分三区：顶部步骤指示器、中部分步内容区、底部操作栏（左侧辅助操作如「退出/保存草稿」，右侧「上一步 / 下一步（提交）」）。
  - 窄屏下步骤指示器自动收敛：保留当前步与总步数文字（如 `第 2 步 / 共 4 步`）与一条整体进度条，节点标签可隐藏或横向滑动，内容区与操作栏全宽可用。
- **主要视觉元素**：
  - **步骤指示器**：圆形或圆角节点（序号；完成态切换为对勾 SVG）+ 节点之间的连接器（connector）。连接器在进入下一步时沿水平方向被填充（`scaleX` transform-origin: left），填充动画有明确的「进度向前推进」方向感。
  - 节点四态：待完成（描边/低对比）、当前（主色实心或主色光环 + 轻微放大/呼吸）、已完成（主色实心 + 对勾）、错误（当前步校验失败时节点短暂描边警示色并轻抖动一次）。
  - 分步内容区：每步一个面板，切换时旧面板按方向淡出 + 横向位移退出（前进向左、后退向右），新面板反向淡入位移进入，形成翻页式空间感；内容高度变化时容器高度平滑过渡而非跳动。
  - 底部操作栏与卡片边界有细分隔；「下一步」为主按钮（末步变为带确认语义的提交按钮），「上一步」为次按钮，首步隐藏或禁用「上一步」；提交进行中按钮进入 loading 态（内联 spinner），完成后进入成功终态视图。
  - 字段错误为内联提示（输入框下方小字 + 警示色描边），不用阻断式 alert。
- **层次、材质、光影与关键细节**：
  - 卡片为半透明深色 + backdrop blur、1px 高光描边与柔和投影；步骤节点当前态有一圈柔和外发光。
  - 进度填充与面板切换统一使用弹性/阻尼缓动曲线（与项目现有 spring 语言一致），节奏短促克制（约 200–350ms 量级），不拖沓。
  - 完成全部步骤后呈现与项目 confetti 语义不重复的**流程内成功态**：成功图标描边绘制动画 + 摘要信息（如订单号、配送方式）+「重新开始」；庆祝彩带不属于本案例范围。
  - 键盘焦点环清晰且与 hover 态分离；当前步骤节点通过 `aria-current="step"` 标记。

## 动态与交互

- **前进与校验拦截**：点击「下一步」先执行当前步字段校验（必填、格式等）；全部通过才推进，连接器填充动画与面板切换同步播放；存在错误时不推进，聚焦到第一个错误字段并展示内联错误，指示器当前节点给一次错误反馈动效。
- **回退与任意回看**：「上一步」返回上一步（不丢弃已填数据、不强制重新校验）；已完成的节点可直接点击跳转回看，回看后再向前推进仍需通过该步校验；不可点击的未来步骤节点处于禁用态。
- **键盘操作**：
  - 向导内 Tab 顺序逻辑正确，操作栏按钮可达；
  - 步骤节点支持方向键（←→/↑↓）在可访问步骤间移动焦点、Enter/Space 跳转；
  - 提交按钮在 loading 态禁用，避免重复提交；
  - Esc 不破坏流程数据（如无弹层则不绑定破坏性行为）。
- **真实流程数据**：四步内容覆盖真实结账要素——配送信息（姓名/地址等文本字段）、配送方式（单选卡片组：标准/加急/自提，选择影响末步摘要与可选的费用显示）、支付信息（卡号等字段，仅复用原生输入、不依赖 payment-card-input 案例）、确认页（只读订单摘要 + 条款勾选）。已填数据在回退/前推间保持。
- **成功与重置**：末步提交模拟异步（按钮 loading → 成功终态）；「重新开始」清空演示数据并回到第一步，进度连接器与节点复位。
- **可选 Micro-HUD**：如需演示参数（动画开关等），使用默认折叠的统一 Micro-HUD（`H`/`Esc` 切换、事件防穿透）；非必需时可只保留右上角 Title 胶囊。
- 适配 `prefers-reduced-motion`：关闭连接器填充位移与面板滑动，改为即时切换 + 透明度过渡（或纯即时），功能与状态表达完整。

## 核心亮点

1. **线性流程状态机容器**：不是单控件，而是把「当前步 / 已完成步集合 / 每步校验结果 / 提交状态」组织成清晰的状态机，任意回看而不丢数据、未来步不可越级、前进必过校验——可直接承载真实结账/注册流。
2. **有方向感的进度叙事**：连接器沿方向填充、当前节点光环、完成态对勾、面板前进/后退方向相反的位移动画，整套动效在叙事上明确表达「进度向前/回退」，而非简单的显隐切换。
3. **完整 WAI-ARIA 向导语义**：`tablist`/`tab` 或带 `aria-current="step"` 的步骤列表语义（二者择一保持自洽）、面板 `aria-labelledby` 关联、错误字段 `aria-invalid`/`aria-describedby` 关联提示、错误摘要可被屏幕阅读器感知；完整键盘可达。
4. **真实业务闭环与成功终态**：从填写、分步校验、回退改单、摘要确认、提交 loading 到成功终态与重新开始，形成可投产完整度的端到端体验；窄屏收敛为进度文字 + 进度条，移动端可用。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：src/playground.js 全部 59 个注册案例（id / 标题 / 描述 / tags）+ playground/effects、playground/components、playground/pages 目录 + rejected.md（当前为空）+ completed.md（当前为空）。
- **相似案例**：
  - `accordion-faq`（手风琴问答列表）：同为「多个分区 + 展开切换 + 键盘漫游」，但手风琴是可任意开合的并列 FAQ 内容，无线性顺序、无分步校验拦截、无进度状态机与前进/回退导航；
  - `capsule-tabs`（胶囊标签动效展厅）：同为多面板切换，但是并列 tab 展示，不含步骤顺序、完成态、校验与流程提交；
  - `otp-input` / `payment-card-input` / `combo-box` / `range-slider` / `color-picker`：同为表单控件，但解决单个字段的输入，不组织多步流程；本案例以结账场景**内置**原生字段演示，不复用、不依赖上述案例；
  - `modal` / `drawer`：同为容器型弹层，但承载的是瞬时内容，无多步进度与校验叙事；
  - `guided-tour`（新手引导）：也有「上一步/下一步/跳过」与步骤气泡，但其本质是**遮罩挖空的页面导览**，步骤是静态讲解、无表单数据、无分步校验、无提交流程与成功终态，进度指示形态与业务语义完全不同；
  - 活动池中的 `IDEA-001`（Date Picker）/ `IDEA-004`（Tags Input）等：均为单一输入原语，非流程容器。
- **差异说明**：核心创意是**线性多步流程状态机 + 进度轨道叙事 + 分步校验拦截**，历史案例中无任何多步骤表单/结账/注册流程容器；与 guided-tour 的步骤按钮仅在控件外观层面相似，核心创意（表单流程 vs 页面讲解）、视觉表达（连接器进度轨道 + 对勾节点 + 方向感面板切换 vs 聚光灯遮罩气泡）、交互方式（校验拦截/不可越级/数据保持/提交成功态 vs 自由上一步下一步/可跳过）与整体表现均存在实质差异，不属于换色、换文案或微调参数类重复。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生零 CDN、双击 index.html 独立离线运行（通用项目铁律，详情不重复）。
- 演示字段使用原生表单元素与内联 SVG 图标，不引用其他案例代码、不引入校验/动画库；分步校验以声明式规则（必填/格式）配合少量原生 JS 完成。
- 连接器填充与面板位移动画优先使用 transform/opacity（合成层属性），切换动画期间防止连续点击导致的状态错乱（如过渡未结束再次推进时以状态机判定为准）。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊；如需参数控制，使用默认折叠的 Micro-HUD（`H`/`Esc`、事件防穿透）。
- 尊重 `prefers-reduced-motion`；窄屏步骤指示器收敛，触控热区达标；切换/卸载案例时清理监听与定时器。
