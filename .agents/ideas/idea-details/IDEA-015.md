## 创意概述

现代网页的内容从「列表 / 网格」切换到「详情页」时，传统做法要么整页生硬跳变，要么依赖重型路由框架才能做连贯过渡；浏览器原生 **View Transitions API**（`document.startViewTransition` + 命名元素跨视图形变）让纯原生页面也能实现「卡片缩略图无缝放大展开成详情大图」的共享元素转场，是当前最值得掌握的原生页面动效能力之一。全仓 60 个已注册案例虽覆盖大量组件、粒子与微交互，活动池 IDEA-001~014 也已排期日期、轮播、Toast、标签、开关等组件，却**没有一个使用或演示 View Transitions / 跨视图共享元素转场**（技术域 3「导航与页面切换」除被动滚动揭示与进度条外几乎空白）。本案例做一个纯原生、零依赖的**视图转场画廊**：在一个不刷新页面的拟真小型作品浏览应用内，演示网格缩略图 ↔ 详情大图之间的共享元素形变、列表筛选 / 排序时元素的 FLIP 式重排转场、以及页面层级的淡入滑移，全程使用原生 View Transitions API，并为不支持的浏览器提供行为等价、观感克制的降级方案，让案例在任何浏览器双击打开都完整可用——既是可直接照搬到真实画廊 / 电商 / 资讯站点的转场范式，也是一份原生视图转场能力的活文档。

## 预期展示效果

- **构图与整体风格**：
  - 延续项目统一的深色玻璃质感（半透明深底、细描边、柔和投影、克制的强调色），主体是一个**拟真作品浏览应用**：顶部为细工具栏（应用名 / 分类筛选 chips / 排序切换），下方是规整的响应式卡片网格（封面、标题、一行元信息）；点击任一卡片后，网格视图被一个**详情视图**取代。
  - 详情视图包含与被点卡片同源的**大封面（共享元素主角）**、标题与描述正文、返回按钮；整体布局为大封面 + 文字内容的阅读式版面，与网格卡片形成明确的「缩略 → 展开」空间关系。
  - 右上角统一点阵色 Title 胶囊（遵循 HUD 规范）；画面无满屏粒子、无炫技堆叠，重点是「元素从哪来、到哪去」的空间连贯性。
- **主要视觉元素**：
  - **共享元素形变（核心视觉）**：被点击卡片的封面（或卡片整体）被标记为命名视图元素，转场时它从网格中的位置与尺寸，沿浏览器自动计算的路径平滑形变 / 位移到详情页大封面的位置与尺寸；其余网格内容淡出退出、详情其余内容淡入滑移进入，形成电影式「聚焦展开」。
  - **反向收合转场**：从详情返回时，大封面沿原路回缩回网格中对应卡片的位置，其余内容反向退场，强调「原路返回」的空间记忆。
  - **筛选 / 排序重排转场**：点击顶部分类 chip 或切换排序时，保留下来的卡片以 FLIP（首末位置插值）方式平滑滑动到新位置，被过滤掉的卡片淡出、新进入的卡片淡入，而非整块列表瞬间重排。
  - **视图层级背景转场**：两个视图的整体背景 / 容器可带极轻微的明暗或模糊差异，在转场中平滑过渡，烘托层级推进；所有封面图以**纯 CSS 渐变 / 几何图形 / 内联 SVG** 构造，零外部图片、零字体文件。
- **层次、材质、光影与关键细节**：
  - 共享元素是唯一视觉主角，转场期间它应浮于其他内容之上（利用视图分组与层级控制），描边与圆角从卡片态连续插值到详情态，避免出现「矩形框跳变」；阴影随放大同步增强，营造「拿起、靠近」的浮起感。
  - 时长与缓动统一且克制：形变与位移使用一条带轻微减速的曲线，主体（共享元素）与背景内容的节奏错开——背景内容先让出、主角再到位，细节文字最后淡入，形成层次而非齐步走。
  - 网格卡片本身保持规整、低噪声：统一圆角、细描边、悬停轻微抬升；详情页大封面给足视觉重量，正文排版有舒适行宽与行距。
  - 不支持 View Transitions 的环境：切换仍**完整可用**，降级为即时切换或一段轻量 CSS / 手动 FLIP 过渡（不出现报错、不卡死、不丢失内容）；`prefers-reduced-motion` 下直接在终态间切换或仅保留极短淡入。

## 动态与交互

- **点击卡片进入详情（核心触发）**：点击 / 轻触网格卡片，调用原生视图转场：标记被点封面为共享命名元素，DOM 在转场回调内从网格态切换为详情态，浏览器自动生成旧视图快照与新视图，封面由网格位置形变展开为详情大图，其余元素按分组淡入淡出 / 滑移。
- **返回（按钮 / 浏览器后退 / Esc）**：提供显式返回按钮，并尽量对接 `history.pushState` + `popstate`，使浏览器后退 / 前进也走同一条反向共享元素转场；Esc 与按钮等价返回。转场必须处理「源卡片已因筛选变化而不在当前网格中」的边界（此时退化为整体淡入淡出，不报错、不定位错乱）。
- **分类筛选与排序**：顶部 chips 切换分类、按钮切换排序（如按标题 / 元信息排序），触发一次视图转场：留存卡片 FLIP 滑动、移除项淡出、新增项淡入；连续快速切换时以最后一次操作为准，不出现卡片错位或残影。
- **悬停与聚焦微反馈**：卡片 hover 轻微抬升 + 封面微光；键盘 Tab 可遍历卡片与工具栏，Enter / Space 打开详情，焦点在进入详情后移至详情容器或返回按钮，返回后焦点还原到原卡片（参考既有 modal/drawer 的焦点管理范式）。
- **可访问性与减弱动态**：视图切换后语义焦点正确、内容可被读屏识别（视图容器使用合适的标题层级 / `aria-label`，转场不把内容藏在不可访问的快照里）；遵循 `prefers-reduced-motion`，关闭形变与滑移，仅做即时或极短淡入切换；降级路径下键盘与读屏体验同样完整。
- **移动端触控**：窄屏网格自适应为单列 / 双列，封面与文字不溢出；触控目标足够大，转场在中低端设备上流畅（以 transform / opacity 等合成友好属性为主，避免大面积昂贵滤镜）。

## 核心亮点

1. **填补全仓「原生视图转场」能力空白**：60 个历史案例与活动池 IDEA-001~014 无任何 View Transitions / 共享元素跨视图转场实现，技术域 3（导航与页面切换）长期偏弱；本案例把浏览器最现代的原生页面动效能力以可投产形态补齐，可直接套用到真实画廊、电商列表详情、资讯流。
2. **共享元素形变的电影式空间叙事**：缩略图沿空间路径连续放大成详情大图、返回时原路回缩，配合背景内容让场、文字延迟入场的层次节奏，呈现「拿起一张卡片看详情」的连贯心智，区别于整页淡入淡出或简单位移。
3. **同框演示两类经典转场**：网格↔详情的共享元素形变 + 筛选排序的 FLIP 重排，一个案例覆盖真实内容类应用最高频的两种视图变化，并含浏览器前进 / 后退、Esc、源卡片消失等真实边界处理。
4. **零依赖、全环境可用的工程完整度**：以原生 `startViewTransition` 为首选并做能力检测，对不支持的浏览器提供行为等价的即时切换 / 手动 FLIP 降级，保证「双击 index.html 任何浏览器完整可用」的铁律；配合焦点管理、`prefers-reduced-motion`、内联构造的零资源封面，达到可直接落地的生产质量。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：src/playground.js 全部 60 个注册案例（components 45 / effects 12 / pages 3，含 id / 标题 / 描述）+ playground/effects、playground/components、playground/pages 三个物理目录 + rejected.md（当前为空）+ completed.md（当前为空）+ 活动池 IDEA-001~014。并以 `startViewTransition`、`view-transition`、`ViewTransition`、`共享元素`、`页面转场`、`FLIP`、`视图转场` 关键字全仓检索（**全仓零命中**，亦无 `view-transitions` 目录或案例 id）。
- **相似案例**：
  - `scroll-reveal`（IntersectionObserver 滚动入场）/ `vertical-timeline`（滚动揭示）/ `infinite-feed`（骨架屏 + 入场）：同属「内容进入视口」的动态效果，但它们都是**单向、滚动触发的入场动画**，元素之间没有跨视图的空间对应关系；本案例是**两个视图状态之间、由同一元素首尾位置驱动的双向共享形变**，核心机制（View Transitions 快照 / 命名元素）与交互模型（点击进入、原路返回、历史栈）完全不同。
  - `menu-morph`（汉堡形变导航，遮罩扫入、链接错峰上滑）：名称含 morph、也做「界面切换」，但它是**单页内导航菜单的开关转场**（遮罩 + 文字入场），不存在列表缩略图与详情大图之间的共享元素对应，也不使用 View Transitions API 或 FLIP 重排；视觉叙事与机制均不同。
  - `card` / `holographic-card` / `holo-card-studio` / `embossed-foil-card` / `spotlight-cards`：都是**单张卡片自身的悬停 3D / 光影**，状态停留在卡片内部；本案例的卡片是**视图导航的入口**，重点是卡片跳出网格、形变成为另一视图的主体，而非卡片本身的材质特效。
  - `swipe-card-deck`（拖拽卡牌堆）/ `kanban-board`（拖拽看板，含占位重排）：kanban 拖拽时有元素重排，但那是**指针拖拽驱动的同列表重排**；本案例的筛选 / 排序 FLIP 是**数据变化后离散视图状态间的自动重排**，且另有网格↔详情共享形变主线，目的与机制不同。
  - `modal`（dialog 弹窗）/ `drawer`（四向抽屉）：同属「从主界面进入一个覆盖层」，也有焦点管理与 Esc，但它们是**浮层覆盖在原页面之上**（底层视图仍在），本案例是**两个对等视图之间的替换式转场**，共享元素从网格位置「长」到详情位置，配合浏览器历史栈前进后退，而非遮罩浮层。
  - 页面类 `app-layout` / `auth` / `pricing` 与活动池 IDEA-008（Chat Workspace）、IDEA-002（Carousel 轮播）：均为单一布局 / 组件演示，无跨视图共享元素转场；IDEA-002 轮播是同区域幻灯片切换，与「网格↔详情」空间展开不同。
- **差异说明**：核心创意是**「在纯原生拟真作品浏览应用中，用 View Transitions API 把网格缩略图与详情大图做成同一元素的双向共享形变，并辅以筛选排序的 FLIP 重排与历史栈导航，同时为不支持的浏览器提供行为等价降级」**。与最接近的 scroll-reveal（单向滚动入场 vs 双向跨视图共享形变）、menu-morph（菜单开关遮罩转场 vs 列表详情共享元素）、modal/drawer（浮层覆盖 vs 对等视图替换）、kanban-board（拖拽同列重排 vs 数据驱动 FLIP + 详情展开）在核心创意、视觉表达（命名元素首尾位置连续插值、背景让场、文字延迟入场）、交互方式（点击 / 返回 / Esc / 浏览器前进后退 / 筛选排序）与整体表现（零刷新作品浏览应用）上均有实质差异，非换色、换文案或微调参数。全仓检索确认无历史（含已删除）同名 id 或目录，案例 id 定为 `view-transitions`。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生零 CDN、零框架、零库，双击 index.html 独立离线运行（通用项目铁律，不重复）。
- 转场能力以特性检测为界：`'startViewTransition' in document` 时走原生 View Transitions（含 `view-transition-name` 命名共享元素与 `::view-transition*` 自定义动画 / 缓动 / 时长）；**不支持时必须提供行为等价的降级路径**（即时切换视图，或用 FLIP / CSS transition 手动实现近似的位移与淡入淡出），确保任何浏览器下进入详情、返回、筛选、排序、键盘与历史栈功能完整，不允许把「仅 Chromium 可用」当成完成。
- 网格封面等所有画面元素一律用 CSS 渐变 / 几何图形 / 内联 SVG 构造，**不得引入外部图片、图标库、字体或任何网络资源**；作品数据为内置静态数据，筛选 / 排序在本地完成。
- 对接 `history.pushState` / `popstate` 时须正确处理直接进入详情态、浏览器前进后退、以及「返回目标卡片已不在当前筛选结果中」的边界（降级为整体淡入淡出，不得抛错或布局错乱）；转场进行中再次触发操作时要有明确的中止 / 以最后一次为准策略，避免快照残影与卡片错位。
- 动效以 transform / opacity 等合成友好属性为主，控制转场层级与截图面积，避免大面积高成本滤镜导致中低端设备卡顿；统一在 iframe 卸载时移除事件监听、中止未完成转场并清理 rAF / 定时器。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊；如需调节（转场开关、缓动曲线 / 时长、降级路径预览、减弱动效预览等），使用常驻演示控件 + 默认折叠 Micro-HUD（`H`/`Esc`、事件防穿透）。本案例默认不需要音效。
- 尊重 `prefers-reduced-motion`：关闭共享形变与 FLIP 滑移，仅在终态间即时切换或保留极短淡入，但所有导航、筛选、排序、键盘与历史栈功能保持完整。
