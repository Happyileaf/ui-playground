## 创意概述

「列表滚动到顶部后继续向下拖拽，超过阈值松手即触发刷新」是移动端信息流、邮箱、社交、天气、任务列表里最高频的刷新原语（iOS/Android 系统级交互、Twitter/微信/Gmail 等应用的共同肌肉记忆）。它的体验核心不是一个转圈图标，而是一套完整的**手势手感语言**：下拉位移随手指增长但有**橡皮筋阻尼**（越拉越费劲）、越过触发阈值时指示器「就位」的确认反馈、松手后的**弹簧回弹与定高刷新态**、刷新成功后顶部内容的注入更新，以及未达阈值松手时的无损复位。

当前案例库在手势方向上已覆盖卡牌飞出（swipe-card-deck）、横滑露操作（在池 IDEA-021）、跨列拖拽（kanban-board）、滑块类与向下无限加载（infinite-feed），却唯独缺少这个**纵向「到顶续拉」的刷新手势原语**；而 infinite-feed 解决的是反方向的「滚到底加载更多」，没有顶部手势、没有阻尼手感、没有刷新状态机。本案例做一个纯原生、零依赖、可直接投产的 Pull-to-Refresh：以一个**拟真移动端信息流卡片流 + 手机视口框架**承载，用自定义手势（Pointer Events 统一鼠标 / 触控 / 手写笔，不依赖不同浏览器不一致的原生 overscroll 回弹行为）实现阻尼拉伸、阈值就位、松手判定、定高刷新、成功注入与失败重试的完整状态机，桌面端可按住鼠标体验、键盘用户有等价刷新按钮，并遵循减弱动效与统一 HUD 规范。

## 预期展示效果

- **构图与整体风格**：
  - 画面中央是一台**拟真手机视口框架**（圆角机身、顶部状态栏时间/信号以纯 CSS 与文本构造），机屏内是一条**可独立滚动的深色信息流**：顶部为应用标题栏（含标题与一个显式「刷新」图标按钮，作为无手势设备 / 键盘用户的等价入口），下方为若干拟真内容卡片；卡片头像、配图、文本条全部由内联 SVG 与 CSS 渐变 / 骨架条构造，零外部图片。
  - 手机框架外（桌面宽屏）左右留白处可放置极简的**状态节奏小样 / 文案提示**（如「下拉 → 就位 → 松手 → 刷新中」），引导用户在桌面端按住机屏内容向下拖拽；窄屏下手机框架退化为整屏容器，操作的就是内容本身。
  - 整体延续项目深色玻璃质感、圆角、克制留白与柔和投影语言；右上角按工作台 HUD 规范放置点阵色 Title 胶囊（固定于案例视口内）。
- **主要视觉元素**：
  - **弹性拉伸区**：下拉手势中，信息流整体（标题栏 + 卡片）随指针纵向平移，顶部露出与机身同色系的拉伸轨道；位移增长遵循递减阻尼，后半程明显「拉不动」，形成橡皮筋手感。
  - **环形手势指示器**：轨道中央为一枚紧凑的环形进度符号（内联 SVG 圆弧 + 箭头）：下拉进度对应圆弧描边生长与箭头小幅旋转；越过触发阈值的瞬间给出「就位」确认（弧闭合、箭头翻转或换为强调色，配合一次轻微的弹性 overshoot）。
  - **刷新定高态**：松手触发后内容回弹，指示器停留在一个**固定高度**的轨道内持续旋转（刷新中），不再随手势漂移；成功时旋转弧短暂 morph 为对勾、失败时呈现克制的警示色重试提示。
  - **内容更新**：刷新成功后 1–2 张新卡片自轨道下方**插入列表顶部**并带短暂高亮 / 入场（与 scroll-reveal 的入场语言一致但独立实现），让「刷新到了新内容」有肉眼可见的结果。
- **层次、材质、光影与关键细节**：
  - 拉伸轨道与信息流为同一材质纵深：轨道压暗一档、内容卡片在其之上平移，边界不出现穿帮缝隙；指示器在轨道中做轻投影 / 描边，保证在深色与卡片交界处都清晰。
  - 动效节奏沿用项目 spring 语言：手势中位移实时跟手（阻尼曲线），松手后用基于 rAF 的弹簧 / 阻尼动画归位或落到刷新定高，时间为数百毫秒量级、带轻微 overshoot；取消（未达阈值）与触发（达阈值）的回弹曲线有可感知区别。
  - 阈值「就位」瞬间可选用一次极轻的 Web Audio 咔哒声（遵循手势内懒激活 AudioContext 的项目惯例，可在 Micro-HUD 关闭），只做触感确认、不喧闹。
  - 刷新中手势被**锁定**（再次下拉不产生二次触发、不跟手）；失败态允许立即重新下拉或点击重试；所有色彩区分同时伴随图标 / 文案语义，不仅靠颜色。

## 动态与交互

- **手势触发与状态机**：
  - 仅当滚动容器 `scrollTop === 0` 且指针纵向位移占主导时才进入下拉（先做短暂方向判定 / 方向锁，避免与横向手势及页面滚动手势冲突）；容器使用 `overscroll-behavior: contain`，在移动端阻止浏览器原生下拉刷新 / 页面橡皮筋干扰自定义手感。
  - 完整状态：`idle → pulling（阻尼跟手，圆弧随进度生长）→ ready（越过阈值，指示器就位）→ refreshing（松手判定：达阈值则回弹到定高、执行异步刷新；未达阈值则弹簧复位回 idle）→ settling（成功后插入新卡片并收回轨道 / 失败显示重试后收回）`，最终回到 idle；刷新全过程为单一可信状态机，刷新中重复手势 / 连点刷新按钮均不产生重复请求。
  - 异步刷新为纯前端模拟（定时器占位），Micro-HUD 可注入「失败」分支演示失败提示与重试；真实环境中该状态机可直接替换为 fetch 回调。
- **多输入统一**：Pointer Events（pointerdown / move / up / cancel）配合 setPointerCapture 统一鼠标、触控与手写笔；桌面端在机屏内按住向下拖即可体验；指针异常中断（cancel / 失焦）安全复位，不卡在中间态。
- **键盘与可访问性等价路径**：标题栏「刷新」按钮可 Tab 聚焦，Enter / Space 触发同一刷新流程（刷新中按钮显示 loading 并禁用）；指示器纯装饰 `aria-hidden`，刷新结果通过容器上的 `aria-live="polite"` 礼貌播报（如「已更新 2 条内容」/「刷新失败，请重试」）；手势不是完成任务的唯一途径。
- **减弱动效**：遵循 `prefers-reduced-motion`——关闭阻尼跟手与弹簧 overshoot，改为手势 / 按钮触发后指示器以固定高度淡入淡出，功能、状态机与播报完整。
- **可选 Micro-HUD**（默认折叠，`H` / `Esc` 切换、事件防穿透）：阻尼强度、触发阈值（下拉距离 / 进度）、模拟刷新时长、成功 / 失败注入、音效开关；非必需时至少保留右上角 Title 胶囊。
- 移动端触控：热区为整个滚动内容区，顶部到顶续拉；窄屏手机框架退化为整屏；不触发浏览器缩放 / 选择干扰（必要的 touch-action 与 user-select 约束仅限交互区）。

## 核心亮点

1. **补齐手势体系里最高频的缺失原语**：库内 60 个案例无任何「到顶续拉刷新」；与反方向的 infinite-feed（哨兵无限加载）、横向的 swipe-action-list / 飞出的 swipe-card-deck 在手势方向、触发条件与用途上都不同，是可直接用于生产 App / 移动 H5 的标准组件。
2. **真实手感而非转圈玩具**：橡皮筋阻尼跟手、阈值「就位」确认、松手弹簧回弹 / 定高刷新、刷新中手势锁定、成功内容注入与失败重试——覆盖生产级下拉刷新的完整状态机与边界（未达阈值取消、指针中断、刷新中重复触发）。
3. **跨端一致 + 无手势可替代**：自定义手势不依赖浏览器原生回弹差异，Pointer Events 统一桌面 / 移动；同时提供键盘可达的刷新按钮、`aria-live` 结果播报与减弱动效降级，避免「只能触屏玩」的演示陷阱。
4. **拟真场景零资源依赖**：手机框架 + 信息流卡片全部内联 SVG / CSS 构造，双击离线即用；刷新结果以顶部新卡插入 + 高亮的方式肉眼可验。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：src/playground.js 全部 60 个注册案例（id / 标题 / 描述 / tags）+ playground/effects、playground/components、playground/pages 物理目录（实测 12 effects / 45 components / 3 pages）+ 活动池 IDEA-001～IDEA-026 + rejected.md（当前为空）+ completed.md（当前为空）。
- **相似案例**：
  - `infinite-feed`（无限加载信息流）：场景同为信息流、同样有模拟异步与骨架屏，但它是**滚动到底部**由 IntersectionObserver 哨兵触发「加载更多」，无顶部手势、无下拉阻尼、无阈值与松手判定；本 Idea 是**到顶续拉的纵向手势刷新原语 + 完整手感状态机**，方向与交互结构相反。
  - `swipe-card-deck`（弹性拖拽卡牌堆）：同样有指针拖拽、阈值与弹性回弹，但对象是**单张卡片的离轴旋转飞出 / 撤回**，无滚动容器「到顶」前提、无刷新定高态与内容更新语义。
  - 在池 IDEA-021（滑动操作列表）：**横向**滑动列表行露出操作按钮，手势方向与用途均不同。
  - `kanban-board`（拖拽看板）：按住卡片**跨列重排**（长按 + 浮动克隆 + 占位符），非滚动边界续拉、无刷新语义。
  - `range-slider` / `image-comparison-slider` / `split-pane`：均为沿轨道的受控拖拽控件，与滚动位置耦合的刷新手势无关。
  - `top-loading-bar`（顶部加载进度条）：模拟路由请求的顶部 trickle 进度，**由代码驱动、无任何手势输入**；本 Idea 的核心恰是手势手感与触发判定。
  - `scroll-progress-bar` / `scroll-reveal`：只读消费滚动位置（进度指示 / 入场揭示），不捕获、不变形滚动内容。
  - `signature-pad`：Pointer Events 手写板，捕获指针绘制路径，但不与滚动边界耦合、无释放触发与异步状态机。
  - 活动池 IDEA-001～IDEA-026（日期选择 / 轮播 / Toast / 标签输入 / 步骤向导 / FAB / 液态下载按钮 / 聊天页 / SVG 图表 / 级联 / 评分 / 分页 / 时钟选时 / 开关合集 / View Transitions / 灯箱 / 贝塞尔工坊 / 翻牌倒计时 / 表情 / 提及 / 横滑列表 / 滑块验证码 / 方向感知图廊 / 穿梭框 / 刮刮乐 / Popconfirm）无任何 Pull-to-Refresh 主题。
- **差异说明**：核心创意是「**滚动容器到顶后纵向续拉的阻尼手势 + 阈值就位与松手判定 + 定高异步刷新状态机（成功注入 / 失败重试 / 刷新锁定）**」。历史案例中没有任何下拉刷新原语：与最接近的 `infinite-feed` 相比方向相反（顶部手势刷新 / 底部哨兵加载）、且新增完整手感与释放判定；与 `swipe-card-deck` / IDEA-021 / `kanban-board` 相比，触发前提（scrollTop=0）、位移轴向与目的（刷新数据并更新列表顶部）均不同；与 `top-loading-bar` 的本质区别是「用户手势驱动」而非「代码驱动的进度展示」。差异体现在核心创意、交互方式（到顶续拉 / 阻尼 / 阈值松手）、视觉表达（拉伸轨道 + 环形就位指示器 + 弹簧回弹）与整体表现上，不属于换颜色、文案或微调参数类重复。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 HTML5 + CSS3 + ES6+，零框架、零第三方库、零 CDN，双击 `index.html` 完整离线可用（沿用案例三件套 `index.html` / `style.css` / `script.js`）。
- 手势必须**自行实现**（Pointer Events + setPointerCapture + rAF 弹簧 / 阻尼），不依赖浏览器原生 overscroll 回弹与原生 pull-to-refresh；滚动容器设置 `overscroll-behavior: contain` 并处理 touch-action，保证移动端不与浏览器自身行为冲突、桌面鼠标可完整演示。
- 仅在 `scrollTop === 0` 且纵向方向占优时进入手势，带方向锁；刷新中锁定重复触发；pointercancel / 失焦 / 卸载须安全复位并清理监听、定时器与 rAF。
- 演示信息流、手机框架、图标与配图全部内联 SVG / CSS 构造，无外部图片 / 字体 / 网络请求；异步刷新为纯前端模拟（可注入失败分支）。
- 如引入音效，Web Audio 必须在用户手势内懒激活 AudioContext，并允许在 Micro-HUD 关闭。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（强制）；如需参数控制使用默认折叠的 Micro-HUD（`H` / `Esc`、事件防穿透）。
- 尊重 `prefers-reduced-motion`（关闭阻尼跟手与弹簧，改为固定高度淡入淡出，功能与播报完整）；窄屏触控热区与不溢出视口由设计保证。
