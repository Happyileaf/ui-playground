## 创意概述

「音乐一响，画面随节拍与频段实时呼吸、翻涌、发光」的音频反应可视化（audio-reactive visualizer），是播放器大屏、播客录音页、线上演出直播、品牌发布站与 DJ / VJ 场景里最具氛围感的视觉原语之一。它的体验核心不是画一组循环摆动的装饰条，而是一条真实可信的信号链路：**音频源 → Web Audio `AnalyserNode`（FFT 实时频域 / 时域分析）→ 每帧驱动 Canvas 视觉**——低频鼓点砸下时画面整体下沉、辉光增强并溅起粒子，中高频人声 / 镲片亮起时对应频段的光柱与波形真实抬起，静音与暂停时画面归于平静，做到「看到的就是听到的」，而非与声音无关的预设动画。

当前案例库 60 个案例中，真正把 Web Audio 作为一等能力的只有 `interactive-piano`（键盘弹奏乐器合成），`fireworks` / `confetti-burst` / `dynamic-dock` / `capsule-tabs` / `swipe-card-deck` / `auth` / 全息卡等仅把 Web Audio 用作一次性短促音效（one-shot SFX）反馈；Canvas 动画类（`kinetic-silk`、`living-constellation`、`particle-text` 等）的运动全部来自指针、预设噪声或生成式物理，**没有任何案例读取真实音频信号做频谱分析**。本案例做一个纯原生、零资源、双击离线即用的 Audio Spectrum Visualizer：内置一段由 Web Audio 振荡器 + 调度鼓点实时合成的演示循环作为默认音源（不依赖任何音频文件，保证 file:// 离线完整可看可听），并可选接入麦克风（`getUserMedia`）与本地音频文件（`<input type="file">` + 解码播放）；提供镜像柱谱 / 环形辐射频谱 / 环形波形三种呈现模式、灵敏度与平滑等实时参数，以及节拍辉光反应，遵循减弱动效、键盘可达与统一 HUD 规范。

## 预期展示效果

- **构图与整体风格**：
  - 画面以近黑深色为底（延续项目克制的暗色玻璃审美，拒绝蓝紫渐变堆砌的 AI Slop 廉价感），绝大部分面积留给随声音律动的可视化主体；底部（或下部悬浮玻璃条）是一条极简播放控制区：播放 / 暂停、模式切换、音源切换（演示合成曲 / 麦克风 / 本地文件）。
  - 默认进入时不自动发声（浏览器自动播放策略 + 手势解锁 AudioContext）：画面中央是一枚高对比的「播放演示」入口与一行极简提示（「点击播放 · 也可按空格」），点击后合成曲起、视觉从静止态被声音「唤醒」。
  - 桌面宽屏下可视化主体居中铺满留白；平板 / 手机视口下等比缩放、柱谱数量与线宽自适应密度，控制条换行或收进图标按钮，不横向溢出。
  - 右上角按工作台 HUD 规范放置点阵色 Title 胶囊（固定于案例视口内）。
- **主要视觉元素**：
  - **镜像柱谱（默认）**：底部一条水平基线上对称生长的频域柱阵（上下或左右镜像），低频在中、高频向两侧（或按频率由低到高单向排布），柱体高度严格映射 FFT 频带能量；可对高频做对数 / 指数映射补偿人耳感知，柱顶有圆头高光与余晖拖尾，低频柱带辉光。
  - **环形辐射频谱**：频谱柱沿圆周径向向外辐射，圆心可叠加一枚随低频（beat / bass）脉动的光球与呼吸光环；旋转方向与速度可随整体能量缓慢漂移。
  - **环形波形**：沿圆周（或中线）绘制 `getByteTimeDomainData` 的实时时域波形线，线条有柔和发光描边，安静时为接近正圆 / 直线的细环，发声后随波形起伏。
  - **节拍反应层**：检测低频段平均能量的瞬时跃升（beat / onset），触发一次克制的全局反应——背景明度与辉光短暂抬升、圆心光球脉冲、少量粒子从低频频柱 / 光球溅出并自然衰减；反应随节拍密度自然收放，不持续满屏轰炸。
- **层次、材质、光影与关键细节**：
  - 视觉分三层：深色背景与微弱网格 / 噪点底 → 频谱主体（柱 / 环 / 波形）→ 节拍辉光与粒子前景；靠 `globalCompositeOperation` 发光叠色、径向渐变与半透明余晖制造纵深，而非扁平色块。
  - 柱体 / 波形使用经过审美的有限色板（同色系明度递进或一小段和谐色相），颜色可同时编码频段与能量，但整体保持低饱和克制；切换色板是整体替换而非彩虹乱跳。
  - AnalyserNode 的 `smoothingTimeConstant` 与渲染层的 lerp 阻尼共同决定「黏弹感」：能量抬起跟手、落下有惯性余韵，不出现锯齿抖跳；静音时画面必须真正回到静止基线，证明视觉由真实信号驱动。
  - 暂停 / 无音源 / 麦克风未授权 / 文件解码失败均有明确但克制的状态视觉与文案，而非黑屏或控制台报错。

> 设计文档约束最终体验与设计意图；FFT 大小、柱数、频率映射曲线、粒子数量、节拍阈值与具体色值由实现阶段按画质与性能统一决定，不在此过早钉死。

## 动态与交互

- **触发方式（Pointer / 键盘统一）**：
  - 点击（pointerdown / click）中央入口或控制条播放键启动 / 暂停；所有控件为真实可聚焦元素，Tab 可遍历，Enter / Space 等价触发，模式切换支持左右方向键或按钮组。
  - 播放必须在用户手势内懒创建 / `resume()` AudioContext（自动播放策略）；暂停时停止调度并让视觉自然回落至静止，再次播放从合理位置继续或重启循环。
- **三种音源**：
  - **内置合成演示曲（默认，离线核心路径）**：用 OscillatorNode（bass / lead 和声与旋律）+ 噪声缓冲或合成鼓点（kick / snare / hat）通过精确的 AudioContext 时钟 lookahead 调度出一段有明显低频节拍与中高频变化的循环，无需任何音频资源；该路径保证断网双击 `index.html` 仍可看可听。
  - **麦克风（可选增强）**：`getUserMedia({ audio: true })` 取麦克风流接入 AnalyserNode，说话 / 放歌即驱动视觉；需处理授权拒绝与无设备情况（友好提示并可退回演示曲），且麦克风流只做分析、不做回放（避免啸叫）。
  - **本地文件（可选增强）**：`<input type="file" accept="audio/*">` 选择本地音频，`decodeAudioData` 后由 BufferSource 循环播放并分析；解码失败 / 非音频文件有明确提示；文件仅在内存中处理，不上传、不产生网络请求。
- **实时参数**：灵敏度（增益）、时间平滑（黏弹感）、可视化模式、色板；参数改动当帧生效，可在 Micro-HUD 中调节；提供简易电平 / 频段读数证明信号真实。
- **渲染与性能**：单 Canvas 2D + `requestAnimationFrame` 驱动，按容器尺寸 + DPR（上限约 2）适配高清屏；柱数随宽度自适应，粒子数量设上限；切到后台标签 / 卸载案例时停止 rAF、关闭振荡器调度与麦克风流、断开音频节点，避免后台耗电与悬挂回调。
- **可访问性**：
  - 控件语义化（`button` / `aria-pressed` / 单选组 `role="radiogroup"` 等）并具可访问名；播放状态、当前模式、音源切换结果通过 `aria-live="polite"` 礼貌播报；颜色不仅靠色相区分（柱高 / 位置 / 明度同时编码）。
  - 尊重 `prefers-reduced-motion`：减弱动效下关闭粒子溅射、辉光脉冲与强烈余晖，改为低幅度、慢速或静态化的频谱呈现（保留真实频段映射这一核心），播放、音源切换、键盘操作等功能完整保留。
  - 纯视觉的频谱信息不强求读屏逐帧播报（会造成噪音），但播放 / 曲目 / 模式等状态变化必须可被读屏获知。
- **移动端触控**：控制条触控热区不小于典型 44px，单指完成播放 / 切模式 / 切音源；Canvas 用 Pointer Events / viewport 单位 + ResizeObserver 自适应，旋转屏幕后正确重取尺寸与 DPR。
- **可选 Micro-HUD**（默认折叠，`H` / `Esc` 切换、事件防穿透）：调节 FFT 大小、灵敏度、平滑系数、色板、粒子与节拍反应开关、减弱动效对照，并显示频带电平 / 节拍触发指示用于验证「视觉由真实信号驱动」；非必需时至少保留右上角 Title 胶囊。

## 核心亮点

1. **补齐 Web Audio 信号分析方向空白**：库内 60 个案例与在池 29 个 Ready Idea 中没有任何「读取真实音频信号做实时频谱 / 波形可视化」的案例——`interactive-piano` 是弹奏输入的乐器合成（无 AnalyserNode 可视化），fireworks / confetti / dock / tabs / 卡券等只用一次性音效，生成式 Canvas 动画则与音频完全无关；本案例首次打通 `AnalyserNode → Canvas` 的音频反应链路。
2. **离线零资源也能完整演出**：默认音源是 Web Audio 实时合成的演示循环（振荡器 + 时钟调度鼓点），不依赖任何 mp3 / wav 资源或网络，双击 `index.html` 即可听到有低频节拍与中高频层次的循环并看到真实反应，完美满足案例独立性铁律；麦克风与本地文件作为能力扩展而非前置条件。
3. **真实信号驱动而非预设摆动**：频域柱阵 / 环形辐射 / 时域波形三种模式分别映射 FFT 频带能量与波形数据，叠加低频 onset 节拍检测驱动辉光与粒子；静音归静、鼓点下沉、镲片亮起，灵敏度与平滑可实时调，视觉与声音严格对应、可验证。
4. **完整音源状态机与真实边界**：演示合成 / 麦克风 / 本地文件三音源，覆盖自动播放手势解锁、暂停回落、麦克风拒绝授权 / 无设备、文件解码失败、后台标签与卸载时的流 / 节点 / rAF 清理等真实分支，而非只做 happy path 的玩具。
5. **克制审美 + 键盘一等路径**：低饱和有限色板、三层发光纵深与黏弹阻尼，拒绝彩虹渐变与满屏粒子的廉价感；Tab / Enter / Space / 方向键可完成全部操作，aria-live 播报状态变化，prefers-reduced-motion 下保留真实频谱核心、关闭强动效，移动端单指可用且自适应密度。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 HTML5 + CSS3 + ES6+，零框架、零第三方库、零 CDN，双击 `index.html` 完整离线可用（沿用案例三件套 `index.html` / `style.css` / `script.js`）。
- 默认音源必须零音频资源：用 Web Audio 振荡器 / 噪声缓冲 + AudioContext 时钟 lookahead 调度合成有清晰低频节拍与中高频变化的演示循环；禁止为默认体验引入外部 mp3 / wav 或网络流。麦克风（`getUserMedia`）与本地文件（`decodeAudioData`）为可选增强路径，失败须有友好降级，不得影响默认合成路径。
- 视觉必须由真实分析数据驱动：通过 AnalyserNode 的 `getByteFrequencyData` / `getByteTimeDomainData` 每帧取值映射几何形态；静音 / 暂停时视觉回到静止基线；不得用与声音无关的预设随机动画假冒频谱。
- AudioContext 必须在用户手势内懒创建 / `resume()`（自动播放策略）；麦克风流只分析不回放（防啸叫）；本地文件仅内存处理、不上传。
- Canvas 2D 按容器尺寸 + DPR（建议上限 2）适配，rAF 循环与柱体 / 粒子密度自适应视口；卸载、切换案例或页面隐藏时停止 rAF、停止合成调度、释放麦克风流并断开音频节点，无悬挂监听 / 定时器 / 回调。
- Pointer 与键盘均可完成完整操作（控件语义化、Tab 可达、Enter / Space / 方向键），播放状态 / 模式 / 音源变化以 `aria-live` 播报；信息编码不仅靠颜色。
- 尊重 `prefers-reduced-motion`（关闭粒子溅射 / 辉光脉冲 / 强余晖，保留真实频段映射的低幅度或慢速呈现，播放与音源功能完整）；移动端单指可用、热区充分、不横向溢出。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（强制）；如需参数控制（FFT 大小 / 灵敏度 / 平滑 / 色板 / 粒子与节拍开关 / 减弱动效对照 / 电平读数）使用默认折叠的 Micro-HUD（`H` / `Esc`、事件防穿透）。
