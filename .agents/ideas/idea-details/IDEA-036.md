## 创意概述

VS Code、Gmail、Notion、Figma、Linear、GitHub……几乎所有生产力工具的「设置 → 键盘快捷键」页里都有同一个小组件：点击「录制」，它进入聆听态，用户按下一串真实的组合键（`Ctrl` `Shift` `K`，甚至 `Ctrl+K` 之后再按 `Ctrl+L` 的双键序列 chord），组件实时把修饰键与主键组合、回显成一颗颗拟真键帽（keycap），校验这条快捷键是否合法（是否含主键、是否保留了浏览器/系统快捷键、是否与别的命令冲突），确认后保存并在命令行上即时生效；按 `Esc` 取消、按 `Backspace` 清空重来。这个「**快捷键录制器（Keyboard Shortcut Recorder / Hotkey Capture Input）**」是把「键盘」这一最原始输入设备重新暴露给用户自定义的关键控件，却极少有人把它做对：大多数实现要么直接吞掉输入框文本、要么无法处理 chord、要么冲突了也不提示。

本案例做一个纯原生、零依赖、零 CDN、双击离线即用的快捷键录制器：以一张拟真的「键盘快捷键设置」面板为舞台，左侧是可搜索的命令列表（保存、搜索、撤销/重做、切换主题、命令面板、加粗等真实命令，每条带默认快捷键、当前自定义快捷键与「录制 / 清除 / 恢复默认」操作），右侧/行内是录制区。点击录制（或键盘聚焦后 Enter/Space）即进入**捕获态**：组件通过 `keydown`/`keyup` 精确累积按下的修饰键（Ctrl/Cmd、Alt/Option、Shift、Meta）与主键，实时把 `Ctrl + Shift + K` 渲染成一排有按压光影、平台符号化（⌃ ⌥ ⇧ ⌘）的键帽序列；支持**双键序列 chord**（录到第一段后进入短暂的「等待第二组键」状态）；实时做**三类校验**——①「仅修饰键不算完成」②「与浏览器保留快捷键冲突」（如 `Ctrl+W`、`Ctrl+T`、`Ctrl+N` 等给出克制警告但不强行阻止演示）③「与其他命令重复绑定冲突」（明确指出与哪条命令冲突、高亮冲突双方）；保存后把绑定写入内存中的命令表（唯一事实源），并真正注册一组演示级快捷键监听，让用户当场按出刚录制的快捷键就能触发对应命令反馈（Toast / aria-live 播报 + 命令行状态变化），让「录制 → 生效」闭环可感知。全程焦点管理、Esc/Backspace 语义、reduced-motion 降级、移动端「外接键盘/触控替代」适配齐全。

当前案例库 60 个已注册案例中，键盘类交互已有 `command-palette`（Cmd+K 唤出、模糊检索并执行命令，行内**只读展示**快捷键提示 `<kbd>`）、`capsule-tabs`/`tree-view`/`context-menu` 等大量**消费**方向键/快捷键的组件，但**没有任何一个案例以「捕获、解析、校验、回显并保存用户自定义组合键」为核心**；全仓与在池 35 个 Ready 中检索 `hotkey / shortcut / keycap / chord / 录制 / 组合键 / keybind`，仅命中 command-palette 的「快捷键提示」与各案例 HUD 的 `H`/`Esc` 字样，无录制/冲突检测/自定义绑定主题。这是生产力设置场景中一处干净、高频、可直接落地的空白。

## 预期展示效果

- **构图与整体风格**：
  - 案例视口是一张克制的**深色「键盘快捷键」设置面板**（拟真但不照抄任何具体产品）：顶部是面板标题 + 一句副标题 + 一个命令搜索框；主体为命令列表，每行一条命令，自左至右为：命令图标与名称（必要时带分组小标题）、默认快捷键（次要色小号键帽）、**当前生效快捷键（视觉主角，大号拟真键帽组）**、行尾操作区（「录制」主按钮、「清除」「恢复默认」次要按钮）。
  - 录制中的行会高亮（细描边点亮 + 很轻的底色），其当前快捷键位置切换为**录制态键帽槽**：依次排列「修饰键键帽 + 主键键帽」，尚未按下时槽内显示安静的占位提示「按下快捷键…（Esc 取消）」，按下后键帽实时填入；chord 场景在两组键之间显示一个分隔符（如间隔点 / 箭头 / 「然后」字样）。
  - 冲突 / 警告以行内小横幅或键帽槽下方一行**带图标的说明文字**呈现（不仅靠颜色）：浏览器保留键冲突为克制的琥珀色提示，命令间重复绑定为另一语义色并同时高亮被冲突命令行；校验通过时键帽槽有一次极轻的「就位」确认光影。
  - 延续项目暗色、哑光、低饱和的 Anti-Slop 审美：键帽是唯一有「物理感」的元素（轻微凸起、顶面高光、底缘投影、按压时下沉），其余界面保持安静；拒绝霓虹描边、满屏发光与蓝紫渐变堆砌；图标全部手写内联 SVG，无任何图片/字体/网络请求。
  - 桌面宽屏列表舒展、信息一列排开；平板/手机视口下每行命令转为上下两层（命令名在上、键帽与操作在下），触控热区充分，不横向溢出。
- **主要视觉元素**：
  - **拟真键帽组（Keycap）**：把捕获到的逻辑按键渲染为一颗颗独立键帽，修饰键与主键形态统一、主键可略强；键帽呈细微的立体倒角（顶面受光、底缘一道暗边与短投影），录制态对应按键**物理按下时同步下沉并点亮**（与真实 `keydown/keyup` 严格对齐），松开后保留在结果序列中；平台符号化呈现修饰键（如 ⌃ Control、⌥ Option、⇧ Shift、⌘ Command，按平台或提供切换），主键显示规范大写标签（`K`、`Enter`、`Esc`、`PageDown` 等）。
  - **录制态捕获槽与 chord 二段等待**：录制中槽位随实际按下逐颗生长（transform/opacity 过渡，无布局跳动）；录满一组合法快捷键后进入短暂的「再按一组以形成序列，或直接保存」等待态（一个克制的倒计时进度环/细线或文字提示，超时或按确认即固化为单组），第二组键录入后形成 `Ctrl+K` `Ctrl+L` 的 chord 键帽序列。
  - **三类校验反馈**：①只按修饰键时主键槽保持空，文案提示「继续按下非修饰键完成」（或 chord 等待态除外）；②浏览器/系统保留键给出具体警告文案（「⌃W 通常用于关闭标签页」）与「仍然使用 / 换一个」引导；③命令冲突时明确写出「与『切换主题』命令的当前快捷键相同」，并把两条命令同时做克制高亮、提供「仍要绑定（覆盖到本命令）/ 取消」选择。
  - **生效反馈闭环**：保存后键帽固化为当前快捷键，列表该行的默认/当前关系清晰；用户当场按下刚保存的组合键时，触发一次统一、克制的命令反馈（顶部/底部 Toast 或命令行「✓ 已执行：保存」），证明绑定真的被注册并生效，而不只是摆拍。
- **层次、材质、光影与关键细节**：
  - 视觉三层：深色设置面板背景（极弱环境光/细网格）→ 命令行卡片（哑光面 + 极细描边 + 柔和圆角）→ 键帽与录制槽（最高对比、物理微立体、按压光影）。
  - 键帽按压必须「讲物理」：下沉位移小而确定、光影随按压缩放，多个修饰键 + 主键同时按下时各自独立响应、不串行不错乱；`keydown` 重复触发（长按自动重复）不能把同一个键重复计入，需按物理 `code` 去重直到 `keyup`。
  - 录制态严格拦截默认行为：对正在捕获的按键 `preventDefault()`/`stopPropagation()`，避免用户按 `Ctrl+S` 真的触发浏览器保存页、按 `/` 输入进搜索框；但录制结束/取消后立即解除拦截，不影响页面与命令演示监听；`Esc` 在录制态语义为「取消录制」而非被当作快捷键录入。
  - 状态真实双向：清除、恢复默认、覆盖冲突后，键帽槽、命令表、已注册监听三者始终一致；冲突是基于内存命令表实时计算，而非写死提示。

> 设计文档约束最终体验与设计意图；修饰键符号化的具体映射表、chord 等待超时时长、键帽精确尺寸/倒角/色值、保留键清单的具体条目数、是否提供 Windows/macOS 符号切换、Toast 形态等由实现阶段按手感与平台惯例统一决定，不在此过早钉死；但「真实捕获物理按键 → 解析为规范化逻辑组合 → 三类校验 → 键帽回显 → 写入命令表并注册可生效监听」这条链路必须真实成立，不允许用预设按钮或写死文本冒充录制。

## 动态与交互

- **触发方式（指针 / 键盘统一）**：
  - **指针录制**：点击某命令行的「录制」按钮，该行进入捕获态，按钮转为「按下快捷键…（Esc 取消）」；再次按下真实组合键实时回显，单击「保存/✓」或在 chord 等待超时后确认，单击「取消/✕」或按 `Esc` 放弃。触控同理（Pointer Events 统一），无 hover 依赖。
  - **键盘录制**：「录制」按钮原生可聚焦，Enter/Space 进入捕获态；捕获期间所有按键被捕获槽接管；Enter/Space 在已录到合法快捷键时作确认（注意与主键录入区分，避免把确认键误录），`Esc` 取消，`Backspace/Delete` 清空当前录入（chord 下可逐段清除）；焦点始终在捕获槽/行内可控移动，不被键帽 DOM 夺走。
  - **清除 / 恢复默认**：行内按钮或键盘可清空当前自定义快捷键（显示「未绑定」空态），一键恢复该命令出厂默认；操作结果即时反映到键帽与命令表。
- **捕获与解析逻辑**：
  - 监听 `keydown`/`keyup`，用稳定的 `event.code` 标识物理键、`event.key`/标准化映射产出可读标签，规范化修饰键顺序（如 Ctrl→Alt→Shift→Meta→主键）以保证同一组合只有一种存储/比较形态；忽略长按产生的重复 `keydown`（`event.repeat`）。
  - 区分「修饰键」与「主键」：主键 = 字母数字、功能键 F1–F12、空格、回车、方向键、PageUp/Down、Home/End、Tab、反引号等可作为命令的键；单独修饰键不构成完成（chord 等待判定除外）；`Esc` 保留为取消语义。
  - chord（双键序列）：录到完整第一组后进入二段等待，录入第二组即形成序列；等待超时或主动确认固化为单组；存储与冲突比较按规范化的整段序列进行。
- **校验与冲突（实时）**：①合法性——必须含主键；②保留键——比对内置的浏览器/系统保留快捷键集合给出警告（演示场景可选择继续，但必须显式告知风险）；③命令冲突——与命令表中**其他**命令的当前绑定做规范化比较，冲突时给出对方命令名、高亮双方并要求用户选择覆盖或取消；冲突状态不仅靠颜色，必带图标 + 文字。
- **生效演示闭环**：保存即在内存命令表更新绑定并注册一组演示级全局快捷键监听（同样 `preventDefault` 已知组合、避免与录制态互相干扰）；按下已绑定快捷键时触发对应命令的可视化反馈与 `aria-live` 播报（如「已执行：保存」）；重新绑定/清除/恢复默认后旧监听立即失效、新监听生效，无重复触发；卸载案例时移除全部演示监听。
- **搜索与列表**：顶部搜索框按命令名/分组/按键标签即时过滤命令行（与库内已有搜索过滤交互语言一致），便于验证大量绑定时的冲突定位。
- **可访问性（一等路径）**：
  - 录制槽具备清晰可访问名与状态（如 `role` 合适用 `button`/`dialog` 语义 + `aria-label`「正在为保存命令录制快捷键，按下组合键，Esc 取消」）；捕获结果与校验信息通过 `aria-live="polite"` 在状态变化时节流播报（如「已录制 Control Shift K」「与切换主题冲突」「已保存」），避免逐键刷屏。
  - 键帽不仅靠颜色表达状态，主键/修饰键有文本标签；冲突/警告含图标 + 文字并可关联到对应命令行；命令列表支持键盘焦点遍历、Tab 顺序合理、焦点可见。
  - 尊重 `prefers-reduced-motion`：关闭键帽下沉/生长光影、chord 倒计时动画与冲突高亮闪烁，保留即时的文本/颜色/状态反馈与全部功能逻辑。
- **移动端与触控**：窄屏行内信息上下分层、不横向溢出；纯触屏设备本就没有实体键盘，录制态进入后给出明确的「请连接/使用键盘按键，或点按下方提供的演示组合」可操作兜底（允许提供少量预置组合快捷录入，保证无键盘用户也能体验保存/冲突流程，但预置只是辅助，真实按键录制仍是主路径）。
- **生命周期**：仅在录制态临时拦截按键，退出（保存/取消/失焦/卸载）即恢复；组件在 iframe 挂载/卸载、页面隐藏时统一移除录制监听与演示快捷键监听、定时器（chord 等待倒计时），无悬挂监听与内存泄漏。
- **可选 Micro-HUD**（默认折叠，`H`/`Esc` 切换、事件防穿透）：实时显示最近一次原始 `event.code`/`event.key`、当前按下的修饰键集合、规范化后的组合字符串、是否命中保留键清单、与哪条命令冲突、`event.repeat` 计数等，便于验证捕获与规范化逻辑的真实性；非必需时至少保留右上角 Title 胶囊。

## 核心亮点

1. **补齐生产力设置场景的干净空白**：库内 60 个案例与在池 35 个 Ready 中没有任何「捕获/校验/回显/保存用户自定义快捷键」主题；最接近的 `command-palette` 只是只读展示 `<kbd>` 提示并执行预置命令，既不录制也不检测冲突。快捷键设置是 VS Code/Figma/Notion/Linear/GitHub 等所有生产力应用的标配页面组件，可直接用于生产环境（实用性 5 分）。
2. **真实按键捕获链路而非摆拍文本**：基于 `keydown/keyup` + 物理 `code` 去重 + `event.repeat` 过滤 + 修饰键规范化排序，把「一次真实按键」精确解析为唯一可比的逻辑组合，并支持 chord 双键序列与二段等待；这是该组件最容易被做坏、也最能体现工程严谨性的部分。
3. **拟真键帽的物理微交互**：键帽随真实按下逐颗下沉受光、松手固化成型，修饰键平台符号化（⌃⌥⇧⌘）、chord 序列分隔、录制槽生长无布局跳动——把抽象的键位数据做成可触摸的物理对象，视觉表达与库内其他表单组件明显不同，命中技术域 2（微交互光影）× 域 5（按键交互）× 域 1（可访问性）的交叉。
4. **完整的校验—冲突—生效闭环**：三类实时校验（仅修饰键 / 浏览器保留键 / 命令间冲突并具名高亮对方）+ 保存后真正注册可触发的演示快捷键监听，让「录制 → 冲突处理 → 生效可按出」形成可感知闭环；命令表是唯一事实源，键帽与监听是其视图，覆盖/清除/恢复默认任何路径下三者一致。
5. **可访问性与边界鲁棒**：录制语义、aria-live 状态播报、Esc 取消/Backspace 清除/Enter 确认的按键仲裁、录制态对默认行为的精确拦截与退出恢复、reduced-motion 降级、触屏无键盘兜底、卸载清理全部监听/定时器——可作为「键盘为一等输入设备」的可访问组件范式；零图片零图标库零 CDN，双击离线完整可用。

  - `command-palette`（命令面板）：全库语义最近者，都围绕「命令 + 键盘」；但它是 **Cmd+K 唤出、模糊检索并执行预置命令**的启动器，行内的 `<kbd class="kbd-shortcut">` 只是**静态只读的快捷键提示**（显示 `/path` 与 `↵ 访问`），既不监听用户自定义组合键、不做按键解析/规范化，也没有冲突检测、chord、键帽回显或保存绑定。本案例核心是「**录制并管理用户自定义快捷键**」，二者是「命令的启动器」与「命令绑定的设置器」关系，核心创意与数据流完全不同。
  - 大量**消费键盘**的组件（`tree-view`、`context-menu`、`mega-menu`、`combo-box`、`kanban-board`、`range-slider`、`drawer`、`capsule-tabs` 等）：它们都内置方向键/Enter/Esc/快捷键导航，但键盘对它们是**操作手段（硬编码、内部消费）**，用户无法查看规范化组合、无法改键、无冲突概念，也不把按键本身作为数据对象回显；本案例把「按键组合」提升为**一类可捕获、可校验、可持久化的数据**，定位与交互结果不同。
  - `otp-input` / `payment-card-input`（录入类）：同为「键盘输入进表单」，但它们处理的是**文本字符的格式化录入**（验证码逐格、卡号分组），不解析修饰键状态、不识别组合键/chord、不做键位物理回显与命令冲突；输入对象（字符 vs 逻辑组合键）与呈现（输入格 vs 拟真键帽）不同。
  - 在池表单/命令类 Idea：IDEA-017 贝塞尔缓动工坊（可复制 `cubic-bezier` 文本）、IDEA-028 行内编辑、IDEA-032 节点流编辑器（消费 Delete/Esc/方向键）、IDEA-005 步骤向导等——经逐一核对均无「快捷键录制/绑定/冲突」主题；全仓与活动池检索 `hotkey / shortcut / keycap / chord / keybind / 快捷键 / 组合键 / 录制`，命中仅 command-palette 的只读快捷键提示与各案例 HUD 的 `H`/`Esc` 快捷键字样，无录制语义。确认无历史（含已删除）`hotkey-recorder` id 或物理目录冲突。
- **差异说明**：核心创意是「**一个把真实物理按键实时捕获、规范化解析（修饰键排序 + 主键 + chord 序列）、以拟真键帽回显、做保留键与命令间冲突校验、写入命令表并注册为真正可触发生效绑定的快捷键录制设置组件**」。与 command-palette 相比，差异在「自定义绑定的录制/冲突管理」vs「预置命令的检索执行（只读提示快捷键）」；与各类键盘导航组件相比，差异在「把组合键作为一类数据对象暴露给用户编辑」vs「内部硬编码消费按键」；与 OTP/银行卡录入相比，差异在「修饰键 + 主键 + chord 的逻辑键捕获与物理键帽表达」vs「文本字符格式化」。差异同时体现在核心创意、视觉表达（拟真键帽组 × 冲突双方高亮 × chord 二段等待）、交互方式（真实按键捕获、Esc/Backspace/Enter 仲裁、录制态默认行为拦截）与整体表现（生产力工具快捷键设置面板）上，不属于换颜色、文案或微调参数类重复。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 HTML5 + CSS3 + ES6+，零框架、零第三方库、零图标库/图标字体、零 CDN、零外部图片（图标手写内联 SVG），双击 `index.html` 完整离线可用（沿用案例三件套 `index.html` / `style.css` / `script.js`）。
- 按键捕获必须真实：基于 `keydown`/`keyup` 与稳定的物理 `event.code` 标识按键，过滤 `event.repeat` 长按重复，规范化修饰键顺序并产出唯一可比、可存储的组合表示；区分修饰键与主键，支持 chord 双键序列及二段等待；禁止用预置按钮/写死文本冒充真实录制（预置组合仅可作为无键盘触屏的辅助兜底路径）。
- 录制态必须精确 `preventDefault()`/`stopPropagation()` 被捕获按键（避免触发浏览器保存页、输入进搜索框等），并在保存/取消/失焦/卸载后**立即解除**；`Esc` 固定为取消语义不被录入，`Backspace/Delete` 为清除，Enter/Space 的确认与主键录入需明确仲裁、不可误录。
- 校验实时且基于内存命令表（唯一事实源）：仅修饰键不完成、内置浏览器/系统保留键集合给出具名警告、与其他命令当前绑定规范化比较冲突并具名高亮对方；覆盖/清除/恢复默认后键帽、命令表与已注册演示快捷键监听三者严格一致，旧绑定立即失效、无重复触发。
- 保存的快捷键要真正可演示生效：注册一组演示级快捷键监听，按下已绑定组合键触发克制的命令反馈（Toast + aria-live 播报 + 行状态），不与录制态互相干扰；页面隐藏或案例卸载时移除全部录制/演示监听与 chord 等待定时器，无泄漏。
- 可访问性为一等路径：录制槽具可访问名与录制/结果/冲突状态，aria-live 在状态变化（非逐键）时节流播报；状态不仅靠颜色（图标 + 文字 + 文本键帽标签）；全键盘可达、焦点可见可控；尊重 `prefers-reduced-motion`（关闭键帽按压/生长/倒计时动画，保留全部功能与即时反馈）。
- 视觉为暗色哑光克制的设置面板风格，键帽是唯一物理微立体元素（按压下沉受光、平台符号化 ⌃⌥⇧⌘），状态色小面积低饱和，拒绝霓虹满屏发光的 AI Slop；桌面/平板/手机自适应、窄屏上下分层不横向溢出，触控热区充分，无键盘设备给出可操作兜底。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（强制）；如需观察捕获细节（原始 code/key、修饰键集合、规范化串、保留键命中、冲突对象、repeat 计数）使用默认折叠的 Micro-HUD（`H`/`Esc`、事件防穿透）。
