## 创意概述

「内容还没来，先看到它将来长什么样」——骨架屏（Skeleton Screen）是 Facebook、YouTube、LinkedIn、Vercel、Semi Design、Ant Design 等几乎所有现代产品在首屏与异步区块上采用的感知性能原语：在真实数据返回前，用**与最终内容同构的灰色占位形状**（圆形头像、标题条、正文多行块、图表块、表格行列）预绘布局，把不可预期的空白等待转译成「即将就绪」的结构预告，显著降低感知延迟与布局跳动（CLS）。它解决的不是「做一个转圈」，而是一套完整的**异步区块加载状态机**：`idle → loading（骨架占位）→ loaded（真实内容揭示）/ error（失败态 + 重试）`，其中占位结构必须与真实内容尺寸严格匹配、微光动效必须克制不抢内容焦点、切换必须无跳变且对屏幕阅读器友好。

当前案例库 60 个案例中，与「加载等待」相关的只有两处：`infinite-feed` 在信息流分页内部使用了卡片骨架 shimmer（且其自身文案已总结「形状贴近真实布局、闪烁克制、首屏不超过一秒」），但它服务的是**无限滚动这一单一场景的从属加载阶段**——只有一种卡片骨架、由哨兵自动触发、无错误态骨架层、无占位与真实内容对齐验证、不可作为通用区块组件复用；`top-loading-bar` 是代码驱动的顶部 trickle 进度条，与首屏区块占位无关。全库**没有任何以「异步区块加载状态」本身为核心、覆盖多种真实页面布局、可对照验证「占位↔内容零位移」的骨架屏组件**，技术域 2（微交互与光影动效）的 Skeleton/Shimmer 方向在组件层面仍是空白。本案例做一个纯原生、零依赖、双击离线即用的 Skeleton Loading System：内置多种真实业务布局模板（内容卡片列表 / 长文详情 / 数据表格 / 个人资料看板等）、多种可切换的微光风格（渐变扫光 / 波浪 / 静态呼吸 / 无动效）、可调延迟与可注入失败的异步模拟器、占位与真实内容同构对齐的揭示切换（淡入 + 轻微 stagger，零布局跳动）、以及完整的 `aria-busy` / aria-live 可访问性与减弱动效降级，并遵循统一 HUD 规范。

## 预期展示效果

- **构图与整体风格**：
  - 案例视口主体是一块**拟真产品界面预览舞台**：顶部极简模板切换条（内容卡片列表 / 长文详情 / 数据表格 / 个人资料看板等布局标签），舞台中央渲染当前模板的完整界面骨架——不是抽象的灰色方块堆，而是一张结构完整、层级分明的真实页面「灰模」：圆形头像位、不同字级对应的标题条、长度递减的正文行块、图片/封面比例块、表格行列、侧边信息块等，圆角、间距、栅格与真实内容态**逐像素同构**。
  - 舞台下方（或侧边）是极简**异步模拟控制条**：重新加载按钮、延迟调节（快 / 中 / 慢，直观的时长刻度而非裸数字）、「模拟失败」开关、微光风格切换（扫光 / 波浪 / 呼吸 / 无）、以及当前状态指示（加载中 / 已完成 / 失败）；右上角按工作台 HUD 规范放置点阵色 Title 胶囊。
  - 延续项目克制的暗色玻璃审美：占位块使用安静的中性灰阶与极细描边，扫光为同色系低对比高光掠过，拒绝高饱和蓝紫渐变与满屏流动高光的 AI Slop 廉价感；真实内容态同样由纯 CSS/内联 SVG 构造（头像、缩略图、图表柱、图标均为几何图形/渐变块），零外部图片。
  - 首屏即处于一次**加载→揭示的完整演示循环起点**（可自动演示一次后交还控制权），用户立刻理解「占位与内容同一张皮」的心智模型；桌面宽屏下舞台与控制条并排舒展，平板 / 手机视口下控制条折行为图标按钮组、舞台纵向铺满，不横向溢出。
- **主要视觉元素**：
  - **同构占位形状系统**：基础占位原语至少包括圆形（头像/徽标）、标题条、多行文本（末行按比例收短，模拟真实段落 rag）、矩形媒体块（带合理宽高比）、表格行/列块、统计数字块；所有占位元素与真实内容态共享同一套布局栅格、内外边距与尺寸，保证切换时零位移。
  - **微光层（Shimmer）**：同一套占位形状支持多种克制的微光风格——线性渐变高光沿轴向扫过（扫光）、明暗错峰传播（波浪）、整体不透明度慢速呼吸、以及完全无动效的静态占位；高光为低透明度同色系，扫掠节奏舒缓、循环之间无跳变接缝。
  - **揭示切换**：数据到达后骨架层与真实内容层交叉淡入淡出（cross-fade），真实内容可带极轻微的自下而上 stagger 入场；两层在同一网格坐标上叠化，肉眼可见「每一块占位都准确长成了对应内容」，无跳动、无尺寸突变、无滚动位置漂移。
  - **失败态**：超时/失败时骨架优雅退场，区块原位呈现明确的失败说明与「重试」按钮（图标 + 文案），重试重新进入骨架态；失败不是弹窗打断，而是区块内联的状态组成部分。
- **层次、材质、光影与关键细节**：
  - 视觉三层：舞台界面背景 → 骨架/内容叠化层 → 控制与状态反馈层；靠一致的栅格、细边与柔和投影制造与真实产品一致的信息层级，占位块表面为哑光中性材质，仅扫光经过时有短暂细腻高光。
  - 微光只服务「正在加载」的生命感反馈：静态画面安静、动效循环无缝；不同微光风格的差异在切换时即时可辨，且在长延迟场景下不引起眩晕或阅读干扰。
  - 真实边界有明确反馈：加载中重复触发被收敛（去重/忽略）、失败可稳定复现与重试、极快返回时骨架不闪烁（设置最短展示或即时透传的合理策略并在状态指示中一致）、切换模板时正确中断上一次未完成的异步模拟，旧内容/骨架不残留。
  - 「零布局跳动」是本案例的核心可验证细节：可提供一种对齐对照视角（如揭示瞬间的轮廓叠影或慢速切换），让占位块与真实内容的尺寸对应被肉眼验证，而非口头声称。

> 设计文档约束最终体验与设计意图；具体模板数量、延迟档位毫秒值、扫光渐变角度与时长、stagger 幅度与叠化时长等由实现阶段按画质与手感统一决定，不在此过早钉死。

## 动态与交互

- **触发方式（点击 / 键盘统一）**：
  - **重新加载**：点击「重新加载」（或按钮聚焦时 Enter / Space）触发当前模板进入 loading 态；经模拟延迟后揭示内容；「模拟失败」开启时则进入失败态，点击区块内「重试」重新加载。
  - **模板切换**：切换条在多种布局模板间切换，切换即重新走一次加载流程；切换瞬间正确取消未完成的上一次模拟（无旧回调晚到覆盖、无悬挂定时器）。
  - **异步模拟控制**：延迟档位调节加载时长以体验快/慢网络质感；失败开关注入稳定可复现的错误分支；状态指示与当前真实状态机严格同步。
  - **微光风格切换**：扫光 / 波浪 / 呼吸 / 无四档即时切换，加载中与静态均可对照观感差异；选择 `prefers-reduced-motion` 或「无」时无循环动效但加载功能完整。
- **状态机语义**：每个演示区块是显式的 `idle / loading / loaded / error` 状态机；loading 展示同构骨架并设 `aria-busy="true"`，loaded 揭示内容并清除 busy，error 呈现内联失败与重试；并发触发被收敛，模板切换/卸载时中止在途模拟，保证不出现错态内容闪现。
- **键盘一等路径**：模板切换条、控制按钮与重试按钮均为原生可聚焦元素，Tab 顺序合理、焦点环清晰可见；全部操作可用键盘完成；Esc 不产生破坏性中断（加载中允许忽略或安全中止回 idle，行为一致即可）。
- **可访问性**：
  - 加载中的舞台容器标注 `aria-busy`，加载完成/失败通过 `aria-live="polite"` 礼貌播报一次结果（节流，不逐帧刷屏）；骨架装饰元素对辅助技术隐藏或标注为呈现性，避免屏幕阅读器朗读一堆无意义「占位、占位」。
  - 信息不依赖微光动效本身传达：加载/完成/失败状态同时由状态指示文案与图标表达；对比度满足暗色主题可读性。
- **减弱动效与移动端**：
  - 尊重 `prefers-reduced-motion`：关闭扫光/波浪/呼吸循环与位移动效，改为静态占位 + 直接（或慢速淡入）揭示，加载状态机、失败重试与播报功能 100% 保留。
  - 移动端触控热区充分，模板与风格切换条可横向滚动或折行不溢出；叠化切换不引起页面滚动跳动；任何视口下舞台不横向溢出。
- **生命周期**：所有异步模拟用可控的定时器/承诺实现，模板切换、重复触发与案例卸载时必须中止/清理在途回调；连续动画用 CSS 动画或 rAF 驱动并在卸载时停止，无悬挂定时器、监听与 rAF。
- **可选 Micro-HUD**（默认折叠，`H` / `Esc` 切换、事件防穿透）：显示当前状态机状态、模拟延迟实际值、最短展示策略是否生效、占位块/内容块数量对照、减弱动效开关与「慢速揭示」对齐对照开关，便于验证零位移与状态正确性；非必需时至少保留右上角 Title 胶囊。

## 核心亮点

1. **补齐「异步区块加载状态」组件空白**：库内 60 个案例无任何以骨架屏加载为核心的组件；最接近的 `infinite-feed` 把单一卡片骨架当作无限滚动的从属阶段（哨兵自动触发、无模板体系、无错误骨架层、无对齐验证、不可复用为区块组件），`top-loading-bar` 是顶部代码驱动进度条。本案例首次把「loading/loaded/error + 同构占位」作为独立、可复用、可验证的产品级组件完整呈现，命中技术域 2（Skeleton/Shimmer 微交互）。
2. **「零布局跳动」可被肉眼验证**：占位与真实内容共享同一套栅格与尺寸，叠化切换零 CLS；配合慢速揭示/轮廓对照，让「每一块占位准确长成内容」成为看得见的核心卖点，而非灰色方块摆拍。
3. **不止于 shimmer 的完整状态机**：多布局模板（卡片列表 / 长文 / 表格 / 看板）× 多微光风格（扫光 / 波浪 / 呼吸 / 无）× 完整异步分支（延迟模拟、稳定失败注入、内联重试、并发收敛、切换中止），是可以直接搬进生产页面的区块加载方案，而非纯自动播放的视觉演示。
4. **克制审美 + 完整可达性**：中性哑光灰阶、低对比同色系扫光、无缝循环，规避满屏流动高光的廉价感；`aria-busy` / aria-live 结果播报、装饰骨架对 AT 隐藏、状态不只靠动效传达，prefers-reduced-motion 保留完整加载流程。
5. **零资源拟真**：全部头像、缩略图、图表、图标由 CSS 与内联 SVG 几何构造，模拟延迟纯前端产生（含失败分支），断网双击亦可完整演示加载、揭示与重试全链路。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 HTML5 + CSS3 + ES6+，零框架、零第三方库、零 CDN，双击 `index.html` 完整离线可用（沿用案例三件套 `index.html` / `style.css` / `script.js`）。
- 占位层与真实内容层必须共享同一套布局栅格与尺寸（同构），切换为叠化交叉淡入而非重排，保证零布局跳动（无滚动位置漂移、无尺寸突变）；真实内容的头像 / 缩略图 / 图表 / 图标全部以 CSS 与内联 SVG 几何构造，无外部图片 / 字体 / 网络请求。
- 每个演示区块实现显式 `idle / loading / loaded / error` 状态机：loading 设 `aria-busy`，完成/失败经 aria-live 播报一次；异步为纯前端可控模拟（可调延迟、可注入稳定失败、内联重试）；加载中重复触发收敛，模板切换/卸载必须中止在途模拟并清理定时器/回调/rAF，杜绝旧回调晚到覆盖与悬挂任务。
- 微光至少提供多种可即时切换的风格（渐变扫光 / 波浪错峰 / 静态呼吸 / 无动效），循环无缝、低对比克制；`prefers-reduced-motion` 下关闭循环与位移动效，加载、揭示、失败重试与播报功能完整保留。
- 提供占位↔内容对齐的可验证手段（慢速揭示或轮廓对照之一）；状态指示同时以文案/图标表达，不仅依赖动效或颜色。
- 全部控制为原生可聚焦元素，键盘可完成加载、重试、模板与风格切换，焦点环可见；移动端热区充分、切换条不横向溢出、叠化不引起页面跳动。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（强制）；如需参数控制（延迟实际值、状态机状态、微光风格、慢速揭示对照、减弱动效开关等）使用默认折叠的 Micro-HUD（`H` / `Esc`、事件防穿透）。
