## 创意概述

打开大量科技公司的落地页、作品集首屏或终端风格界面，标题往往不是「直接出现」，而是先显示一串 `#@&X?=0▓` 之类的乱码，再像老式终端或电影里黑客破解密码那样，**从左到右逐字符「锁定」成真正的文字**：每个位置先经历若干帧高速随机跳变，随后在一瞬间稳定为目标字符并轻微提亮，整条文本形成一道从左向右推进的「解析波」。这个被业界称为 Text Scramble / Decode / Glitch-Resolve 的效果（经典实现如 Guillermo Rauch 的 text-scramble 片段、无数 Awwwards 站点首屏），是把「加载、解密、系统启动」叙事感做得最克制、最高级的文字动效之一——它**不是故障**，而是「信息从噪声中浮现」。

本案例做一个纯原生、零依赖、零 CDN、双击离线即用的文本乱码解码器：以一张暗色终端美学的「解码实验室」为舞台，中央是若干条可切换的演示文案（大标题、副标题、数据/标签行），每条文本可在**多种触发方式**下播放解码动画——①进入视口自动解码一次（IntersectionObserver）；②鼠标悬停/手指点按重播；③点击「重新解码」按钮；④键盘聚焦后按 Enter/Space 触发；并提供一个真实可输入的**自定义文案框**，用户键入任意中英文/数字/符号（含空格与 emoji 安全处理），点解码即可看到自己的文字经历同样的乱码→锁定过程。动效引擎必须是**按字符独立调度**的真实状态机：每个字符拥有独立的「开始时刻 / 锁定时刻」，在未锁定前每帧从一个可配置的安全字符集（如全角片假名 `アァカサタナ…` 或 ASCII 符号数字集，可选）中随机取样，锁定后不再变化；解析推进方向、错峰延迟（stagger）、单字符跳变帧率、解析波时长均可调；中文等宽不保证时以**字符等宽布局**（每个字符包裹独立 span 并保留空格宽度）保证乱码替换不引发布局跳动（无 CLS）；尊重 `prefers-reduced-motion`（直接显示最终文本或仅极轻微淡入），含「解析中→完成」的 aria-live 状态播报。Micro-HUD 默认折叠，可实时切换字符集、方向、速度、stagger 与循环模式并查看当前已锁定字符数等真实引擎状态。

当前案例库 60 个已注册案例中，文字类特效仅 `particle-text`（离屏 Canvas 光栅化取像素点、粒子爆炸与弹性聚合）、`glitch-text`（赛博朋克 RGB 通道错位/抖动的**持续视觉滤镜**，文字内容恒定可读、不存在「逐字符锁定为另一串目标文本」的状态机）、`typewriter`（逐字**新增/删除**真实字符的打字机，字符只会被追加或回退、从无随机替码阶段）；在池 36 个 Ready 中检索 `scramble / 解码 / 乱码 / 逐字 / 字形 / splittext`，无任何同主题条目。这是文字动效域里一个干净、高频、可直接落地且与三者核心机制完全不同的空白。

## 预期展示效果

- **构图与整体风格**：
  - 案例视口是一张克制的**深色「解码实验室 / 终端」舞台**（拟真但不照抄任何具体产品）：大面积近黑留白，中央偏上是一条大字号主标题（视觉主角），其下一条较小的副标题与一两行「系统状态 / 数据标签」式等宽文本；底部或侧下方是安静的控制区（自定义文案输入框、演示文案切换、重新解码按钮、触发方式说明）。
  - 文本在**静止（已解码）态**是正常、清晰、可读的高品质排版；只有在播放解码的一小段时间内，未锁定字符位置才呈现低对比、等宽的乱码字形；乱码字符使用比正文更低的明度/更小的视觉重量，**已锁定字符明亮、未锁定字符暗淡**，形成自左向右推进的明度阶梯——这是该效果「信息浮现」叙事的核心视觉，而非整行一起闪烁。
  - 字符锁定瞬间有一次极克制的「就位」反馈（极短的明度提升/微小字重变化/一道可选的扫描微光扫过），幅度小而确定，拒绝大幅缩放、弹跳与满屏发光。
  - 延续项目暗色、哑光、低饱和的 Anti-Slop 审美：仅允许一处小面积语义强调色（如解析波前沿的微光），拒绝霓虹描边、红蓝满屏色散与蓝紫渐变堆砌；不使用任何外部字体/图片/网络请求，依赖系统无衬线 + 系统等宽字体栈即可成立。
  - 桌面宽屏标题舒展、可放至较大字号；平板/手机视口下标题自适应换行、控制区上下堆叠，触控热区充分，不横向溢出。
- **主要视觉元素**：
  - **逐字符解析波**：播放开始后，每个字符位置按「起始延迟 = 索引 × stagger（或反向/居中扩散等方向模式）」进入乱码态，在若干帧随机跳变后于各自的锁定时刻稳定为目标字符；视觉上表现为一道明度与字形从噪声到秩序的推进波，波前可有极细的扫描微光，波后是完全稳定的正文。
  - **多形态演示文案**：预置 3～4 组真实语境文案（如产品主标题 + 副标题、终端启动日志行、数据标签行），切换时重新播放解码；另有自定义输入框，用户输入任意字符即时作为新的解码目标（含空格保留、多语言字符与 emoji 的安全处理：emoji/代理对字符在未锁定阶段可直接显示或用统一占位符，不得拆成代理对半字符乱码）。
  - **解码状态与重播控件**：一个主「重新解码 / Decode」按钮、文案切换控件、触发方式说明（进入视口 / 悬停 / 点击 / 键盘）；播放中可有一条极细的整体进度细线或字符锁定计数（x / n），完成态有一次安静的确认。
- **层次、材质、光影与关键细节**：
  - 视觉三层：深色舞台背景（可带极弱网格/扫描线纹理，但不得喧宾夺主）→ 控制区哑光卡片（极细描边、柔和圆角）→ 标题文本本身（最高对比，乱码态暗、锁定态亮）。
  - **不乱跳是底线**：每个字符由独立 inline 元素承载并保持与目标字符一致的占位宽度（空格用 `&nbsp;`/等宽占位处理），乱码字符替换与锁定全程不引起行宽变化、不换行抖动、无 CLS；长文本在窄屏的换行点在解码前后保持一致。
  - 乱码字符集必须「安全」：默认使用不含歧义/侵权风险、终端观感强的字符集（如片假名字符集或 ASCII `!<>-_\\/[]{}—=+*^?#` 类符号数字集），由 Micro-HUD 可切换；不得引入外部字形资源。
  - 动画节奏参数化：stagger（相邻字符启动间隔）、单字符乱码帧停留时长（跳变速度）、整体解析时长三者解耦，保证既能做快速干脆的标题（约 0.6–1.2s）也能做舒缓长文本；同一引擎支持正向、反向、居中向外等推进方向。

> 设计文档约束最终体验与设计意图；具体字符集条目、帧更新节奏（基于 rAF 的时间累积而非固定 setInterval）、stagger/时长的默认数值、扫描微光的具体形态、是否提供终端光标等由实现阶段按手感统一决定，不在此过早钉死；但「按字符独立调度的真实状态机 → 未锁定帧随机取样 → 到达各自锁定时刻稳定为目标字符 → 全程无布局跳动 → 多触发方式与自定义文案真实可用」这条链路必须真实成立，不允许用预录 GIF 式写死序列、整行 `opacity` 切换或直接显示最终文本冒充解码。

## 动态与交互

- **触发方式（多输入统一，非纯自动播放）**：
  - **进入视口**：文本区块进入视口时自动解码一次（IntersectionObserver，触发后可选择解除观察或保留以便滚回重播，行为需明确）；
  - **悬停 / 点按**：指针悬停文本（桌面）或点按（触屏）重新播放一次解码；播放中再次触发的节流/重入语义需明确（忽略或从头重启，避免动画叠加错乱）；
  - **按钮 / 键盘**：点击「重新解码」按钮重播；按钮与自定义输入框原生可聚焦，Enter/Space 触发解码，Tab 顺序合理、焦点可见。
  - **自定义文案**：在输入框键入任意文本后触发解码，舞台标题的目标文本真实替换并重播；空输入给出克制提示而非报错。
- **解码引擎（核心逻辑）**：
  - 把目标字符串按字符安全拆分（正确处理代理对 / emoji / 组合字符簇，至少不拆坏 emoji），为每个字符建立独立调度参数：开始时刻、锁定时刻（由方向模式 + stagger + 整体时长推导）；
  - 用单个 `requestAnimationFrame` 循环按时间累积驱动：未到开始时刻的字符可显示占位/空白；处于跳变区间的字符每帧（或按累积帧间隔）从字符集随机取样；到达锁定时刻写入目标字符并标记锁定、触发一次就位反馈；全部锁定后结束循环并释放 rAF（不得空转）；
  - 支持中途重播、切换文案、切换参数后的干净重启（取消上一轮调度、无双重 rAF、无状态串台）。
- **控制与可配置项（Micro-HUD 默认折叠，`H`/`Esc` 切换、事件防穿透）**：字符集切换（片假名 / ASCII 符号数字 / 数字）、推进方向（左→右 / 右→左 / 居中扩散）、跳变速度、stagger、整体时长、是否循环、扫描微光开关；面板实时显示真实引擎状态（总字符数、已锁定数、当前阶段、rAF 是否在跑）。
- **可访问性（一等路径）**：
  - 乱码跳动文本不得让屏幕阅读器逐帧朗读：动画层与可访问文本分离（如对动画容器 `aria-hidden`，另设仅对辅助技术可见的完整最终文本，或在容器上使用 `aria-label` 表达最终内容）；解码开始/完成通过 `aria-live="polite"` **仅在阶段边界**播报一次（如「正在解码」「解码完成」），不逐字符刷屏；
  - 自定义输入具备可见 label、焦点样式与足够对比度；完成态文本对比度达 WCAG AA；状态不仅靠颜色（乱码/锁定以明度 + 字形稳定性共同区分）；
  - 尊重 `prefers-reduced-motion`：默认直接呈现最终文本（可保留一次极短、非字符跳变的淡入），所有触发方式、自定义输入与参数切换的功能逻辑完整保留。
- **移动端与触控**：窄屏标题自适应、控制区上下堆叠不横向溢出；悬停触发在触屏以点按兜底；点按热区充分；视口变化（resize / 横竖屏切换）后重新计算布局，已完成文本不因此重新乱码抖动。
- **生命周期**：IntersectionObserver、rAF、事件指针/键盘监听在案例卸载（iframe 销毁）、页面隐藏时统一清理，无悬挂 rAF、无观察者与监听泄漏；切换案例后不继续在后台跑帧。

## 核心亮点

1. **补齐文字动效域的高频空白**：库内 60 案例与在池 36 个 Ready 中，文字动效仅有粒子聚合（particle-text）、持续故障滤镜（glitch-text）、打字机（typewriter）三种，无一具备「随机替码 → 逐字符锁定为目标文本」的解码状态机；Text Scramble 是作品集/科技落地页/终端主题界面的标配首屏动效，可直接用于生产环境（实用性 5 分）。
2. **真实的按字符调度引擎而非摆拍**：每字符独立开始/锁定时刻、单 rAF 时间累积驱动、字符集随机取样、多方向推进波、参数（stagger/帧率/时长）解耦——这是该效果最容易被做成「整行闪烁」或「写死序列」的地方，也是工程严谨性的展示点。
3. **「噪声 → 秩序」的克制叙事美学**：以乱码态低明度、锁定态高明度的明度阶梯和一道极细解析波表达「信息浮现」，锁定瞬间轻微就位反馈；区别于 glitch-text 的持续 RGB 故障，强调「最终文本完全稳定可读」，符合 Anti-Slop 的克制高级感。
4. **完整交互面：不只是自动播放**：进入视口、悬停、点按、按钮、键盘、**自定义文案真实解码**（含多语言/emoji 安全处理）六种触发与输入路径，配合可切换字符集/方向/速度的 Micro-HUD，把单一动效做成可玩的实验室；严格规避 SOP 对「无交互纯自动播放动画」的禁止。
5. **工程边界鲁棒 + 零资源离线**：字符独立 span 等宽占位保证零 CLS、emoji 代理对不拆坏、reduced-motion 降级但功能完整、aria 朗读与视觉乱码分离、重入/重播/切文案的干净重启、卸载统一回收 observer/rAF/监听；系统字体栈、零外部字体/图片/CDN，双击离线完整可用。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：src/playground.js 全部 60 个注册案例（id / 标题 / 描述 / tags）+ playground/effects、playground/components、playground/pages 物理目录（实测 12 effects / 45 components / 3 pages）+ 活动池 IDEA-001～IDEA-036（全部 Ready）+ rejected.md（当前为空）+ completed.md（当前为空）。
- **相似案例**：
  - `glitch-text`（赛博故障文字）：名称最近、同属文字动效，但它是对**恒定可读文本持续施加**的赛博朋克视觉滤镜（RGB 通道错位、色偏、位移抖动，强度/速度可调），文本从一开始就是目标内容且不会变成另一串字符；本案例核心是「**每字符先随机替码、再逐位锁定为目标文本的一次性/可重播解析状态机**」，最终态完全稳定无故障，视觉语义为「解密浮现」而非「信号干扰」，二者机制（字符级状态机 vs 整文本 CSS/层叠通道偏移）、叙事与最终呈现均不同。
  - `typewriter`（打字机文字）：同为「文本随时间逐步呈现」，但它是**字符的追加与回退**（多段文案循环打字/删除 + 光标闪烁），任何时刻屏幕上都是目标文案的真实前缀，从不存在「位置上先显示别的随机字符再被替换」的替码阶段；本案例每个位置都经历「随机乱码帧 → 锁定」，且最终呈现是瞬间整行稳定，交互与引擎模型不同。
  - `particle-text`（粒子文字）：同样有「从散乱到拼出文字」的从噪声到秩序叙事，但它在 **Canvas 上把文字光栅化为像素粒子**，靠粒子爆炸/弹性弹簧聚合复原，单位是粒子点而非排版字符，输入输出与视觉材质（物理粒子 vs DOM 字符）完全不同；本案例不使用 Canvas 粒子，直接操作真实文本字符，可选可复制、可被读屏（分离层）、可即时输入任意文案。
  - `count-up`（数字滚动爬升）：数字在补间中快速跳变到目标值，形似「跳变→稳定」，但它处理的是**单一数值的连续数值补间**（easeOutExpo + 千分位/小数），不是逐字符独立调度的文本解码，没有字符集随机、解析波方向、stagger 与多语言文本概念。
  - `scroll-reveal`（滚动入场）：本案例也会在进入视口时触发，但 scroll-reveal 是**整个元素块级**的上移/缩放/滑入/模糊一次性入场，不触及文本字符内容；二者是触发手段与内容动效的关系，可共存而不重复。
  - 在池文字/输入类 Idea 逐一核对：IDEA-028 行内编辑（只读↔可编辑切换，非动效）、IDEA-020 提及输入 / IDEA-004 标签输入 / IDEA-019 表情选择器（输入组件）、IDEA-018 机械翻页倒计时（数字翻牌机械呈现）等——均无「乱码解码/逐字符随机替码锁定」主题；全仓与活动池检索 `scramble / decode / 乱码 / 解码 / 逐字 / 字形 / splittext / 字符`，命中仅上述各案例的既有机制描述，无解码语义。确认无历史（含已删除）`text-scramble` id 或物理目录冲突。
- **差异说明**：核心创意是「**一个按字符独立调度、未锁定帧从字符集随机取样、到达各自锁定时刻稳定为目标字符、形成明度解析波的真实文本解码引擎，配合进入视口/悬停/点按/按钮/键盘/自定义文案多触发方式的终端美学标题动效**」。与 glitch-text 相比，差异在「一次性解析为稳定文本的字符状态机」vs「持续施加于恒定文本的通道故障滤镜」；与 typewriter 相比，差异在「随机替码后锁定（替换语义）」vs「真实字符追加/回退（前缀语义）」；与 particle-text 相比，差异在「DOM 真实排版字符的字符级动效」vs「Canvas 像素粒子的物理聚合」；与 count-up 相比，差异在「离散字符的随机解析编排」vs「连续数值补间」。差异同时体现在核心创意、视觉表达（低明度假码→高明度锁定的解析波 × 扫描微光）、交互方式（六类触发 + 自定义文案实时解码 + 参数化 HUD）与整体表现（终端解码实验室）上，不属于换颜色、文案或微调参数类重复。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生 HTML5 + CSS3 + ES6+，零框架、零第三方库、零动画库、零图标库/图标字体、零 CDN、零外部图片与外部字体（使用系统无衬线 + 系统等宽字体栈），双击 `index.html` 完整离线可用（沿用案例三件套 `index.html` / `style.css` / `script.js`）。
- 解码必须真实：按字符建立独立开始/锁定时刻的状态机，单 `requestAnimationFrame` 按时间累积驱动，未锁定字符在每帧间隔内从安全字符集（默认片假名或 ASCII 符号数字集，可切换）随机取样，到达锁定时刻写入目标字符；禁止整行 opacity 切换、写死帧序列或直接显示最终文本冒充解码；全部锁定后必须停止 rAF，不得空转。
- 字符处理安全：正确拆分多语言字符与 emoji/代理对（至少不把 emoji 拆成半个代理对乱码，未锁定阶段可对其使用统一占位或直接保留）；空格保留宽度；每字符独立 inline 占位保证乱码替换与锁定全程无行宽变化、无换行点漂移、无 CLS，窄屏视口下解码前后换行一致。
- 触发必须多路径且非纯自动播放：进入视口（IntersectionObserver）、悬停/点按、重新解码按钮、键盘 Enter/Space、自定义文案输入后解码全部真实可用；明确播放中重入（忽略或干净重启）与 resize/横竖屏切换后的行为，不产生双重 rAF 或状态串台；observer/rAF/监听在卸载与页面隐藏时统一清理，无泄漏。
- 可访问性为一等路径：动画乱码层与读屏文本分离（aria-hidden + 可读最终文本或等效 aria-label），aria-live 仅在解码开始/完成的阶段边界播报一次；控制具可见 label/焦点样式与 AA 对比度，状态不仅靠颜色；`prefers-reduced-motion` 下默认直接呈现最终文本（可保留非跳变的极短淡入），但全部触发、自定义输入与参数功能完整。
- 视觉为暗色哑光克制的终端实验室风格：乱码态低明度/低字重、锁定态正常可读，允许一处小面积解析波强调色，拒绝霓虹满屏、红蓝色散堆砌的 AI Slop；桌面/平板/手机自适应、窄屏控制区堆叠不横向溢出，触控热区充分。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（强制）；字符集、推进方向、跳变速度、stagger、整体时长、循环/微光开关与真实引擎状态（总字符数、已锁定数、阶段、rAF 运行态）通过默认折叠的 Micro-HUD 提供（`H`/`Esc`、事件防穿透）。
