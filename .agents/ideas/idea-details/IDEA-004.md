## 创意概述

「一组值」是网页表单中极高频的输入需求：邮件收件人、技能/兴趣标签、筛选条件、协作者、问题分类。它既不是 `otp-input` 那种**固定位数、一格一字**的分段码，也不是 `combo-box` 的**单值**选择或 `payment-card-input` 的**格式化单串**，而是一个数量不固定、每个值独立成「芯片（chip）」、可增删改与整批解析的**多值复合输入原语**，站内没有任何案例覆盖。本案例做一个纯原生、零依赖、可直接投产的标签输入器：用户在同一输入行内连续键入并提交多个值，每个值即时生成带状态的芯片；支持分隔符/回车/失焦批量解析、整段粘贴拆分、退格回删、重复检测与数量上限、非法值（如邮箱格式）内联纠错，以及带匹配高亮的建议下拉与完整的 WAI-ARIA 多值文本框 + listbox 键盘模型。

## 预期展示效果

- **构图与整体风格**：
  - 以真实「撰写邮件 / 完善资料」场景承载：上部为收件人字段（严格邮箱模式），下部为技能标签字段（自由文本模式），旁边给出当前值的实时回显（如「收件人 N 位」或生成的数组/字符串预览），避免出现脱离上下文的孤立输入框；页面留白克制，延续项目深色玻璃质感。
  - 控件本体是一个可整体聚焦的容器：芯片在左、文本光标在右，自动换行流动；容器聚焦时有清晰的整体焦点环，与内部芯片焦点区分层表达。
- **主要视觉元素**：
  - **芯片（chip）**：圆角胶囊，含可选语义图标（邮箱模式的小信封）、值文本、悬停/聚焦才显现的移除 ✕；有效态为低饱和中性玻璃底，非法态为克制的暖红描边与底，并带说明小标。
  - **建议浮层**：输入时在容器下方弹出的毛玻璃 listbox，每条含头像/图标、主文本与副文本（如部门、匹配原因），命中字符高亮，键盘焦点行有实心高亮条。
  - **状态文案**：占位提示（如「输入后按回车添加」）、计数（`已添加 5 / 上限 10`）、错误内联提示，均在容器内或下方以小号字分层呈现。
- **层次、材质、光影与关键细节**：
  - 芯片与建议浮层使用项目既有毛玻璃语言（半透明底 + backdrop blur + 1px 高光描边 + 柔和投影），浮层明确悬浮于内容之上。
  - 芯片入场为 opacity + 轻微 scale/回弹的弹性缓动；非法芯片可有一次极轻的水平抖动；移除时收缩塌陷并由后续芯片以弹性节奏补位（流动重排，而非生硬跳格）。
  - 重复值不新增芯片，而是让已存在的同名芯片做一次「高亮呼吸」提示，明确反馈「它已经在了」。
  - 焦点分两层：容器整体焦点环（来自 Tab 进入）与单个芯片/建议行的内部焦点（来自方向键），视觉上可清晰区分；退格回删的「待删目标」在键盘流中有明确预选态。

## 动态与交互

- **添加**：键入值后按 `Enter` 或分隔符（逗号、分号；邮箱模式下空格亦可作分隔符）即生成芯片；容器失焦时按当前模式决定是否把残留文本提交（邮箱模式自动解析，自由模式可配置保留）。
- **批量输入**：整段粘贴 `"a@x.com, b@x.com;c@x.com"` 时一次性拆分为多个芯片，按规则逐一校验，合法/非法分流呈现，不弹打断式告警。
- **删除与编辑**：
  - 点击芯片 ✕ 移除；
  - 输入框为空时按 `Backspace` 预选最末芯片（高亮），再按一次 `Backspace` 确认删除（两步防误删）；
  - 方向键 `←/→` 在芯片与文本输入之间漫游焦点，聚焦某芯片后按 `Backspace/Delete` 删除、按可打印字符则删除并以该字符开始新输入（接近主流邮件客户端的「回格编辑」手感）。
- **建议补全**：根据当前片段过滤建议列表（如通讯录/技能词库），`↑/↓` 在建议间移动、`Enter/Tab` 采纳、`Esc` 收起；采纳与手动键入走同一校验与重复检测通道；无结果时给克制的空态。
- **规则与校验**：
  - 邮箱模式做基本格式校验，非法值生成「暖红芯片」并在字段下方汇总原因（如「2 个邮箱地址格式不正确」），允许保留以便修改；
  - 数量上限达到后输入与建议采纳均被阻止并给出明确提示；单值长度超限同样内联提示。
- **触控**：芯片移除按钮满足触控热区；建议项整行可点；窄屏下容器与浮层宽度自适应、浮层不超出视口。
- 适配 `prefers-reduced-motion`：关闭弹性/抖动动效，保留即时增删与状态切换。

## 核心亮点

1. **真正的多值复合输入模型**：数量不固定、逐值成芯片、支持分隔符/回车/失焦三种提交时机与整段粘贴批量拆分，覆盖邮件收件人、技能标签等真实业务，而非 demo 式「回车加一个词」。
2. **完整的双通道键盘交互**：芯片流内左右漫游、两步 Backspace 回删防误删、回格编辑；同时叠加 listbox 建议的 ↑↓/Enter/Esc 采纳流，两套焦点模型在同一控件内协同且符合 ARIA 多值文本框语义。
3. **克制的内联纠错而非弹窗打断**：非法邮箱以「暖红芯片 + 汇总文案」就地呈现可改可删；重复值通过已有芯片的高亮呼吸反馈；上限与长度规则均有明确但不粗暴的提示。
4. **流动重排的弹性反馈**：芯片增删时弹性入场与塌陷补位、建议浮层毛玻璃质感与命中高亮，达到可直接投产的完成度，延续项目 Anti-Slop 视觉标准。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：src/playground.js 全部 60 个注册案例（id / 标题 / 描述 / tags）+ playground/effects、playground/components、playground/pages 目录 + 活动池 IDEA-001~003 + rejected.md（当前为空）+ completed.md（当前为空）。
- **相似案例**：
  - `otp-input`（分段验证码）：同为「一格一值」的多格视觉，但 OTP 是**固定 6 位、单字符、自动前进**的校验码输入，无自由文本、无数量可变的芯片、无建议列表与批量解析；
  - `combo-box`（可搜索下拉选择框）：同样具备「输入框 + 建议 listbox + ARIA 键盘」，但语义是**单选**（选中即填入并结束），无多芯片、退格回删、整段拆分与逐值校验；本案例的建议采纳只是「往集合里追加一个值」；
  - `payment-card-input`（银行卡输入）：同为输入中的格式化与校验，但产出是**单一卡号串**，无多值集合语义；
  - 队列中的 IDEA-001 `date-picker`：同为复杂表单控件，但核心是月历网格与日期状态机，无文本芯片集合；
  - `avatar-stack` / `tooltip` / `context-menu`：可借鉴边缘避让与浮层定位，但无输入语义。
- **差异说明**：核心创意是**变长多值集合输入 + 芯片状态机**（批量分隔解析、重复检测、数量上限、逐值内联纠错、芯片流与 listbox 双键盘模型协同），与全部历史案例在核心创意、视觉表达（可增删的芯片容器）与交互方式（两步退格、粘贴拆分、追加式建议采纳）上均无实质重叠；不属于换色、换文案或微调参数类重复。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生零 CDN、双击 index.html 独立离线运行（通用项目铁律，详情不重复）。
- 邮箱校验仅需合理的前端格式判定（单一正则或等价规则即可），不做真实发信与网络校验；建议数据（通讯录/词库）为内置静态演示数据。
- 建议浮层定位与边缘避让使用原生 JS 计算（不引入定位库）；浮层内容不依赖外部图片，头像等以内联 SVG/CSS 构造。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊；模式切换（严格邮箱 / 自由标签）与上限等演示控制使用默认折叠的 Micro-HUD。
- 尊重 `prefers-reduced-motion`；键盘焦点环与触控热区满足无障碍标准。
