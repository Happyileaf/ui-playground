## 创意概述

Mentions Input 是评论区、即时通讯、协作文档、工单系统与代码评审里的另一项肌肉记忆式刚需：在输入过程中键入 `@`，一块候选浮层自动在**光标正上方**浮出，边打名字边模糊过滤，↑↓ 选择、回车确认，选中对象随即变成一枚**与正文融为一体、不可从内部编辑的内联提及胶囊（mention token）**，组件同时向外输出「纯文本 + 结构化提及元数据」两份值，可直接用于消息发送、表单提交与后端通知链路（GitHub / Slack / Linear / 飞书的共同范式）。全仓 60 个已注册案例中，输入增强类原语已有 `combo-box`（可搜索下拉）、`otp-input`、`payment-card-input`、IDEA-004 标签输入、IDEA-019 表情选择器、`rich-text-toolbar` 富文本工具条等，但**没有任何一个组件实现「行内触发符检测 → 光标坐标锚定浮层 → 查询态过滤 → 内联原子化 token → 结构化值输出」这一完整提及链路**；全仓出现 “mention” 字样的两处仅是通知中心（`notification-center`）里一条“在动态中提到了你”的通知数据，是提及的**下游消费结果**，而非提及输入本身。本案例做一个纯原生、零依赖、双击即用的**生产级提及输入组件**：演示场景为一条协作文档 / 工单评论撰写框，用户正常打字，输入 `@`（并可扩展 `#` 话题等第二触发符）即唤起联系人浮层，浮层始终跟随当前查询词所在的光标位置；联系人数据内嵌（头像用内联 SVG / 首字母色块生成，零图片零 CDN），支持姓名 / 拼音 / 部门的模糊匹配、最近 @ 过的人置顶（localStorage，file:// 静默降级）、键盘全流程操作与完整 ARIA combobox 语义；确认后查询词整体被替换为不可分割的提及胶囊，退格整体删除、光标无法进入胶囊内部；下方实时给出两份产出预览（纯文本渲染结果 + 可复制的结构化 JSON：提及对象 id / 显示名 / 在文本中的区间）。它是技术域 1「现代高可访问性 UI 组件」与技术域 5「按钮与表单交互」交叉处一个覆盖面空白、实用性直达生产的组件，也与上一轮的 Emoji Picker 构成「文本输入区两大标配浮层」的互补关系而非重复。

## 预期展示效果

- **构图与整体风格**：
  - 延续项目统一深色质感，视觉主体是一个**协作评论撰写场景**：页面中部一张文档 / 工单卡片（纯 CSS 与内联 SVG 构造的标题、段落与元信息占位，零外部图片），卡片底部是评论撰写区——一个大号的富输入框（可换行、可容纳内联胶囊）、底部一行工具区（字数 / 提及数统计、提示文案、提交按钮，提交仅做本地演示态点亮，不发请求）。整体留白克制，不铺满屏控件。
  - 键入 `@` 后，一块**毛玻璃候选浮层**在触发符所在光标的**正上方**弹出（光标贴近视口上缘 / 左右缘时自动翻转或平移，始终完整可见）；浮层为窄长列表，每行 = 头像 + 主名 + 次要信息（部门 / 拼音或昵称），无匹配时给空状态。浮层与输入文字之间有小箭头或最近一条投影暗示“锚定关系”，但不使用全屏压暗遮罩（提及是打字流中的轻量旁路，不能遮蔽上下文）。
  - 确认提及时，`@` 与已键入的查询词在原位置被替换为一枚**内联提及胶囊**：胶囊是行内圆角小标签（头像微缩 + 名称），与文字基线对齐、随正常文本一起换行，视觉上明显是“原子单元”但不喧宾夺主；胶囊有 hover 高亮与可见焦点态，颜色 + 形态双编码，不单靠颜色。
  - 输入框下方（或可折叠副区）实时展示**结构化产出预览**：一行纯文本结果（提及渲染为 `@显示名`）与一块 JSON 片段（提及数组：id、name、起止区间等），让“这个组件到底产出什么、怎么对接后端”一目了然，是本案例区别于普通演示的“生产组件说明书”。
  - 右上角为统一点阵色 Title 胶囊（遵循 HUD 规范：毛玻璃胶囊 + 固定主题色呼吸点，指示灯颜色不随浮层状态联动）。组件自身即交互主体，不需要额外的 Micro-HUD 调参面板。
  - 窄屏（手机视口）下撰写区与浮层宽度收敛为接近卡片宽度，候选行触控热区不小于典型 44px 规格，浮层打开时页面背景不被误滚动。
- **主要视觉元素**：
  - **候选浮层（核心视觉）**：规则的联系人行列表，头像统一为圆形（内联 SVG 几何头像或首字母 + 确定性底色，零图片资源），主名与次要信息两级排版；当前激活行有克制的底色提亮与左侧 / 整体微位移指示；浮层顶部可有一行极小的灰字提示（如“↑↓ 选择 · Enter 确认 · Esc 取消”），首次使用后可不再强调。
  - **提及胶囊（mention token）**：行内圆角标签，内含微缩头像与名称；与普通文字同处一条排版流，背景为低饱和半透明主题色，描边极细；光标经过与悬停时有轻微提亮，点击胶囊可整体聚焦（外轮廓焦点环），再次按退格整体移除。
  - **触发瞬间反馈**：键入 `@` 时浮层做一次短促的 fade + 轻微上移 / scale 入场（约 150–200ms，带阻尼感）；输入查询词时列表内容即时更替但浮层位置保持稳定（只随光标位置变化而移动），不产生跳动闪烁。
  - **多触发符扩展**：演示中 `#` 可作为第二触发符唤起「话题 / 频道」候选（数据与视觉与联系人略作区分，如图标与胶囊色调的形态差异），用以证明组件的触发器架构是**可配置的触发符 → 数据源 → 渲染器**，而非写死一个 @；普通邮箱地址中的 `@`（前邻非触发边界）不得误唤起。
  - **空状态与边界**：查询无结果时浮层显示空状态图标 + 文案（如“没有匹配的人”），不残留上一次结果；浮层打开但用户删掉触发符、键入空格或继续输入使查询失效时，浮层按规则关闭。
- **层次、材质、光影与关键细节**：
  - 材质关键词：**深色磨砂玻璃浮层 + 行内轻量胶囊 + 柔和内聚投影**。浮层用半透明深色底 + `backdrop-filter` 模糊（与仓库既有 tooltip / context-menu / emoji-picker 语言一致），边框为低透明度亮线；投影短而柔，让浮层“贴”在光标附近。
  - 反 AI Slop 细节：行高、头像尺寸、内边距构成严谨模数；不使用彩虹渐变描边、不堆叠发光；胶囊的主题色只做低面积点缀；激活态、选中态、焦点态全部颜色 + 形态双编码。结构化预览区使用安静的等宽字体色块，视觉层级低于撰写区。
  - 触发符识别必须有明确的**触发边界规则**：仅当 `@` 出现在输入起始或其前一个字符是空白 / 换行等分隔符时才唤起（`a@b`、邮箱 `x@y.com` 不触发）；查询词中出现空格、标点或长度超出合理上限时自动取消本次提及会话。
  - 遵循 `prefers-reduced-motion`：偏好减弱时取消浮层位移 / scale 入场与胶囊插入动效，浮层即时显隐、token 即时替换，过滤、键盘、结构化输出全部保留。

## 动态与交互

- **触发与关闭（核心机制）**：在富输入区内监听输入，当满足触发边界规则键入 `@`（或 `#`）时开启一次“提及会话”：记录触发符的文本位置，浮层锚定到该位置的**光标像素坐标**（通过镜像元素 / Selection Range 几何等标准手段测量，不依赖第三方库）；继续键入的字符成为查询词，浮层即时过滤。以下情况关闭浮层并结束会话：确认选择、Esc、触发符被删除、查询词中出现分隔符、输入区失焦（点击候选行时通过悬停态 / `mousedown` 防失焦等常规手段保证点击不提前关闭）、外点。
- **光标锚定与碰撞**：浮层默认显示在触发光标上方；光标贴近视口上缘时翻转到下方，贴近左右缘时水平平移，始终完整落在视口内；输入导致换行、页面滚动或窗口尺寸变化时实时重定位；浮层位置只跟随真实光标，不随意跳动。
- **过滤与选择**：联系人数据为内嵌的适量演示数据集（约 20 人量级，含中文名、拼音 / 昵称、部门 / 角色字段），支持跨字段模糊匹配（子序列或包含匹配均可，具体算法不早限定，但必须对中文友好且无结果可判定）；“最近 @ 过的人”在空查询态置顶（去重、有上限，localStorage 持久化，file:// / 隐私模式 try/catch 静默降级为内存态）；↑↓ 在候选行间循环移动激活项（空结果时不移动），Enter / Tab 确认，Esc 取消并把浮层关闭（已键入的 `@query` 作为普通文本保留，不强制删除）。
- **内联 token 化（核心机制）**：确认后触发符与查询词被整体替换为一枚不可从内部编辑的原子化提及胶囊（contenteditable 原子节点或等价的行内原子结构）：光标不能进入胶囊内部、不能只删除胶囊的一半；退格 / 删除键在胶囊前后时整体移除并收敛为普通文本编辑；胶囊随文本自然换行；在胶囊前后继续输入普通文字互不干扰；同一人可被多次提及，结构化值中如实记录多次。
- **结构化值输出（核心机制）**：组件维护并实时更新两份值——① 纯文本（提及渲染为 `@显示名`，话题为 `#话题名`），② 结构化提及数组（每项含触发符类型、对象 id、显示名及在纯文本中的区间，具体字段以实现为准但必须可对接提交）；撰写区下方实时预览，提交按钮演示读取两份值并给出本地反馈；字数 / 提及数统计联动。
- **键盘与可访问性（硬性）**：
  - 输入区为可编辑元素并有正确可访问名称；浮层具备完整 ARIA combobox / listbox 语义：输入元素（或承载 combobox 的容器）带 `role="combobox"`、`aria-expanded`、`aria-controls`、`aria-activedescendant` 随激活项联动，浮层为 `listbox`、联系人为 `option`（带姓名与次要信息的可访问名称），选中态有 `aria-selected`。
  - 浮层打开期间 ↑↓ 移动激活、Enter / Tab 确认、Esc 取消，按键不得误写入正文或引起页面滚动；Tab 确认与否的具体取舍以实现为准，但必须有明确、文档化的键位。
  - 已插入的提及胶囊可通过键盘整体聚焦（可见焦点环）与整体删除；屏幕阅读器在激活项变化时通过 `aria-activedescendant` 或等价的 aria-live 机制获知候选名称；所有交互元素有清晰可见的 focus-visible 焦点环。
- **移动端触控**：单指点击候选行确认（触摸不导致输入区先失焦而丢会话）、行高满足触控热区；浮层打开时内部滚动与背景页面滚动隔离；窄屏浮层与输入区同宽级，不遮挡正在输入的那一行。
- **生命周期**：iframe 卸载 / 浮层关闭时移除全部监听与临时镜像 / 浮层节点、断开观察器；无持续 rAF（测量与重定位仅在输入、滚动、resize、开合时发生）。

## 核心亮点

1. **填补全仓「行内触发式提及输入」空白，实用性直达生产**：60 个历史案例与活动池 IDEA-001~019 中没有任何 @ 提及组件（全仓 “mention” 仅命中通知中心的一条通知数据与邮箱校验正则）。提及输入是评论、IM、文档协作、工单、代码评审的标配，成品可直接嵌入真实网页并对接通知链路，实用性 5/5。
2. **有真实工程深度的四个机制闭环**：触发边界识别（邮箱等 `@` 不误触）、**光标像素坐标锚定浮层**（镜像 / Range 几何 + 碰撞翻转 + 滚动重定位）、**原子化内联 token**（不可入内编辑、退格整体删除、随文换行）、**纯文本 + 结构化元数据双值输出**（实时 JSON 预览，可直接提交）——这四点是“生产级 Mentions”与“一个弹列表的玩具”的分水岭，也是与所有相邻组件的本质分界。
3. **完整的高可访问性模型**：ARIA combobox/listbox/option 语义、`aria-activedescendant` 联动、↑↓/Enter/Tab/Esc 全键位、token 可聚焦可整体删除、可见焦点环、颜色 + 形态双编码、外点 / 失焦 / 触摸的关闭时序正确、`prefers-reduced-motion` 完整降级，达到可直接交付的无障碍水准。
4. **可配置的触发器架构与零依赖离线**：触发符 → 数据源 → 行渲染是可配置的（演示内置 @ 联系人和 # 话题两套），而非写死；联系人为内嵌数据、头像内联 SVG / 首字母色块生成，零图片、零字体文件、零 CDN、零网络请求；最近提及用 localStorage 且对 file:// 静默降级，任何现代浏览器双击 index.html 均为完整作品。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：src/playground.js 全部 60 个注册案例（components 45 / effects 12 / pages 3，含 id / 标题 / 描述 / tags）+ playground/effects、playground/components、playground/pages 三个物理目录 + rejected.md（当前为空）+ completed.md（当前为空）+ 活动池 IDEA-001~019 全部详情。并以 `mention`、`提及`、`@[`、`@用户`、`at-user` 为关键字（不区分大小写）全仓检索：**未发现任何提及输入案例或目录**；全部命中仅 4 处且经逐一核实均为偶然命中——① `playground/pages/auth/script.js` 第 370 行邮箱校验正则 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` 中的 `@`；② `playground/components/notification-center/script.js` 第 13、49 行通知类型枚举 `mention`（一条“在动态中提到了你”的通知数据，是提及的**下游通知展示**，无任何输入机制）；③④ IDEA-017 / IDEA-019 详情「检查范围」段落中对 Popover API 等技术词的描述性文字。
- **相似案例**：
  - **`combo-box`（可搜索下拉选择框）**：交互原语最接近——浮层 + 即时过滤 + ↑↓ Enter Esc + ARIA combobox。但它是**独立的单值表单控件**：固定输入框、浮层锚定整个控件、选中即填值关闭；本案例发生在**多行富文本输入流内部**：由行内触发符在特定边界条件下唤起、浮层锚定**光标的像素坐标**并随换行 / 滚动重定位、选中后替换的是行内一段查询文本并产出**原子 token + 结构化区间元数据**，且一次撰写可多次提及、可与 `#` 等多触发符复用同一架构。锚定模型、替换语义、数据产出均不同。
  - **IDEA-019 表情选择器（Emoji Picker，Ready）**：上一轮刚准入的输入区浮层，共享“保存选区 → 浮层选择 → 插回输入区”的部分原语。但它由**外部按钮**唤起、锚定**触发按钮**、插入的是普通可编辑字符（可从中间删除）、二维分类网格 + grid 键盘模型；本案例由**行内键入触发符**唤起、锚定**行内光标坐标**、产出不可分割的**原子 token**与结构化提及值、一维 listbox + combobox 模型，并承担触发边界识别（邮箱不误触）与查询态生命周期。二者是评论输入区两大互补标配，非重复。
  - **IDEA-004 标签输入（Tags Input，未来案例 id `tags-input`，Ready）**：同为“输入区里的芯片”且都有退格整体删除。但标签芯片来自**自由文本提交**（键入完整词后回车 / 逗号成 chip），芯片 = 用户刚输入的词本身，无浮层、无候选数据、无触发符、无结构化外部对象；本案例的胶囊来自**对一组已知对象的检索选择**，芯片绑定的是对象 id（同名两人可区分），并维护查询区间与结构化元数据。一是“自由文本多值录入”，一是“行内实体引用”，数据模型不同。
  - **`rich-text-toolbar`（富文本工具条）**：作用于 contenteditable，具备选区保存 / 还原与链接浮层录入，是编辑能力上最邻近的案例。但它是**选中文本后施加格式**的工具条（加粗 / 标题 / 链接等），没有触发符检测、没有候选数据检索、没有原子实体 token 与结构化值输出；本案例未来可与其共存于同一编辑器，自身独立。
  - **IDEA-008 实时对话工作台（Chat Workspace，Ready，pages）**：页面级 IM 拟真，最可能被期待“应该有 @”。经核对其输入区仅有“少量常用 Emoji”内嵌小面板，**无任何 @ 提及机制**；且它是整页会话叙事而非可复用输入组件，本案例与其是“可移植组件 vs 使用组件的页面”的关系。
  - **`tooltip` / `context-menu` / `mega-menu` / `notification-center` / IDEA-010 级联选择器**：都包含浮层、边缘碰撞或键盘漫游，是**通用浮层原语**；本案例复用同类设计语言（毛玻璃、避让、焦点管理），但核心是行内触发会话 + 光标锚定 + 实体 token 化 + 结构化输出，浮层定位只是实现手段。
  - 活动池其余 Ready 项（日期 / 轮播 / Toast / 步骤 / FAB / 液态按钮 / SVG 图表 / 评分 / 分页 / 时钟 / 开关 / 转场 / 灯箱 / 贝塞尔工坊 / 翻页倒计时等）均无行内实体提及语义。
- **差异说明**：核心创意是**“一个在富文本输入流中由触发符唤起、锚定光标坐标、模糊检索已知对象、把查询词替换为原子化内联 token，并实时输出纯文本与结构化提及元数据的零依赖高可访问组件”**。与 combo-box（固定控件单值选择 vs 行内光标锚定 + 多实体 token + 区间元数据）、IDEA-019（按钮锚定 + 插入普通字符 + 分类网格 vs 触发符锚定 + 原子实体 + combobox 模型）、IDEA-004（自由文本芯片 vs 绑定对象 id 的检索式胶囊）、rich-text-toolbar（选中文本加格式 vs 行内实体引用）、IDEA-008（整页 IM 拟真且无 @ vs 可复用生产组件）在核心创意、视觉表达（光标锚定浮层 / 行内胶囊 / 双值预览）、交互方式（触发边界识别、查询会话、键盘选择、token 化与整体删除）与整体表现（协作评论撰写生产组件）上均有实质差异，非换色、换文案或微调参数。全仓检索确认无历史（含已删除）同名 id 或目录，案例 id 定为 `mentions-input`。

## 实现约束（仅记录该案例必要的约束）

- 必须纯原生零 CDN、零框架、零库，双击 index.html 独立离线运行（通用项目铁律，不重复）。
- 联系人 / 话题为**内嵌 JS 数据集**（约 20 人量级，含中文名、拼音或昵称、部门 / 角色），头像一律用**内联 SVG 几何图形或首字母 + 确定性底色**生成，不引入图片、字体文件或任何网络资源；模糊匹配必须对中文友好（姓名 / 拼音 / 部门字段均可命中）且能正确判定无结果。
- 触发符识别必须实现**触发边界规则**：仅在输入起始或前邻为空白 / 换行等分隔符时唤起，邮箱等 `xxx@xxx` 形态不得误触；查询词出现分隔符、超长或触发符被删时正确结束会话。
- 浮层锚定**触发符光标像素坐标**：以镜像元素 / Selection Range 几何等原生手段测量，默认向上展开并做视口碰撞翻转 / 水平平移；换行、滚动、resize 实时重定位；候选行点击（触摸 / mousedown）不得先令输入区失焦而丢失会话；不使用全屏压暗遮罩；支持时可利用浏览器顶层呈现能力（如 Popover API），不支持时降级为定位浮层。
- token 必须是**行内原子单元**：不可进入其内部放置光标、不可部分删除，退格 / 整体删除键一次移除，随文本自然换行；结构化值至少包含纯文本与提及数组（类型、对象 id、显示名、文本区间），并在演示区实时可见；一份输入可多次提及同一 / 不同对象。
- “最近提及”用 localStorage 持久化但必须 try/catch 包裹，file:// 或隐私模式不可用时降级为内存记录，绝不抛错阻断输入。
- 可访问性为硬性要求：combobox / listbox / option 完整 ARIA 与 `aria-expanded` / `aria-controls` / `aria-activedescendant` 联动、↑↓/Enter/Tab/Esc 键位完整且不穿透到正文 / 页面、token 可键盘聚焦与整体删除、可见焦点环、状态颜色 + 形态双编码、候选变化可被辅助技术感知；`prefers-reduced-motion` 下取消入场 / 位移动效但触发 / 过滤 / token 化 / 键盘 / 输出全部保留。
- 遵循统一 HUD 规范：右上角固定点阵色 Title 胶囊（指示灯颜色不联动）；组件自身即主交互，不另设参数 Micro-HUD。
- 响应式：窄屏浮层宽度与最大高度受限、候选行触控热区达标、浮层滚动与背景页面滚动隔离；iframe 卸载时移除监听、临时镜像与浮层节点、断开观察器，无持续 rAF。
