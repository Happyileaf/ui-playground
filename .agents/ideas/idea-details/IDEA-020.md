## 创意概述

一个把「从一个较大的候选集合里挑出一个有序子集」这件高频表单事务做成可视化「分流闸」的纯原生组件：左侧是待选池、右侧是已选集合，用户通过勾选 + 方向闸按钮、双击、跨栏拖拽或键盘在两栏之间成批「穿梭」选项；两栏各自带搜索过滤、全选（含半选态）与计数，已选栏还支持就地排序。它解决的体验问题是：当候选项多于十几个、且需要一次挑多个、还要能解释「哪些选了 / 哪些没选 / 还能选几个」时，普通多选下拉要反复开合、看不清全局，标签输入又依赖用户知道有哪些可选项，而穿梭框让**全集、已选、未选三态同时可见、可批量操作、可键盘完成**。

## 预期展示效果

- **构图与整体风格**：暗色「分流控制台」展台。主体为左右两张等高的深磨砂面板，中间是一条竖向轨道，轨道中央上下叠放两枚圆形方向闸按钮（右移 → / 左移 ←），无可用移动时按钮为克制的禁用态。左面板标题「待选」，右面板标题「已选」，整体像一道把元素从一侧摆渡到另一侧的闸机，而非两个无关的列表。
- **主要视觉元素**：
  - 两栏顶部工具行：带半选（indeterminate）态的全选勾选、栏标题、形如 `已选 3/24` 的计数徽标、以及一个内嵌的轻量搜索框（带结果计数与清除钮）。
  - 选项行：左侧可选标记点 + 主标签 + 一行灰色副描述 / 标签 chips；勾选态整行高亮并出现实色勾选；禁用项（如名额已满、权限不足）降低对比但仍可读，并在悬停时以一句话说明禁用原因。
  - 穿梭动效：被移动的项以 FLIP 位移动画沿中间轨道滑入对栏对应位置，轨道在移动瞬间流过一道短暂的方向流光；批量移动 N 项时做轻微 stagger，不做浮夸弹跳。
  - 已选栏底部摘要条：`已选 n 项`、容量提示（如 `最多 8 项 · 还可选 5`）、「清空已选」；已选行提供拖拽排序与上移 / 下移，序号在排序后平滑更新。
  - 空态：搜索无结果或某一栏为空时，以虚线轮廓 + 一句话静默提示（如「没有匹配的成员」「还没有选择任何项」），不使用报错红色。
- **层次、材质、光影与关键细节**：面板为深色磨砂底配 1px 半透明描边，两栏之间靠间距与轨道而非粗分割线拉开层次；选中态、焦点态、禁用态三态不仅靠颜色区分——同时有勾选点、外描边和文案。方向闸按钮是视觉锚点，可用时在悬停 / 键盘聚焦下有轻微提亮与方向箭头位移，禁用时不隐藏只降权。整组组件在窄视口下从左右双栏折叠为上下堆叠，轨道转为横向、方向闸按钮旋转 90°，交互完全等价。

## 动态与交互

- **三种转移方式等价**：勾选后点方向闸按钮、直接双击某个选项、以及跨栏拖拽，三种方式更新的是同一份选择模型并触发同一套穿梭动效；批量勾选后一次转移多项。
- **双侧独立搜索过滤**：在任一栏输入即时过滤，显示匹配数；过滤视图下的全选只作用于当前过滤结果；清空搜索恢复完整列表且已勾选状态不丢失。
- **全选与半选**：全选勾选支持「全选当前可见 / 取消全选」，选中一部分时呈现 indeterminate 态；计数徽标随勾选实时更新。
- **已选栏排序**：拖拽或上移 / 下移改变已选集合的顺序，输出值即有序子集；排序仅为已选集合内的附属能力，不改变待选池。
- **容量与防错**：可配置最大选择数；达到上限时待选项的转移入口禁用并给出原因提示，不弹惊吓式错误；无勾选时对应方向闸按钮天然禁用。
- **键盘与读屏**：两栏均为 `listbox` 语义（`role=listbox/option`、`aria-selected`、`aria-multiselectable`），列表项 roving tabindex；支持 Shift 连选、Ctrl/Cmd 点选，回车或 → / ← 键在两栏间转移选中项，焦点在转移后落在对侧新位置或本栏下一项；方向闸按钮可 Tab 到达并以空格 / 回车触发。
- **移动端触控**：触控目标不小于 44px，双击转移在触控上退化为明确的行内转移按钮；`prefers-reduced-motion` 下关闭 FLIP 与流光，选项直接出现在终态，功能不降级。

## 核心亮点

1. **三态同时可见的选择模型**：全集、已选、未选一屏呈现，配合搜索与计数，彻底避免多选下拉「选了什么要重新打开才知道」的黑盒感。
2. **把移动做成「穿梭」母题**：中间轨道 + 方向闸 + FLIP 摆渡动画与一次方向流光，让抽象的数据集合变更拥有直观、克制且有记忆点的空间隐喻，而不是两个干巴巴的 `<select multiple>`。
3. **批量与逐条、鼠标与键盘全部等价**：双击、跨栏拖拽、勾选 + 闸按钮、键盘连选转移殊途同归；半选全选、过滤后批量选择、容量防错覆盖真实表单场景。
4. **输出有序子集**：已选栏内排序让组件的价值不止「选没选」，还包含「按什么顺序」，可直接服务权限成员排序、字段列顺序、优先级编排等场景。
5. **表单控件级可访问性**：以 listbox/option 与 aria-selected 建模，而不是一堆无语义 div，键盘用户与读屏用户可独立完成全部转移与排序操作。

- **相似案例**：
  - `components/kanban-board`：多列看板，卡片可在列间拖动。
  - `components/combo-box`：可输入过滤的单选 / 建议下拉。
  - `components/tree-view`：层级树展开选择；`components/split-pane`：可拖拽调整比例的布局容器。
  - 在途 **IDEA-016（Accessible Sortable List，#59）**：单一列表内的键盘可达拖拽排序。
  - 历史（已 Revert）IDEA-002「标签输入（Tag Input）」：自由输入 token 的标签录入。
- **差异说明**：
  - vs `kanban-board`：看板是**工作流状态板**——多列（通常 ≥3）代表流程状态，卡片承载独立内容编辑与 WIP 限制，移动语义是「改变状态」，没有全选勾选、双侧搜索、计数与「有序选中子集」的值模型。本组件是经典**双栏表单控件（恰为两栏：待选 ↔ 已选）**，核心是从一个有界候选集合中产出一个有序子集，配备全选 / 半选、双侧过滤、批量转移、容量约束和标准 listbox 语义；两者视觉母题（分流闸 vs 看板墙）、数据模型（有序子集 vs 状态列）和用途（表单输入 vs 流程管理）均不同。
  - vs `combo-box`：后者是单栏建议下拉，关注输入联想与单项（或简单多选）选择，无法同时展示全集与已选集、不支持批量穿梭与已选排序；本组件三态常驻可见。
  - vs IDEA-016 排序列表：其核心是**在一个集合内部重排**；本组件的核心是**在两个集合之间成批转移**，排序仅是已选栏内的附属操作，二者交互焦点与输出模型不同，非子集 / 微调关系。
  - vs 历史 Tag Input：标签输入依赖用户自由键入、候选项可有可无，表达「任意标签集合」；本组件面向**有界、可搜索的候选全集**，表达「从已知项中挑选的有序子集」，且全程不产生候选之外的新值。
  - `tree-view`（层级浏览）、`split-pane`（布局容器）及其余在册 / 在途案例与双栏穿梭选择均无实质重叠；全库与全部在途 / 历史 Idea 对该概念零覆盖。

## 实现约束（仅记录该案例必要的约束）

- 纯原生 HTML/CSS/ES6+，零框架、零第三方依赖、零 CDN，双击 `index.html` 离线完整可用；数据以小型内置常量数组给出（如成员 / 权限项），不发起任何网络请求。
- 选择模型需为「单一数据源 + 视图派生」：待选 / 已选、勾选集合、搜索过滤与排序都从同一份状态计算，避免双栏 DOM 状态不同步；转移与排序动画结束后正确取消订阅 / 清理，无定时器与监听泄漏。
- 语义必须是 `listbox`/`option` + `aria-selected`/`aria-multiselectable`，转移与排序全程键盘可达；颜色不作为唯一状态表达，对比度满足 WCAG AA，触控目标 ≥ 44px，尊重 `prefers-reduced-motion`。
- 遵守统一 HUD 规范（右上角点阵色 Title 胶囊；Micro-HUD 默认折叠、H/Esc 开关且事件防穿透）与暗色 Anti-Slop 审美：穿梭动效克制、时长短促，不使用刺眼高饱和与浮夸弹跳。
- 响应式：窄视口下双栏上下堆叠、轨道横向化，功能与键盘操作保持等价。
