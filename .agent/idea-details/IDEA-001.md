## 创意概述

网页中最常用却尚未在案例库中独立呈现的轻量反馈组件：一个支持四种语义类型、堆叠排列、自动消失与手动操作（Action）的 Toast / Snackbar 系统，解决“操作后如何给予不打断流程的反馈”这一高频日常需求。

## 预期展示效果

- **构图与整体风格**：暗色精致底（延续 `#0f172a` 系克制深色），演示页中央放置一组触发按钮（成功 / 信息 / 警告 / 错误 / 带操作的 Snackbar），通知从屏幕右下角自下而上堆叠。
- **主要视觉元素**：圆角卡片式通知体、左侧语义色细竖条或圆点图标、标题与两行以内正文、可选 Action 文字按钮、关闭小叉；进入时高度与透明度过渡无跳变。
- **层次、材质、光影与关键细节**：毛玻璃或半透明深色材质（`backdrop-filter`）、柔和投影；多条通知之间保持统一间距；最新一条在堆顶或堆底（择一并保持一致）；同类型通知可做限量合并，避免刷屏。

## 动态与交互

- 触发：点击演示按钮（也支持键盘聚焦后回车 / 空格）。
- 入场：从右侧滑入 + 淡入 + 轻微回弹；退场：向右滑出或收起高度后淡出。
- 自动消失：每条带可暂停的倒计时进度提示，悬停 / 聚焦时暂停计时，移开续时；错误类默认停留更久或不自动关闭。
- 操作：Action 按钮（如“撤销”）执行后该条关闭并可级联一条确认 Toast；关闭按钮、`Esc` 关闭当前最新一条。
- 可访问性：`role="status"` / `aria-live="polite"`（错误类用 `assertive`），焦点不被强制夺走；移动端从底部全宽弹出、触控目标 ≥44px。
- 尊重 `prefers-reduced-motion`：降级为即时淡入淡出、无位移。

## 核心亮点

- 工程上完整的通知队列模型（堆叠、限量、自动/手动消失、悬停暂停），而非单条静态提示；
- 高度自适应的进场/退场过渡（不出现布局塌陷跳动）；
- ARIA live region 与键盘/Esc 的完整可访问闭环；
- 一条“可操作 Snackbar”（带撤销动作）展示真实产品场景价值。

## 历史案例对比（进入 Ready 前必填）

- **检查范围**：src/playground.js 全部 59 个注册案例 + playground/effects、playground/components、playground/pages 目录 + rejected.md（空）。
- **相似案例**：
  - `notification-center`（通知中心）——铃铛驱动的下拉面板，承载历史列表、未读筛选与已读管理；
  - 外壳层 `appToast`（src/playground.js 内部）——工作台自用的极简 2.4s 提示，不是独立案例、无类型/堆叠/Action/可访问语义。
- **差异说明**：核心创意不同——本案例是**瞬时、自动消失、可带动作的被动反馈（Toast/Snackbar）**，notification-center 是**持久化、可回溯管理的通知收件箱**；视觉表达上本案例强调右下角堆叠队列与高度过渡，交互上强调倒计时悬停暂停与 Action（撤销）闭环，ARIA live 播报策略也是 notification-center 下拉面板所不具备的。与外壳 appToast 更是“案例 vs 内部实现”的区别，且能力维度（类型、堆叠、操作、无障碍）完全不同。

## 实现约束（仅记录该案例必要的约束）

- 纯原生、零框架、零 CDN；双击 index.html 可离线运行。
- 队列与计时器需在页面卸载时清理；音效（若有）必须手势后懒激活。
- 遵循统一 HUD / Anti-Slop 规范（克制配色、对比度 AA、触控 ≥44px）。
